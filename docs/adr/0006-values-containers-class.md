# ADR-0006：值域统一 —— json / dynamic / 容器 / class / UFCS

状态：已接受（2026-08-25）· 修订 PLAN.md 第 1 节「值表示」与第 4 节「UFCS 解析顺序」两条

## 1. 一个值域，三个名字

`dynamic`、`json`、JS 子集的变量，本质是同一个东西：**运行时带标签的值**。

- `dynamic` = 完整的动态值域（含 class 实例、函数值）
- `json` = `dynamic` 中「可序列化」的静态视图：`null | bool | int | real | string | list<dynamic> | dict<string, dynamic>`
- JS 子集里未标注类型的变量 = `dynamic`

**决定：不为 json 单独造类型和容器。** `json` 是对 `dynamic` 的约束（不含 class 实例 / 函数 /
NaN / inf），共用同一份运行时表示与同一套 list/dict 实现。三份实现是"原生 JSON 支持"最常见的
死法 —— 序列化器、动态字段访问、JS 互操作会各自长出一套语义。

## 2. 值表示：不上 NaN-boxing（**修订** PLAN §1）

原决定是「VM 内 NaN-boxing」。研究 Cyber 源码后推翻，依据在
`docs/notes/jit-jancy-cyber.md` §2.3.2：Cyber 名义上定义了完整的 NaN-boxing 位布局，但实际已
演进为「静态类型 slot 存裸值 + 只在 `dyn` 边界装箱」，`Value.initInt` 就是个裸 bitcast；
`VALUE_IS_INTEGER` 等三个宏引用了仓库里根本不存在的 `TAGGED_INTEGER_MASK`，是死代码。代价是
整数运算按 48 位语义做（`_BitInt(48)`）—— 这是长期负债。

**决定**：
- 静态类型的 slot 存裸值（i64 / f64 / 对象指针），不装箱、不限宽
- `dynamic` 用 `{tag: u8, payload: u64}` 的 16 字节胖值（C 后端）/ JS 原生值（JS 后端）
- 装箱只发生在 `静态 → dynamic` 的显式边界上，且这个边界在 OIR 里是一个可见的 op（便于将来消解）
- 值得抄 Cyber 的一点（notes §2.3.1）：把「是否堆对象」「是否可循环」编码成**有序区间**，
  判定退化成一次无符号比较，而不是掩码 + 相等比较

## 3. 容器：编译器内建参数化，不做用户泛型

`list<T>` / `dict<K,V>` / `set<T>` 由编译器直接认识，后端按实例化类型展开；**用户自定义泛型推到
comptime 参数化（Mojo 路线）之后**。

理由：解锁容器和 JSON 不需要先定下泛型设计。反过来做会把关键路径拖长数月，而自举只需要
「编译器自己够用的容器」。这与 Go 在 1.18 之前的 `map`/`slice` 是同一个取舍。

### dict 必须保持插入序（硬约束）

否则 JSON 序列化文本在 js/c 两个后端上不一致，**差分测试就不再是安全网**。实现走 Python 3.7 /
V8 的路子：稀疏索引表 + 紧凑 entries 数组，迭代顺序 = 插入顺序。

### set：做，但不给字面量语法

`{1, 2}` 在 C 系语法里与块语句冲突（Python 靠 `set()` 绕开同一问题）。决定：
`set<int> s = set(1, 2, 3);`，内部复用 dict 的索引结构、省掉 value 数组。

### 字面量与语法歧义

- `[1, 2, 3]` = list；`{"a": 1}` = dict
- **语句位置的 `{` 永远是块**；只有表达式位置的 `{` 才是 dict 字面量
- 空 dict 写 `{:}`，空 list 写 `[]`
- 现有 parser 的 tentative 机制（`looksLikeVarDecl` 那套）足以判定，不需要新机器

### JSON 的数字模型（必须显式决定，否则必然踩坑）

严格 JSON / JS 里数字全是 f64，i64 往返会静默丢精度。**决定**：
- 解析：无小数点、无指数、且落在 i64 范围内 → `int`；否则 `real`
- 序列化：`int` 不带小数点；`real` 用能往返的最短表示（注意这与 `print` 的 `%.6g` **不是**同一
  条规则，见 ADR-0005 —— `print` 是给人看的，序列化是给机器看的）
- NaN / inf 不可序列化 → 抛运行时错误，不静默变 `null`

代价：与 JS 的 `JSON.parse` 在大整数上不逐位等价。这是**有意**的选择，i64 保真优先；只要两个
后端一致，差分测试仍然成立。

## 4. struct 是值类型，class 是引用类型

- `struct` = 值语义（已实现，C struct 语义，赋值即拷贝）
- `class` = **引用语义 + ARC**。Jancy 的 class 本就是 GC 引用，JS 子集的对象也是引用，两边一致
- 单继承；interface 后续再加；**多重继承不进自举子集**
- 不支持原型改写、不支持运行时增删字段 —— 字段集在编译期封闭。这正是"不直接支持原型"的落地
  形式：JS 那套 `obj.__proto__` / 动态挂方法的能力不进语言，靠下一节的机制覆盖其实际用途

## 5. 方法 = 第一参数为 this 的自由函数（**修订** PLAN §4）

这一条同时实现了"数据成员和函数自动挂钩"与 Nim 的 UFCS —— 它们是同一件事：

- class 体内写的方法，降级后就是 `f(This self, …)`；`o.f(x)` 与 `f(o, x)` 完全等价
- 由此**免费得到扩展方法**：给内建容器写 `int sum(list<int> xs)`，就能 `xs.sum()`；
  不需要原型，也不需要 `partial class`

**修订原 UFCS 规则**：原方案是「① 成员 → ② 作用域内自由函数 → ③ 类型所在模块」的有序回退，
首个命中集参与重载解析（PLAN §4 与当前 `stage0` 实现均如此）。改为：

> 三处候选**合并为一个重载集**，按隐式转换代价择优；并列最优 → 报歧义错误。

理由：一旦方法本身就是自由函数，有序回退会产生「新增一个自由函数意外遮蔽了成员方法（或反过来
被遮蔽）」这种无法向用户解释的行为。合并 + 歧义报错的代价是「加个同名自由函数可能让原本合法的
调用变成歧义」，但那是一条**显式的编译错误**，而不是静默改变已有调用的目标。可解释性优先。

## 6. 迭代协议（容器可用性的前提，优先级紧跟容器）

没有协议的话，list / dict / set / string / json 会各长一套遍历方式。**决定**：
- 协议 = `iter()` 返回迭代器、迭代器有 `next()`；`for (x in c)` 是它的语法糖
- 对内建容器，编译期直接内联展开成索引循环，不走虚调用
- `in` 同时用作成员测试（`k in d`）—— 借 Python，语义按容器类型区分（dict 查键、list/set 查值）

## 7. 记录但靠后：pointer / unsafe

明确：**v1 的语言表面没有裸指针**，安全指针也不是入门特性。以下条目登记在案，排在自举之后：

- `pointer<T>`：Jancy 式胖指针 `(ptr, base, limit)` + 越界抛异常 + 边界检查消除 pass
- `unsafe { }` 块：唯一允许裸地址运算的地方
- C FFI / `extern "C"` / struct 布局兼容
- 手工内存管理（arena / 显式 free）

唯一可能让它提前的触发条件：用 Omni 写原生寄存器 VM 时，如果 `list<int>` / bytes buffer 无法
表达指令流与栈操作，就必须提前引入。届时重新评估，不预先承诺。

## 8. 其他语言：只抄这几条，其余明确不抄

- **Nim**：UFCS（已有）+ **迭代器**（第 6 节）。`distinct` 类型暂不
- **Python**：切片、`in`。**列表推导先不做** —— 纯语法糖，等迭代协议稳定后再加成本更低
- **Go**：多返回值 —— 与 Jancy 双错误模型是同一个问题的两种解（`(T, error)` vs 调用点选
  errorcode/异常），**先不定**，等错误处理整体设计时一起决
- **Zig / Mojo**：comptime + 参数化 —— 用户自定义泛型的最终形态，容器先内建、后统一到它
- **JS**：模板字符串、解构、spread —— JS 子集前端必需，实现成本低，可以早做
- **Lua 的 table 统一 array+hash**：**不抄**。list 与 dict 分开，类型信息才留得住，
  静态后端才能生成不带哈希查找的索引访问
- **Asymptote**：命名实参 + 隐式转换图（已有）

## 9. 落地顺序（替换 `docs/bootstrap-subset.md` 原 MVP-2 列表）

1. ✅ `list<T>` + 索引/边界检查 + **迭代协议**
2. ✅ `dict<K,V>`（插入序）+ `string` API（长度、切片、按**字节**索引 —— 码点 API 见 ADR-0005 已知偏差）
3. ✅ `dynamic` 值表示 + `json` 解析/序列化（复用 1、2；实现在 `stage0/lib/json.omni`，
   用 Omni 自己写，于是两个后端共享同一份实现）
4. ✅ `class`（引用）+ 方法降级为自由函数 + UFCS 合并重载集 —— **ARC 未做**，
   当前只分配不释放，等 ADR-0007 的 unwind 表落地
5. ✅ `set<T>`（复用 dict 索引）
6. ✅ 模块系统 `import` + `private`（ADR-0009，`libsFor` 已删除）；
   ✅ tagged union（ADR-0012：`enum` + 必须穷尽的 `match`，载荷按值内联）
7. ✅ 闭包 / 函数值（ADR-0010：`fn(...) -> T`，捕获按值，lambda 提升在检查器里做）
8. …… pointer / unsafe 在这之后

每一步的出口条件不变：js/c 双后端差分全绿 + 快照更新 + 基准无回退。

C 侧另过 `clang -Wall -Wextra -fsanitize=address,undefined` 无报告，

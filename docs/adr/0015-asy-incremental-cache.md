# ADR-0015：asy 增量编译重做（增量的粒度是**一条声明**，不是一个文件）

状态：设计（这一版定粒度与契约，落地顺序在最后）
日期：2026-08-30
相关：ADR-0014（决策 1 核心方言、决策 5 函数级编译单元、第七十六刀"一个源文件一份产物"、第七十八刀"接口索引"）

## 背景：现在这一套错在哪

不是缓存摆得不好。是**从头到尾以"整份文件"为单位**，于是每一处不一致都变成"全量否定"。
四条都是量出来的：

1. **一格存不下来，整份接口作废**。`plain` 的接口索引一直没写出来 —— 它的 struct 体里有
   6 条语句是 `{node, mat, bi}` 这种包装，打包器认不出形状，`asyIfaceDump` 于是把
   **整个 plain**（450KB、13 份库里最大的一份）判成 `bad`，一条也不存。
2. **改一个字符，整个前端重跑**。tri.asy 改一个数字、强制走前端，安静环境下各量三趟：
   接口索引**开** 617/674/690ms、**关** 635/642/640ms —— **在噪声里，一点不省**。
   （从前记的"932 vs 787"是后台还在跑 oracle 时量的，不算。）
   为什么不省，量出来了：那一趟**解析了 21 个源文件，只有 11 个是单元**——
   `plain_constants` / `plain_strings` / `plain_pens` / `plain_paths` / `plain_filldraw` /
   `plain_margins` / `plain_picture` / `plain_prethree` / `plain_Label` / `plain_arcs` /
   `plain_arrows` / `plain_boxes` / `plain_shipout` / `plain_markers` / `plain_debugger` /
   `plain_scaling` 这 15 份**并进了 plain 那一个单元**，于是它们**压根没有缓存身份**：
   没有 `.stamp`、没有 `.sec`、不可能有 `.aif`，每一趟都重新读、重新解析。
   接口索引只覆盖 21 份里的 7 份，所以它省不出东西来。
   按"文件"切产物的设计从来没覆盖过这 15 份；按"条"切之后，一条声明从哪个文件、
   哪个单元来都不重要，这个洞自动消失。
3. **一份产物的印记盖的是"它引到的那几个源文件"**。同一份文件里改任何一条声明，
   引它的那几份产物全部重编 —— 与"改了哪一条"无关。
4. **有一桶按整个程序生成的东西**（`omni_weak`）。它的名字固定、内容由程序决定，
   于是换个入口跑就把它刷掉：tri.asy 与 implicit.asy 依赖完全相同、各几行代码，
   交替跑每趟都是 ~950ms（命中时 0.28s），两份 weak 差 728 字节。

共同点：**判据的粒度比改动的粒度粗**。一个字符的改动落到"整份文件"这一格上，
就必然放大成整趟重来。s-expr 这一层本来是给"逐条可寻址"用的，被我当成了整块校验。

## 参照

- **rustc 的查询系统**（salsa 那一套）：每一件派生事实都是一次查询，key 是它的输入。
  输入的哈希没变就是"绿"，直接拿上一趟的结果；变了才重算，并沿依赖图往上标红。
  粒度是**一条 def**（`DefId`），不是一个文件。
- **rustc 的 CGU 与符号名**：单态化实例的符号名是内容哈希，链接期按 weak symbol 去重 ——
  "程序决定"的东西也各有确定的归属与名字。
- **tsc 的 `.tsbuildinfo`**：每个文件一格 version（内容哈希）+ 文件间引用图，
  改了谁就沿图算影响面；跨工程只读 `.d.ts`。粒度是文件 —— 这已经比我们细。
- **Cargo 的 fingerprint**：Merkle 值只由源侧输入算（编译器版本、features、依赖的
  fingerprint），与"这一趟在编谁"无关。

## 决策

### 1. 增量的粒度 = 一条顶层声明

核心方言的顶层项本来就有名字：`(fn 名 …)`、`(global 名 …)`、`(class 名 …)`。
**它们就是增量单位**（下称"条"）。一个源文件只是"这些条的一个来源"，不再是判据。

一条的身份：

```
h(条) = H( 编译器印记
         , 这一条自己的正文（核心方言文本，逐字节）
         , sorted[ 名字 + ":" + h(它引到的那一条) ] )
```

引用图有环（互相递归、互相 import）时按 SCC 整块算一个值，环里的成员共用它。
**只由源侧算**：与"这一趟的入口是谁""哪几份被跳过"无关。

### 2. 一个声明存储（declaration store），一切都按条寻址

```
.omni-cache/asy/
  d/<h>.sx     一条声明的核心方言正文
  d/<h>.js     它编出来的 JS（emit 的最小单位）
  d/<h>.if     它的接口（名字 + 签名 + 它引到哪几条的 h）
  d/<h>.ast    它要带的 AST 碎片（默认实参那一档，见决策 4）
  u/<单元名>-<uh>.idx   一个单元的目录：它有哪几条、每条的 h、声明顺序
  e/<入口 h>.idx        入口清单：这个程序要哪几条（按拓扑序）+ 环境
```

每一格**只写一次**（名字由内容决定），所以：

- 谁都不会盖谁 —— 交替跑、并发跑都不再互相作废（现在这两样都会）。
- 改一条声明只多出几格 `d/<新 h>.*`，别的原样躺着。
- 同一条被两个程序用到就是同一格，天然共享。

### 3. 文件级产物退化成一层索引

node 那边要 ESM 模块，所以每个单元仍出一份 `.js`，但它**只是一串 re-export**：

```js
export { s_foo } from '../d/9f2c….js';
export { s_bar } from '../d/a71b….js';
export function omni_init_plain() { … }   // 只有这一份是按单元生成的
```

于是"改一条"重编的只有那一条与这层薄索引，不是整份 450KB。
（模块数量会涨 —— 一个程序几千格。这一条要量：ESM 模块加载有固定开销，
量出来太贵就退一步，按单元把 `d/<h>.js` **拼**成一份，拼是纯字符串拼接，
不是重新编译。拼与不拼都不影响判据。）

### 4. 前端也按条走：接口索引不再"整份否定"

`.if` 一条一格。**一条存不下来就只有这一条回落到源码**，别的照旧走索引 ——
现在是整份作废（背景第 1 条）。落到实现上：

- 声明遍产出的每条声明各自出一格 `.if`；存不下来的那条在单元的 `.idx` 里记一格
  `raw|<名字>`，读回时**只**为这些名字重新解析源码那一段（span 已经在手上）。
- 正文降级（body pass）按条：一条的 `.sx` 还在、h 没变，就不重降它。
  现在是"整份正文一起跳过或一起降"。

### 5. "程序决定"的那一桶（`omni_weak`）删掉

逐条看，它里面每一项都由**某一条声明**决定（量出来的组成：391 条 `(fn …)`、
36 条 `(global …)`、0 条 class）：

- HELPERS：编译器自带的表，用到才发 -> 归运行时。
- cyclic 登记处（那 36 条有状态的）与数组工厂：由**元素类型**决定 -> 归定义那个类型的那条。
- 默认实参包装：由**被调方那条声明**决定 -> 归被调方。

所以它们本来就是"从某条声明推出来的另一条声明"，进声明存储即可，归属与内容一起定。
已经量过：这样算出来的归属在 tri / implicit / cardioid / floor 四个入口下**完全相同**
（共有 437–439 项、0 处不同）。

### 6. 入口清单：变了就只重算变了的那一段

`e/<入口 h>.idx` 记的是"这个程序用到哪几条的 h"与环境。跑一趟先按源文件内容哈希
认哪些源变了，只对变了的源重新算它那些条的 h，沿引用图往上标红；**没被标红的一条都不动**。
不再有"整张清单一行对不上就全量重来"。

## 门槛（这一批算完成的判据，全部用 `time` 量）

- 改入口里一个字符：只重编那一条 + 入口那层索引，**≤0.35s**。
  量到哪了：只编译（`asy-units`）**406/333/273ms**，连跑带编（`run`）551/502/477ms。
  写这条门槛时那一档是 787–932ms，而那个数字里混着两个 bug（见下面"已经修掉的"）。
- 改一份库里一个函数体：只重编那一条与依赖它的那几条，**≤0.5s**（现在整份库重编）。
- tri.asy 与 implicit.asy 交替跑：每趟命中，各 ≤0.35s。**过了** —— 八趟 167–207ms。
- 2D 例子与 3D 例子交替跑：各自命中（现在这一档必挂）。
- 220 个例子快扫仍 ≤10s、单个 ≤500ms；退出码与产物字节与改之前一致。
  **过了** —— 219 干净、2.4s、最慢 genusthree.asy 144ms。
- 并发跑两个入口不出错（现在会：`omni_weak.js` 被对方盖掉，报 does not provide）。

## 落地顺序

每一步都能单独量、单独回退。前三步已经落地并验过：

1. ✅ **指纹层**（决策 1 的单元级版本）：`asyFps`，源侧算。验过：同一个源文件在
   tri / implicit / cardioid / floor 下指纹全同（共有 12 份、0 处不同）。
2. ✅ **归属层**（决策 5）：每一项生成物算出归属单元。验过：四个入口下归属全同。
3. ✅ **把核心方言按条切开**（`OMNI_ASY_DECLS=1`）：13 个单元 4293 条切开再拼回**逐字节
   相同**。还没接线 —— 只落盘 `d/<h>.sx` 与 `<单元>.idx`，产物仍然走整份 `.sx`。
4. **emit 按条**（决策 3）：`d/<h>.js`，单元的 `.js` 变成 re-export 索引。
   先量 ESM 模块数量的开销，太贵就拼。验：220 个例子退出码与输出不变。
5. **接口按条**（决策 4）：`.if` 一条一格，`raw|` 回落只影响那一条。
   验：`plain` 不再因为 6 条语句丢掉整份索引；改一个字符的时长；**EPS 那一轴的出图数
   追平"关索引"那一档（55/192）并继续往上**。
   （单元级的那一版已经能跑，但**默认关着** —— 它快（改一个字符 273–406ms 对 508–537ms）
   却还欠 11 份图，还剩两族只有它才有的错：34 份"X 在这里还看不见"、19 份"默认值不能把
   null 当成 T"。根子就是"按整份存"：一份库的表里混着别人家的格子，来回一趟就掉。）
6. **生成物进存储**（决策 5 落地），`omni_weak` 整条删掉。
7. **入口清单换成 `e/<h>.idx` + 红绿标记**（决策 6），删掉 `main-*.dep` 与 `w|`。
8. **`omni asy-gc`**：从 `e/*.idx` 出发算可达集回收。

## 这一批已经修掉的（在上面第 3 步之前，止血用）

- 入口自己那几条包装从共用桶挪回入口：tri ↔ implicit 交替从 ~950ms/趟 变成 275–453ms 且命中。
- **产物名只取基名 —— 会跑错程序**（第七十九刀，ADR-0014 里有完整那一节）。
  `omni run /tmp/tri2.asy` 一步前端不走、跑出 `/tmp/asyfp/tri2.asy` 那个程序的 EPS：
  AST 缓存、每文件产物、入口清单三处名字都只取基名，而 `inpOk` stat 的是**印记里记着的**
  那个路径。改成 `<基名>__<身份哈希>`（rustc 的 `-C metadata`）。
  这也解释了从前那些"周期性不正常"的时长：两份同名入口一直在互相盖对方的缓存。
- **接口索引整片是死的**：`asyIfaceLoad` 写死 `obj.v !== 1`，dump 那边写的是 `v: 2`。
  所以"开索引一点不省"那次测量测的是同一条路。修好之后 10 个库全走索引。

- `sts` 那一格按 `{node, mat, bi}` 存（背景第 1 条）：`plain` 终于有了接口索引，
  13 份里 7 份走索引，改一个字符 932ms -> 787–851ms。接口索引版本号升到 2。
- 快路不命中时说清原因（`asy mods 不命中 weak 那一份被别的入口盖掉了` 之类）——
  从前它悄悄失效，日志上看不出来。

### `-f svg` 卡在哪儿：**`_shipout` 住错了地方**（设计缺陷，不是缺一个开关）

现状：`omni run x.asy` 出 SVG 的唯一办法是在源文件头上贴一句 `asy__defaultformat = "svg";`
（`tests/asy/svg.js` 就是这么做的）。这不是「少一个 CLI 开关」，是三处结构错了：

1. **格式是编译器的开关，不是用户源码里的一句话。** 真 asy 的 `-f` 是 `settings.cc`
   从 argv 填 `settings::outformat`，程序跑之前就定好了；我们把它塞进源码，等于让
   「输出成什么」变成程序的一部分。
2. **`_shipout` 在内建面里（`asy_builtins.asy`），而它去猜格式。** 真 asy 的 C++ 侧
   `_shipout` 只管「按给定格式写字节」，决定格式的是 `base/plain_shipout.asy`（asy 源码），
   它读 `settings.outformat`。我们让内建面自己猜，于是发明了 `asy__defaultformat` ——
   那个变量存在的唯一理由是「内建面看不见 settings」，而这个前提**是错的**：
   `asyDeclPass` 里 `asySettingsIn(L, u, off)` 对**每个单元**都跑（decls.js:1281），
   `settings` 本来就并进来了。
3. **产物缓存的键里没有格式。** 一旦格式进编译期，`-f svg` 与不带 `-f` 会命中同一份
   产物 —— cli.js 里那句「这不是慢，是**跑错程序**」警告的正是这种。

改法（四处，顺序固定，先键后行为）：

- `jsCacheStamp()` 加一格格式（那儿已经有 `ASYMPTOTE_DIR`/`OMNI_ASY_BUILTINS` 两个先例）。
- `lowerAsy` 的选项加 `outformat`，在降 `settings` 那个模块时作为 `outformat` 的**初值**
  （这是编译期选项，与 `prelude`/`load` 同类，不是往源码里插句子）。
- `asy_builtins.asy`：删掉 `asy__defaultformat`，`_shipout` 读 `settings.outformat`。
- `cmds.js` 加 `-f FMT`；`-o x.svg` 在没给 `-f` 时按扩展名推断（写明这是我们多给的方便，
  真 asy 的 `-o` 只定名字）；`tests/asy/svg.js` 改用 `-f svg`，删掉那句头部注入。

**试过并否掉的三条**（记下来免得再走）：往源码头上贴（就是要改掉的那条）；合成一个入口
单元 `settings.outformat=…; import "x";`（会改掉 `_mainname()`，等于跑另一个程序）；
每种格式一个一行的库模块 `asy_fmt_svg.asy`（还是「插入」，而且把 CLI 开关伪装成库）。
另外查明：asy 那条腿**没有运行期从宿主读字符串的原语**（`builtins.tab` 只有实数数学函数，
方言对外只有 `(print …)` 一个出口），所以「运行期读环境变量」这条路要先加一条封闭 ABI 的
原语才谈得上 —— 那比编译期选项贵，而且格式本来就该在编译期定。

### 更正上一节：**格式是运行期的值，不能被模块锁定**（上一节的结论是错的）

上一节写着「格式该是编译期选项」。**错了**，而且证据是我自己写下的那一行：那条路要求
`jsCacheStamp()` 加一格格式 —— 也就是**同一份源码要为每种格式各编一份产物**。这荒谬：

- 真 asy 里格式**根本不进程序**。`settings::outformat` 是运行期的全局，C++ 侧从 argv 填；
  `asy -f svg x.asy` 与 `asy -f eps x.asy` 跑的是**同一个**编译结果。
- 一旦格式住进某个模块的变量（无论是内建面的 `asy__defaultformat`、还是一个
  `asy_fmt_svg.asy`、还是编译期注入的一句赋值），格式就被**编译进产物**了：产物缓存要
  按格式分叉、`-f` 换一次就重编一遍、库产物也跟着分叉。这就是「输出格式被模块锁定」。

所以正确的形状只有一个：**格式是宿主给的运行期值**。而这一刀真正缺的东西也就此明确 ——

> **asy 那条腿没有「运行期从宿主读一个字符串」的原语。**
> 方言对外只有 `(print …)` 一个出口；`builtins.tab` 只绑实数数学函数
> （68 行，从 asy 的 runmath.in 生成）；`settings.outformat` 连**读**都还不支持
> （量过：`settings.outformat` 当表达式报「asy 前端第一刀还不支持：带点的名字」，
> 赋值那一路已经支持）。

于是这一刀的正确顺序是（与上一节完全不同，上一节作废）：

1. **加一条封闭 ABI 的原语**：读宿主的一格设置（形状照 ADR-0011 那套：`host/native.js`
   + `frontend-js/link.js` 的 NATIVE_OPS + `hir/js_abi.js` + `backend-js/prelude.js`
   + C 运行时 + `omni.h`，与第三刀加 `i32Op` 是同一套六处）。
2. **asy 前端给它一个绑定**：现在非数学的宿主调用在 asy 侧没有入口，`builtins.tab` 那张
   表只有数学。这一格是这一刀的真正工作量。
3. `settings.asy` 的 `outformat` 初值从那条原语来（真 asy 就是 settings.cc 填的）；
   顺带把「带点的名字当表达式」补上，`_shipout` 才能读 `settings.outformat`。
4. CLI 的 `-f FMT` / `-o x.svg` 推断只是**设那格宿主设置**，产物缓存的印记**一个字都不用改** ——
   这正是「格式没被锁进模块」的检验：换格式不重编。

试过并否掉的四条，一并记着免得再走：源文件头部贴一句（测试现在的做法）；合成入口单元
（改掉 `_mainname()`，等于跑另一个程序）；每种格式一个库模块；**编译期注入 + 印记加格式**
（上一节那条 —— 它的代价就是"同一份源码按格式各编一份"）。

### 落地：`(getenv E)` 一条原语 + `_getsetting` 一个口子 + CLI 的 `-f/-o`

按上一节那四步做完了。**每一步都只有一处，没有一处是"往源码里插句子"**：

1. **方言多一条 `(getenv E)`**（`sexpr/lower.js`，内建名 `get_env`，string -> string）。
   没设那一格回**空串**，不是运行期错误 —— 与 `(readtext E)` 刻意相反：那边分不清
   「空文件」与「没这个文件」所以读不到就抛，而"没设"在这一条上是常态（调用方拿它
   当"用默认值"）。五条腿各一份实现，与 `read_text` 一格对一格：
   `interp/builtin.js` 的 `get_env`、`backend-js` 的 `$get_env`、`backend-c` 的
   `omni_get_env`（`omni_fmt.c`，getenv + omni_str_new 抄一份）、`backend-llvm` 的
   `get_env.string -> omni_get_env`（收发都是 `[2 x i64]`）。
   门：`tests/sexpr/cases/37-getenv.sx` —— **五方一致**（没人设过的那一格回空串、
   `PATH` 非空；不依赖任何一格具体的值，所以在别人机器上也成立）。
2. **写那一侧也补了一条封闭 ABI**：`setEnv` -> `js_proc_set_env`（六处齐：`host/native.js`
   + `link.js` 的 NATIVE_OPS + `js_abi.js` + `prelude.js` 的 `$js_proc_set_env`
   + `omni_js_host.c` 的 `setenv(n, v, 1)` + `omni.h`）。为什么要"写"：CLI 设一次，
   本进程 eval 的 JS、spawn 出去的 node、链好的可执行文件**都**看见（子进程继承环境）。
   注意方言里**没有**写那一侧 —— 设环境是驱动的事，程序自己不设。
3. **asy 侧的绑定是 `_getsetting(name)`**（`frontend-asy/calls.js`，降成 `(getenv …)`）。
   名字带下划线照 asy 自己的规矩（`_draw`/`_eval`/`_shipout`/`_readlines` 那一族都是
   "C++ 那一侧的口子"）。它与旁边的 `_searchpath` 刻意**相反**：那一格是编译期印成
   字面量的（路径进了产物缓存的键），这一格必须是运行期的。
4. **两格设置，都从宿主读**（`asy_builtins.asy`）：
   - `asy__outformat()` = `_getsetting("OMNI_ASY_OUTFORMAT")` —— `asy__defaultformat`
     那个变量**删掉了**；
   - `asy__outname()` = `_getsetting("OMNI_ASY_OUTNAME")` —— `-o 名字` 那一格。
   `settings.asy` 的 `string outformat` 初值也从同一格来，所以程序里读
   `settings.outformat` 与真正出的格式一定一致（真 asy 那边两者是同一个 C++ 全局）。
5. **CLI 只做一件事：设那两格**（`cli.js` 的 `asyRunSetup`，`cmds.js` 的 `--format/-f`）。
   `-o x.svg` 在没给 `-f` 时按后缀猜（`.svg` / `.eps`/`.ps`），猜不出就**报错**而不是
   悄悄出 EPS。摆在 `switch (cmd)` 之前而不是 `case 'run'` 里：`--backend llvm` 会把
   `run` 换成 `run-llvm`，摆在里头那几条腿就看不见 `-f`。

**检验（这一刀真正要证的那一条）**：`jsCacheStamp()` 一个字都没改。同一份编好的产物，
`-f svg` 与不带 `-f` 跑的是**同一个文件**，只是宿主那一格设置不同 —— 换格式不重编。
量出来的（同一个三行的 `fill((0,0)--(1,0)--(1,1)--cycle)`，`--verbose` 看那一行）：

```
run -f svg   asy units -> .omni-cache/asy-mods       exec 178ms   （第一趟，编）
run          asy mods 命中  6 份产物一份没动  [5ms]  exec  66ms
run -f svg   asy mods 命中  6 份产物一份没动  [4ms]  exec  66ms
run -f eps   asy mods 命中  6 份产物一份没动  [4ms]  exec  67ms
```

换格式那两趟连一份产物都没重编 —— 从前那条编译期方案在这儿一定是"重编一遍"。

顺带填上的两个坑（都是"图落到文件里"这条路上现出来的）：

- `-o 名字` 落盘走 `asy__out` 那个既有的缓冲开关（`asy__tobuf`/`asy__bufs`），末尾一次
  `_writetext`。**程序自己 `write(...)` 的字仍旧走 stdout** —— 图进文件、文字进终端，
  与真 asy 分得一样。
- `asy__baseeps` 从前在末尾把 `asy__tobuf` **钉成 false** 并清空缓冲。带标签的图正是
  经它拿底图的，于是 `-o x.eps` 时 dvips 出来的那段字节会绕过缓冲直接印到 stdout、
  文件里落一份空的。改成存旧值再还原。
- SVG 那个出口从前只有 `_shipout(frame)`（引了 plain 的那一路）有；不 import plain 时走的是
  这一层自己的 `shipout(picture)`，`-f svg` 在那条路上**没有效果**（量到过：一个三行的
  `draw((0,0)--(1,0)--(1,1)--cycle)` 加 `-f svg` 照旧出 EPS）。把 SVG 那段抽成
  `asy__svgcore(drawop[] ops, labelrec[] labs, box, w, h, real s)` —— 多的那个 `s` 是
  picture 那一路的 `fitscale`（frame 那一路恒是 1，字节与从前一致），两个出口共用一份。
  前向引用用**函数变量**（`asy__svgcorefn`，与 `asy__dashadjfn`/`asy__arclenfn` 同一个套路）：
  SVG 那一段住在文件后面，而 `shipout(picture)` 在前面。

还差一格，写在这儿不装作没有：程序里 `settings.outformat = "pdf"` 只改那个模块变量，
改不到宿主那一格（真 asy 那边两者是同一个 C++ 全局）。要补就得让那个名字变成"写宿主"的
口子（方言里现在**刻意没有** `setenv`）—— 等真有例子这么写的时候再动。

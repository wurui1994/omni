# ADR-0033：特性代数（原子 · 消去序 · 可删除性）—— 一个平台承载多门语言的形式基础

## 0. 这一份要回答的问题

ADR-0029 把前端切成了四个形式（位置代数 / 作用域图 / 类型偏序 / nanopass），可它切的是
**实现的层**，不是**语言的构成**。于是三个问题还悬着：

1. **原子化**：一门语言由哪些**不可再分的特性**拼成？"class"是一个特性还是五个？
2. **可删除性**：删掉 `class`，剩下那门语言还能不能编？**源码不许到处改** —— 谁保证？
3. **统一**：`~/Documents/Lang/reference` 底下躺着 go / vlang / mojo / freebasic / sbcl /
   chez，后面还有 C++。它们要共用什么、各自加什么，**在定义特性的那一刻就算得出来**吗？

今天的答案都是"靠人记"。证据：`src/lang/jnc/features/*.js` 已经是五份特性清单，可它们
只贡献**位置**与**账**两栏（`fields.js` 开头那句自己写着"binding / types / lower 等到
Phase 2~4 再填"）；真正的落法散在 `emit-ctx.js`（3500 行）、`lower.js`（1900 行）里，
**特性与代码之间没有可判定的对应关系**。所以"删一个特性"今天是一次重构，不是一次配置。

这一份给出那个可判定的对应关系：**特性 = 签名扩展 + 一组消去规则**。

## 1. 三条不变量（往下所有设计都为了守住它们）

- **I1 原子性**：一个特性只做一件事，且这件事有**唯一的消去目标**。判据：它的规则集里
  每条规则的右手边**不再出现它自己引入的任何算子**（自己把自己消干净）。
- **I2 契约自动**：一个特性对方言的要求 = 它规则右手边用到的核心算子的并集。
  **不是手写的文档**，是从规则里算出来的一份集合；方言缺一格就是**构建期错误**，
  不是运行期"还没接"。
- **I3 可删除**：删掉任一特性，剩下的语言仍是一门**完整的语言** —— 语法上它的写法变成
  一句语法错，语义上没有任何残留引用。判据是可执行的：**不带该特性重编一遍前端**，
  拿**不提它的那部分语料**跑，输出与全量构建**逐字节相同**。

三条都是"可判定"的：I1 是对规则集的静态检查、I2 是一次集合运算、I3 是一次差分测试。
凡是需要"人去记住"的规矩，这一份都不算完成。

## 2. 形式骨架

### 2.1 语法 = 多类签名（many-sorted signature）

一门语言的树不是"随便的 JSON"，是一个**多类代数**：

- **类（sort）**：`module` / `class-body` / `fn-body` / `expr` / `type` / `decl` / `stat` …
  —— 这正是 ADR-0029 §4.1 那张位置矩阵的行，已经有了（`JNC_SORTS`）。
- **算子（operation）**：每个算子带一条**定型规则** `op : s₁ × … × sₙ → s`。
  `class` 引入的是 `class-decl : name × base* × class-body → decl`；
  `property` 引入 `prop-decl : name × type × accessor* → decl`。

写下 Σ 的好处不是"更学术"，是**两件事立刻变成机械的**：树的合法性（`named()` 那一层今天
靠洞名对照表，正是 Σ 的弱化版）与**例子的生成**（Σ 的项枚举 = ADR-0029 §11 那台
"要素乘出来、例子自动生成"的机器）。

### 2.2 特性 = 签名扩展 + 消去规则

一个特性 `F` 是一个三元组：

```
F = ⟨ ΔΣ_F , R_F , C_F ⟩
  ΔΣ_F : 它引入的算子（含每个算子的定型规则与它能出现的 sort 集合）
  R_F  : 消去规则 T(Σ ∪ ΔΣ_F) → T(Σ)，每条形如 pattern ⇒ template（带侧条件）
  C_F  : 它要求的**能力名**（capability），不是文件、不是别的特性的名字
```

`C_F` 那一格是**可删除性的全部机关**：`property` 要的是能力 `record`（"有一格带字段的
存储"）与 `callable`（"能发一个函数"），**不是** `class`。`class` 与 `struct` 都
**提供** `record`。于是删掉 `class`，`property` 一个字都不用改 —— 它的能力还在。

### 2.3 组合 = 并，但要证两件事

把两个特性放进同一门语言 = `ΔΣ` 取并、`R` 取并。两个义务：

- **终止**：给每个算子一个**秩**（rank，= 它在消去序里的层号），要求每条规则的右手边
  只出现**更低秩**的算子。于是并集上的重写是良基的（多重集序下严格下降）——
  这一条把"nanopass 的顺序"从人排变成**算出来**（拓扑排序）。
- **合流**：两条规则的左手边**不许在同一棵项上都能匹配**（无重叠）；真要重叠就写
  **显式优先级**并记账。无重叠 + 终止 ⇒ 局部合流 ⇒ 由 Newman 引理得唯一正规形。
  这正是今天 `feature.js` 里"显式优于通配、冲突即错"那两句话的形式版本。

**唯一正规形**这件事直接兑现成一句工程话：**一份源码降出来的方言文本是唯一的**，
与特性的加载顺序无关。今天做不到这一点（`lower.js` 里的顺序处处要紧），
所以每加一族就要担心撞车。

### 2.4 分层 = 消去序；方言 = 不动点

按秩把特性分层：`L_k` = 消去掉所有秩 > k 的算子之后剩下的那门语言。于是

```
L_n = 源语言（jancy / C++ / Go …）
L_0 = 没有任何特性可消 —— 这就是**方言**（sx）
```

**方言不再是"设计"出来的，是算出来的**：`L_0` 的算子集 = 所有特性规则右手边用到的
核心算子的并集（I2）。今天 ADR-0031 在争论"方言该不该有整数宽度"，那场争论其实有
机械答案：把 `sizeof` / 位域 / `uint8_t*` 那几族的规则写下来，看它们的右手边**必须**
提到什么。提到"按宽度读写内存"，方言就得有；一条规则都不需要，就不该有。

## 3. 可删除性：语言切片 + 语料切片 + 逐字节相同

**"删掉 class"要能一条命令做到**，而且不改一行源码：

```
omni frontend jnc --without=class     # 造一个不带那格特性的前端
node tests/lib/slice.js jnc --without=class   # 语料切成"提它的"与"不提它的"两堆
```

三步判据，全是机械的：

1. **先印闭包**：`--without=class` 先算传递闭包 —— 谁要的能力**只有** class 提供，谁跟着
   出局（`class → virtual, basetype, opaque-class`）。名单先印出来给人看，
   而不是等编译报错才发现自己删掉了什么。
2. **语法上是错，不是静默**：`ΔΣ_class` 从签名里拿掉之后，`class C { … }` 在**读树那一层**
   就没有对应的算子 —— 报"这门语言里没有这个写法"。**删掉的特性不许留下"能过但错"的路径**，
   这是 I3 的骨头。
3. **剩下那门语言仍然完整**：拿"不提 class 及其闭包"的那堆语料，两个构建（全量 vs 切片）
   降出来的方言文本**逐字节相同**。不同就是有人偷偷依赖了 class —— 那正是要找的碎片。

这就是**可删除测试**：它既是架构的证明（没有隐式耦合），也是回归的网。代价是构建次数，
收益是"改一处不炸别处"第一次有了判据。

## 4. 级联影响怎么算（能力是唯一的间接层）

影响面 = 图上一次可达性计算，图**只有两种边**：`F —provides→ cap`、`G —requires→ cap`。
删 `F` 就把它的提供边去掉；哪个 `cap` 的提供者集合空了，所有 `requires` 它的特性进队，
重复到不动点。**特性之间没有直接边** —— 直接边一多，图就退回今天那张"谁也说不清谁依赖谁"
的网。能力名是一层很薄但强制的间接。

能力的粒度是这份设计里最要紧的手艺，三条原则写死：

- 能力是**语义承诺**，不是数据结构：`record`（有字段的存储）、`dispatch`（按运行期类型挑
  一个函数）、`scope-exit`（作用域出口能挂动作）、`indirect-call`（调一格函数值）、
  `layout`（字段偏移算得出来）、`gc-lifetime`（寿命由宿主管）。
- **至少两个可能的提供者才配叫能力**：`record` 由 class / struct / union 三家提供，合格；
  `vtable` 只有 class 提供 —— 那它不是能力，是 class 的内部事，别绕。
- 能力**不带类型参数**（不上 typeclass 那一套高阶）—— 够用，且保持可判定。

## 5. 契约"自动确定"：五份产物都从规则里算出来

写下 `⟨ΔΣ, R, C⟩` 之后，**下面五样一个字都不用手写**（这是"避免代码碎片"的正解 ——
碎片的根源是同一件事被人手抄进了五个地方）：

1. **方言需求**：`R` 右手边核心算子的并集。方言少一格 ⇒ **构建期**报错，
   而不是运行期一句"还没接"。ADR-0031 那份"方言承载力"清单从此是算出来的报告。
2. **诊断（账）**：一格位置 × 一格要素**没有规则** ⇒ 自动生成一条账，话由 `ΔΣ` 里那个
   算子的 `doc` 与位置名拼出来。今天 `features/*.js` 里那 24 条手写的 `say` 就是这一步
   的手工版；自动生成之后"认错人"这类毛病从根上没了。
3. **测试矩阵与例子**：Σ 的项枚举（sort × kind × 修饰词）→ 每格一份最小例子
   （ADR-0029 §11 已有雏形）。**特性一写完，判据就有了**，不用一格一格手攒语料。
4. **文档**：每个特性一节，出处（jancy / Go / C++ 的哪一行）+ 规则 + 判据位置 —— 从同一份
   数据渲染。ADR-0032 那张"合理化对照表"应该是这台机器的输出，不是手写的散文。
5. **顺序**：拓扑排序给出 nanopass 的层号；今天 `lower.js` 里"这一段要排在那一段之后"
   那十几条注释，都是这份拓扑序的手工痕迹。

## 6. 多语言：一门语言 = 词法 + 原子子集 + 三张表

`~/Documents/Lang/reference` 底下那几门语言按这套拆，共用的比想象的多。**先按能力对齐，
再谈语法**：

- **共用的原子**（今天 jancy 这条线上已经有实现的）：`record`（字段与布局）、
  `named-type`（typedef / alias / 命名空间）、`overload`（一台择优器，ADR-0029 §4.3 已落）、
  `member-call`、`indirect-call`（函数值）、`enum`、`array`、`ptr`、`scope-exit`、
  `errorcode`（早退 + 错误槽）。
- **go**：加 `goroutine`（→ 单线程事件队列，与 ADR-0032 §4 的 `async` **同一格能力**
  `task-queue`）、`channel`（→ 队列 + 阻塞点 = 续延）、`defer`（就是 `scope-exit`）、
  `interface`（→ `dispatch` 的另一个提供者：胖指针 + 方法表）、`multi-return`（→ 元组）。
  `defer` 与 jancy 的 `disposable` **共用同一份规则**，只换语法 —— 这是原子化的第一份红利。
- **vlang**：`option/result`（→ `errorcode` 那一族）、`sumtype`（→ tag + union，
  与 `variant_t` 同一格）、`immutable-by-default`（一格**属性检查**特性，不产生代码）。
- **mojo**：`ownership/borrow`（检查型特性：不产生代码，只在 `scope-exit` 上挂 drop）、
  `trait`（→ `dispatch` 第三个提供者）、`parameter`（编译期值 → 与 jancy 泛型
  **同一台单态化机器**，ADR-0025 已落）、SIMD（→ 方言已有的向量那一格）。
- **freebasic**：`stmt-flavored-syntax`（词法与语句形状不同，**原子基本全共用**）、
  `implicit-conversion`（一张偏序表 —— 就是 §4.3 那张表换一份数据）、`gosub/goto`
  （→ 结构化控制流的重写：一格状态机，与 `await` 切段同一份机器）。
- **sbcl / chez**（Lisp / Scheme）：`s-expr-syntax`（读树那一层换掉，**下游全共用**）、
  `dynamic-tag`（→ variant 那一格）、`macro`（**编译期重写** —— 恰好就是这份 ADR 的
  规则引擎自己，宿主语言的宏 = 用户可写的特性）、`call/cc`（→ CPS 变换：与
  `async` / `channel` / `gosub` 共用**同一格续延机器**）、`tail-call`（方言要一格保证）。
- **C++**：`template`（两阶段 + 单态化：jancy 泛型那台机器 + 一格"依赖名"规则）、
  `ADL`、`RAII`（= `scope-exit`）、`multiple-inheritance`（`layout` 的另一种提供者）、
  `operator-overload`（已落）、`exception`（`errorcode` 那一族的另一种落法）。

看这张表最要紧的一件事：**`call/cc`、`goroutine`、`await`、`channel`、`gosub` 落到同一格
"续延 / 状态机"机器上；`defer`、`disposable`、`destruct`、`RAII` 落到同一格 `scope-exit`
上；`interface`、`trait`、`virtual` 落到同一格 `dispatch` 上。** 这就是"不做原子化就永远
做不完"的量化答案：七门语言那几十族特性，真正不同的机器不超过十台。

## 7. 与既有系统对照（借什么、不借什么）

- **nanopass**（Racket）：借"很多小遍 + 每遍一个明确的语言"，**不借**"语言定义写在宏里"
  —— 我们要的是**数据**（可枚举、可切片、可生成文档与例子）。
- **Rascal / Spoofax / MPS**：借"重写规则是一等公民"，**不借**整套 IDE 与自家语言 ——
  一个新 DSL 会把"谁都能读"这条丢掉。
- **K framework / 项重写**：借终止与合流这两条**义务**（这份 ADR 的 §2.3 就是它们的工程版），
  不借它的完整语义框架（我们不需要证明程序等价，只需要正规形唯一）。
- **属性文法（attribute grammar）**：借"每个特性只声明自己那几格属性"，
  不借自动求值顺序 —— 顺序由消去序显式给出，看得见。
- **Featherweight / feature-oriented programming（FOP）**：借"特性组合与产品线"那套词汇
  （feature model、interaction、product），**并借它一条硬纪律**：
  **feature interaction 必须显式声明**（我们的显式优先级 + 冲突即错）。

## 8. 落地路径（不推倒重来，每步都有可量的产出）

1. **给现有五个特性补齐三栏**（`provides` / `requires` / `rank`），先只补声明、不动实现。
   产出：一张能力图（`omni features --graph`）与一份拓扑序，与 `lower.js` 里那十几条
   "要排在…之后"的注释对账 —— 对不上的每一处都是一笔账。
2. **把 emit 那一层改成规则表**，从三格开始（`record`、`enum`、`scope-exit`），
   每格的规则右手边只许用方言算子。产出：**方言需求集合**第一次是算出来的，
   与 `sexpr/lower.js` 里那张算子表对账（多出来的、没人用的，各是一笔）。
3. **可删除测试的骨架**：`--without=X` 只做到"语法上摘掉 + 印闭包 + 跑语料切片"。
   先拿 `props`（依赖它的人少）与 `variant` 试；再拿 `class` 试 —— 那一次会暴露一大批
   隐式耦合，**那正是这一步的价值**。
4. **诊断与例子改成生成的**：`features/*.js` 里那 24 条手写 `say` 撤掉，改由"缺规则"生成；
   语料按 sort × kind 生成最小例子。产出：手写判据的行数下降、覆盖矩阵上升。
5. **第二门语言接进来**：选 **V**（语法小、特性与 jancy 重叠大）或 **Go 的子集**，
   只写词法 + 原子子集 + 三张表，**一行降级代码都不写**。这一步是整份 ADR 的验收：
   如果还得写降级代码，说明原子切得不对。

## 9. 代价与放弃

- **构建变慢**：可删除测试是 N 个构建 × 语料切片。对策：只在提交前跑全量，平时跑
  "受影响的那几格"（能力图给出影响集）。
- **规则表达力有上限**：纯项重写写不下"要看全局信息"的那几族（重载择优、作用域查名）。
  所以保留**求解器**这一类零件（已有：择优器、作用域图），规则里以**副作用自由的查询**
  形式调用它们。这条界要写在每个特性的文档里：它用了哪个求解器。
- **短期会更慢**：前三步基本不产出新特性。这份 ADR 主张这笔钱值得花 —— 因为按今天的
  粒度，jancy 之后每加一门语言都要重来一遍 15,000 行。
- **不做的**：不做用户可写的宏（Lisp 那一格例外，它自己就是这套引擎）；不做增量重写；
  不做规则的形式化证明（只做终止与无重叠的**检查**）。

## 10. 一句话

**特性是数据，语言是特性的子集，方言是消去的不动点，删除是集合运算，测试是差分。**
这四句话每一句都对应一个可执行的检查 —— 那才是"公理化般的严格"在工程里的样子。

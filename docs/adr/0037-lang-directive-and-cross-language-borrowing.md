# ADR-0037：`#lang` 与跨语言借用（读入器可换 · 借别人的实现当标准库）

状态：**提议**（本文是设计；未改一行代码。落地顺序与判据在 §7）

关联：ADR-0009（模块路径）、ADR-0014（sexpr 前端与 LLVM 后端）、ADR-0021（分语言插件）、
ADR-0022 的 J4d（`import "libfoo.dylib" with "foo.h"`）、ADR-0029（前端的形式化分解）、
ADR-0031（`sx` 的承载力 = 语言与方言的契约）、ADR-0033（特性代数）、ADR-0034（`.y` 直接收）

---

## 0. 两件事，与它们共用的那一格

- **事情一**：`#lang`（读入器可换，默认**关**）+ **卫生宏**。宏管"语法兼容的内置 DSL"，
  `#lang` 管"语法不兼容也能进来"的那一半通用支持。
- **事情二**：**跨语言借用**四档 —— 同层编译 / 跨层 FFI / 语法空间 `as g` / 进程边界。
  标准库的策略跟着它走：**先借，自带的后写**（今天 `src/lib` 只有 `json.omni` 与 asy 那一摊）。

两件事看着无关，底座是同一格，所以合在一份 ADR 里：

| 底座 | 事情一要它做什么 | 事情二要它做什么 |
|---|---|---|
| **语法对象**（树 + span；作用域集**不必加**，见 §4.1） | 宏在它上头重写；`#lang` 的产物就是它 | `as g` 那一档交给用户的就是它（同像能力） |
| **语言注册表**（`plugin.js` 的 `registerLang` / `declareProvider`） | `#lang <名字>` 查的就是这张表 | `import "x.nim"` 认语言查的也是这张表 |
| **方言词汇**（ADR-0031 的类型与算子） | 宏引入的算子要落进它 | 两门语言"契约一致"是在它上头判定的 |

一句话：**`#lang` 换的是"哪台读入器"，借用换的是"边界画在哪儿"，中间那棵树只有一种。**

## 1. 现状：先摆这棵树里的事实

- **认语言只按后缀**。`registerLang(exts, name, compile)`（`src/core/plugin.js:98`）；
  类型模式也只按后缀：`MODE_BY_EXT = { '.omni', '.omnid', '.omnis' }`（`src/core/module/load.js:39`），
  而 `load.js` 头上那段明写着「不猜后缀 —— 后缀同时决定模式，猜后缀就等于猜模式」。
  **今天一份文件的语言由文件名决定，源码第一行说不上话。**
- **`import` 只有一种形态**：`import "./util.omni";`（`src/core/parse/parser.js:277-286`）——
  没有 `as`、没有 `with`、没有语言标记。
- **`with "x.h"` 只长在 jancy 上**：`src/core/frontend-jnc/lower.js:9865`，靠 `cap('c.declsOf')`
  （`src/core/lang/c.js:302`，实现是我们自己那台 C 前端）。omni 自己那门语言没有这一格。
- **宏一格都没有**。全树搜"宏 / macro"，命中的全是 C 后端的 `#define`（`hir/js_abi.js`、
  `sexpr/lower.js:1130` 那类）—— 没有任何展开机制、没有 `define-syntax`。
- **语法对象缺一半**：s-expr 读入器出的是三种节点 `{kind:'list'|'atom'|'string', …, span}`
  （`src/core/sexpr/read.js:15-18`），**每个节点都带 span**（好消息），但没有作用域集。
- **语法可以是数据**：GLR + `.grammar`，`.y` 直接收（ADR-0034）。一门新语言的 L0 不必手抄。
- **借用要优先的那三门，L0 已经在了**：`ext/go/go.grammar`、`ext/nim/nim.grammar`（405 条产生式）、
  `ext/vlang/vlang.grammar`，各带一份 `tograph.js`（CST -> 节点图）与 `examples/`。
  **（修正）**初版这一条写的是"节点图那层没有 js 后端，所以编到 js 卡在一格后端"——**错的**，
  是照 `ls src/core/graph`（没有 `backend-js.js`）推的。js 后端在，只是**写在
  `contract.js` 里**（`registerBackend({name:'js', …})` + `jsLower`），而且
  `tests/graph/run.js` 那张矩阵印着 **js 108/108 跑通**。
  真正缺的是**产物**：`build --engine graph --backend js` 从前明着拒绝（"那份文本是一格函数
  表达式，要外面喂十几个运行时钩子"）。那一格第一百五十一片补上了（`graph/js_rt.js`
  + `.mjs` 自足产物），判据 `tests/graph/js-artifact.js` 40/40。
- **跨层那一半已经有两块**：封闭的 `C_ABI` 表（`src/core/hir/c_abi.js`）与 `C_SYSLIBS`；
  但**类型词汇只有七格标量**，聚合体按值、数组、回调「一律不支持」（那份文件头上的原话）。
- **标准库现状**：`src/lib` = `json.omni` + `asy/`。所以"借用优先"不是偏好，是现状的名字。

## 2. 决定（十一条，结论先摆出来）

- **D1** `#lang` 是**读入器指令**，不是新语言、不是新后缀。它只回答一个问题：
  这份文本交给注册表里**哪一格** provider 去读。
- **D2** `#lang` **默认关**。开法两处（不设第三处）：命令行 `--lang-directive`、
  环境 `OMNI_LANG_DIRECTIVE=1`。关着的时候遇到 `#lang` 一行**当场报**并给出开法 ——
  静默当注释是最坏的一种（与 `--profile` 认腿那条纪律同一条：收下开关一声不响不许有）。
- **D3** 一份文件的语言由三处按**固定优先级**决定：`#lang` 行 > 命令行 `--as <名字>` > 后缀。
  三处给了**不同**答案就报（印出三处各说了什么），不许"最后一个赢"。
- **D4** 宏跑在**语法对象**上，不在文本上。语法对象 = `read.js` 那三种节点各加一格
  `scopes`（作用域集）。**不新开表示**：`{kind, span, scopes, …}` 仍是那三种。
- **D5**（**修订**）卫生照 **Nim 那两趟**：定义期把体里的局部标成 gensym、自由名字**在定义处
  绑定**、体里定义的函数默认 inject；展开期按位置替形参 + 一张 per-展开 的 mapping 表换名
  （`semtempl.nim` / `evaltempl.nim`，见 §4.1 那张对照表）。
  **不用 set-of-scopes**：Racket 那套要给每个节点挂一格作用域集 + 一个子集最大匹配的解析器，
  而 Nim 用两趟拿到同一份卫生（含"模板里的 `+` 不被调用处的局部 `+` 遮住"那一条），
  代价只是要求"定义处查得到名字"。初版写的是 set-of-scopes，这一条是明着改的。
- **D6** 宏展开是 ADR-0029 那七层里插在 L1 之后的一步（记作 **L1.5**），输出仍是 AST；
  L2（位置矩阵）/ L3（作用域图）/ L4（类型偏序）/ L5（nanopass）**一格不动**。
- **D7** 借用四档写成**一张表**（§5），每档有自己的边界、语法、契约与判据。
  `import` 的语法只加三格：`as g`、`with "…"`、`via <协议>`。
- **D8** `import "x.py" as g` 的 `g` 是**语法空间句柄**，不是模块对象：`g` 上的操作是
  查 / 改 / 展开 / 拼语法树（同像能力）。"直接当函数调"是**契约一致时的特例**，不是通例。
- **D9** 契约一致性是**算出来的**（ADR-0033 的 I2 同一条路子）：两侧各交一份
  「用到的方言算子集 + 类型词汇集」，缺一格是**构建期错误**，不是运行期"还没接"。
- **D10** 进程边界那一档走 **JSON-RPC over stdio**（`spawn` 已有，`src/core/host/native.js`）。
  它的判据是唯一能证明"档与档可换"的那一条：**同一份调用在同层与跨进程两条路上答案相同**。
- **D11 标准库先借后写**：这一份 ADR **不承诺任何自带库**。凡是"某个功能要不要自己写一遍"
  的问题，先答"哪一档借得到"（`with` 一个头、`via rpc` 一个包），借不到再谈自己写。
  自带库的第一批只写**借不到的那些**：与方言词汇绑死的那几格（值语义的容器、错误模型的壳）。

## 3. 事情一（上）：`#lang`

### 3.1 形状与词法的一格便宜

```
#lang omni                  ;; 就是默认那门（写出来只为显式）
#lang sx                    ;; 这份 .omni 文件里躺的是 s-expr
#lang jnc                   ;; 一份 .omni 里躺 jancy
#lang glsl frag             ;; 名字之后的词原样交给那门语言（这里是"片元着色器"）
```

**必须是第一行**（允许前面只有空白与 shebang）。两条理由都是可验证的，不是审美：

1. `#` 在 s-expr 读入器的 idchar 表里（`src/core/sexpr/read.js:25` 那一行原样含 `#`）——
   于是 `#lang` 对读入器就是一个普通 atom，**认它不用改词法**；
2. C / js / jancy 那几门里，行首 `#lang` 都不是合法代码（C 那边是未知预处理指令），
   所以"一行 `#lang` 被误当程序"这件事在所有已装的语言上都不成立。

### 3.2 开关（默认关的那一格怎么关）

| 处 | 形状 | 说明 |
|---|---|---|
| 命令行 | `--lang-directive` | 一趟有效；`run` / `build` / `emit` / `repl` 都收 |
| 环境 | `OMNI_LANG_DIRECTIVE=1` | 给 `spawn` 出去的子进程继承用（与 `OMNI_PROF` 同一手法） |

关着时的诊断（措辞钉住，判据要比它）：

```
x.omni:1: #lang 这一格默认关着 —— 一份文件的语言默认只由后缀决定（ADR-0009）。
  开法：加 --lang-directive，或 OMNI_LANG_DIRECTIVE=1。
  装着的读入器：omni / sx / jnc / js / asy / glsl / wat / c
```

最后一行来自 `langNames()`（`src/core/plugin.js:212`，`cli.js:1278` 已经在用它印同一份表）——
**"有哪些"只有一处说法**，声明了还没装进来的也算（`declareProvider` 那一格，同一个函数已经这么做）。

### 3.3 `#lang` 与后缀的关系（D3 那张优先级）

`#lang` **不改**类型模式（`mixed` / `dynamic` / `static` 仍由后缀定，ADR-0008）——
它只换读入器。于是 `.omnis` + `#lang sx` 是合法组合：静态模式的 s-expr 源文件。
冲突的例子与报法：

```
x.jnc:1: #lang js 与后缀 .jnc 说的不是同一门语言
  #lang 行说 js、后缀说 jnc、命令行没说。
  要按 #lang 走就把文件改名（或用 --as js 明说），要按后缀走就删掉这一行。
```

### 3.4 一门 `#lang` 要交什么（provider 的形状）

沿用 `declareProvider({ name, exts, caps, … }, load)` 那一格，只多两栏：

```js
declareProvider({
  name: 'sx',
  exts: ['.sx'],
  langNames: ['sx'],          // ← 新：`#lang` 认的名字（可以不等于 exts）
  reader: 'sx.read',          // ← 新：cap 的名字，签名 (file, diags, argv) -> AST
  caps: ['sx.textToMod'],
}, () => registerSxLang(api));
```

`reader` 那一格是 `#lang` 唯一新增的接口。今天五门语言的 `compile(path, argv)` 已经等价于
"读 + 降"合在一起（`registerLang` 的第三个实参），所以第一步落地**不必**把它们拆开：
`#lang <名字>` 先直接改派到那门语言的 `compile`，`reader` 是给"同一份文件里换读入器"
（宏与 DSL 要的那一格）留的位置。

## 4. 事情一（下）：卫生宏

### 4.1 卫生怎么落：照 Nim 那两趟（**修订：不用 set-of-scopes**）

初版这一节写的是"每个节点加一格 `scopes`、按 set-of-scopes 解析"。**改了**，理由不是审美：
Nim 用**更便宜的两趟**拿到同一份卫生，而且它那两趟正好落在我们已有的结构上。
参考实现（本机 `~/Documents/Lang/reference/Nim/compiler/`）：

**第一趟 · 定义期**（`semtempl.nim`，模板体在**定义处**就走一遍带作用域栈的遍历）：

| Nim 那一条 | 在哪儿 | 我们照抄什么 |
|---|---|---|
| **局部默认 gensym** | `addLocalDecl`（`semtempl.nim:185`，注释原话 "locals default to 'gensym', fields default to 'inject'"）；`newGenSym` 打上 `{sfGenSym, sfShadowed}`（`:181-183`） | 体里 `let` / 形参引入的名字，标成"这一格要换名" |
| **自由名字在定义处解析** | `qualifiedLookUp` + 换成 `nkSym` 节点（`semtempl.nim:299` 那一族） | 体里引用的外部名字，在**定义处**绑定成一格**具体引用**（不再是一个待查的名字） |
| **routine 默认 inject** | `semRoutineInTemplBody`（`:311`，注释原话 "routines default to 'inject'"） | 模板体里定义的函数**不换名**（它就是要泄出去的那格） |
| 显式覆盖 | `{.inject.}` / `{.gensym.}`（`symBinding`）、`mixin` | 同名两格标注；`mixin` = 明说"这个名字留到用处再查" |
| 作用域栈 | `openScope` / `closeScope`（`:170-179`） | 我们两台解释器与各前端都已经有这一格 |

**第二趟 · 展开期**（`evaltempl.nim`，"Template evaluation engine. Now hygienic." 那一行）：

- 形参**按位置**替（`handleParam actual[s.position]`，`evaltempl.nim:53-56`）；
- **每次展开一张 mapping 表**（`TemplCtx.mapping`，`:19-21`：注释原话 "every gensym'ed symbol
  needs to be mapped to some new symbol"），gensym 的名字换成 `` name`gensymN ``
  （`:73-74`，`N` = `instID`，一次展开一个号）。

**这一改省掉了初版的第 1 步**：不必给三种节点各加一格 `scopes`、不必写子集最大匹配的解析器。
代价写清楚：Nim 这套的"定义处解析"要求**那门语言在定义处查得到名字** ——
所以第一格落在 `sx` 上（顶层名字与算子表在读完那一遍就齐了），而不是先落在 asy / jnc 上。

**（修订 · 用户指出的一处）落在 `sx` 上只是第一格，不是终点。**
`sx` 是**中间格式**，不是 omni 主语言 —— 卫生宏这一格**必须在 omni 主语言上有实现版本**
（那门语言自己的前端：`parse/parser.js` 的 AST + `hir/check.js` 的作用域）。
两处的关系是：

- `sx` 那一份（`sexpr/template.js`，已落地）验的是**机制**：两趟的分工、gensym 的号、
  定义处绑定那一手在一门"顶层名字读完就齐"的语言上成立；
- **omni 主语言那一份**（`hir/template.js` + `parse/parser.js` 的 `parseTemplate`，**已落地**）
  才是给人写的那一格：`template 名(形参) { … }` 与函数同形的调用点、`let`/`var`/`for`
  引入的局部按 gensym、自由名字在**模块作用域**里定义期解析。

落点最后不在 `compileProgram`（那儿拿到的是**整张模块图拼好**的 decls），而在
`module/load.js` 里 parse 之后 —— 一份文件展开自己的模板，模板不跨模块，检查器一个
`TemplateDecl` 都见不到。`template` 是**软关键字**（不进 KEYWORDS 表，判据是
`template` + 名字 + `(` 三个 token 连着），所以现有语料一个字节都不受影响。

判据：`tests/cli/lang.js` 第七、八节（8 条）。三条性质写成 omni 的语法一份文件跑完
（`10 / 5`、`1 / 1`、`2 / 1`），加上"展开两次两个号"、四处拒绝、以及**中性**那一条
（`bench/fib.omni` 开关开与不开输出逐字节相同）。

**这条腿与 `sx` 那条腿差一格，明着记在这儿**：`sx` 那份把模板体里的模块级引用改写成
`(gvar 名)`，所以调用处的同名局部**遮不住**它；omni 这份做不到同一件事 —— 检查器给遮蔽的
声明**不改名**（`hir/check.js` 的 `Scope.declare` 原名入表，没有 alpha 改名那一趟），
于是"改写成模块级引用"在降到 OIR 之后仍会被内层那一格接住。所以这一格**报**：
"调用处有一个局部 'x'，会遮住模板 … 这一格还没接"。静默取错那一个是最坏的一种。
要补齐得先给检查器加一趟 alpha 改名 —— 记在 §8。

另一格差别是**顶层语句是合成入口函数的局部**（omni 的模块级变量不是全局）：所以模板体引用
模块级变量、而调用点落在函数体里时也**报**，报的就是这句话。

### 4.2 两层宏，各自一格开关

| 层 | 形状 | 编译期跑谁的代码 | 默认 |
|---|---|---|---|
| **模板宏** | `(define-template 名 (形参…) 体)`（Nim 的 `template`：按位置替 + 上面那两趟） | 谁都不跑，只重写树 | 跟 `#lang` 一起开 |
| **过程宏** | `(define-macro 名 (树) 体)`（Nim 的 `macro`：宏体是真代码，收树回树） | **跑用户的代码** | **另一格开关，单独开** |

Nim 自己就是这两层（`template` 与 `macro` 是两个关键字，后者跑在它那台编译期 VM 上）——
所以"两层"不是我们的发明，是那门语言已经验证过的分法。

过程宏不必新写求值器：我们已经有两台（`src/core/interp/eval.js` 与 `src/core/mir/interp.js`）。
但它把"编译一份文件"变成"跑一份别人的程序"，所以它是**第二格开关**
（`--macro-eval`），而且诊断里要明说"这一趟在编译期跑了你的代码"。

### 4.3 三条卫生用例（判据就是它们）

写成我们这边的形状（Nim 的 `template` + 按位置的形参）：

```
;; 1. 体里引入的局部不许捕获调用处的名字（Nim：locals default to gensym）
(define-template my-or (a b) (let ((t a)) (if t t b)))
(let ((t 5)) (my-or false t))     ;; 要 5，不是 false

;; 2. 体里引用的外部名字不许被调用处遮住（Nim：自由名字在定义处绑定成 nkSym）
(define-template add1 (x) (+ x 1))
(let ((+ *)) (add1 3))            ;; 要 4（模板里的 + 是定义处那个 +）

;; 3. 两个洞都是调用处的名字，一个都不许换（经典 swap!）
(define-template swap! (a b) (let ((t a)) (set! a b) (set! b t)))
```

gensym-only 能过第 1 与第 3 条，**过不了第 2 条** —— 那一条就是 Nim 定义期那半趟
（`qualifiedLookUp` 换 `nkSym`）在判据上的样子，不是偏好。

第四条判据（Nim 有、Racket 那套里叫 `datum->syntax` 的反面）：**inject 要能明说** ——
体里定义的函数默认泄出去（`semRoutineInTemplBody` 那一条），而局部要泄出去得写标注。

### 4.4 内置 DSL = 宏 + 位置矩阵的一行（不是新读入器）

"语法兼容的内置 DSL"这句话在这套分层里有确切的落点：

- 语法一格不加（所以叫"语法兼容"）：DSL 的入口就是一个普通调用形式；
- 展开规则一条条写在模板里，出的是**核心形式**；
- 它能出现在哪儿由 ADR-0029 §4.1 那张 **Sort × Kind 矩阵**里加一行说，
  而不是靠"在哪儿写都行"；
- 它对方言的要求（要哪几格算子）由模板右手边**算出来**（ADR-0033 的 I2）；
  方言缺一格 = 构建期错误。

### 4.5 与特性代数的三条对齐

| ADR-0033 的不变量 | 宏这一格怎么满足 |
|---|---|
| I1 原子性（自己把自己消干净） | 展开的不动点里不许再出现宏引入的形式；查得出来（一次遍历） |
| I2 契约自动 | 宏要求的算子集 = 所有模板右手边算子的并集 |
| I3 可删除 | 关掉宏这一格重编：DSL 语料变语法错，**其余语料输出逐字节相同** |

## 5. 事情二：跨语言借用的四档

一张总表（这一节的正身，下面四小节是每格的展开）：

| 档 | 边界在哪 | 语法 | 何时用 | 契约怎么算 | 代价 | 判据 |
|---|---|---|---|---|---|---|
| **一 · 同层编译** | 没有边界：一起降到同一棵 sx | `import "./x.nim"` | 那门语言的前端我们有 | 方言词汇的交集（可判定） | 要写它的 L0 语法 + L5 规则 | 与手写同一功能的 `.omni` 输出等价 |
| **二 · 跨层 FFI** | 一条 C ABI | `import "libfoo.dylib" with "foo.h"` | 一边在 js/我们这层、另一边是 native | C 头文件里的声明（`cap('c.declsOf')` 现成） | marshal；聚合与回调今天缺 | 同一份头，两侧收到的声明集合逐条相同 |
| **三 · 语法空间** | 一棵树 | `import "./x.lang" as g` | 语法契约**不**一致 | Σ（多类签名）校验树的合法性 | 自己动手改写，不带卫生 | `g` 读进来再打印回去，与它自己的 sx 逐字节相同 |
| **四 · 进程边界** | 一根 stdio | `import "./x.py" via rpc` | 那门语言我们没有前端 | 一份接口描述（按方言词汇写） | 拷贝语义、启动与往返开销 | **同一份调用在第一档与第四档答案相同** |

**选档不许靠猜**：`import` 的写法就是选档（`as` / `with` / `via` 各指一档，都不写 = 第一档）。
第一档拿不到那门语言的前端时**不自动降级**到第四档 —— 报一句"这门语言只有 `via rpc` 那条路"。
悄悄换档就等于悄悄换语义（值语义在第四档只能是拷贝），那是最坏的一种。

### 5.1 第一档：同层编译（都落到 js / c / wasm）

**先做哪三门是定了的：go / nim / vlang。** 理由不是喜好，是**调用形状与我们基本兼容**
（位置实参、返回值一格、方法 = 名字 + 一格 self），于是 §5.1 那三条自动转换的条件最容易全中。
它们的现状（`ls ext/`）：

| 门 | L0 语法 | CST -> 节点图 | 例子 | 跑在 js 上 | `.mjs` 产物 |
|---|---|---|---|---|---|
| go | `ext/go/go.grammar` | `ext/go/tograph.js` | 13 份 | ✓ | ✓ |
| nim | `ext/nim/nim.grammar`（405 条产生式） | `ext/nim/tograph.js` | 15 份 | ✓ | ✓ |
| vlang | `ext/vlang/vlang.grammar` | `ext/vlang/tograph.js` | 12 份 | ✓ | ✓ |

所以"编到 js"这一格**已经成立**（`tests/graph/js-artifact.js` 40/40：产物 node 直接跑、
且与本进程那条腿逐字节相同）。往下要选的不是"有没有 js"，是**要不要那套 omni 的语义**：

- **A. 停在节点图这一层**：现在这样。图上的数就是宿主的 number、真值观最保守一档、
  map 的印法明着不定 —— 够跑例子，也够跑那三门的"纯计算"库；
- **B. 把 `tograph.js` 的产物接到 `sx`/OIR**：一次接通，**js / c / wasm / llvm 四条腿一起有**，
  ADR-0011 那套语义（int = i64 的规范形、字符串按字节、闭包按值捕获）与摇树、profile、
  REPL 全都白得；代价是那 28 格算子要映到方言词汇上（ADR-0031 那张表正是为这件事写的），
  而且**图上没有类型**这件事要在映射那一侧补齐。

**倾向 B**，理由与 ADR-0034 那句一样：不新开一条路，就不会有两条路走散。
但 B 不是"编到 js"的前提 —— 它是"用 omni 的语义编到 js"的前提，这两句话不该混。

"无缝函数调用"的可判定条件（三条全中才自动，缺一条就报，不猜）：

1. **类型都在方言词汇里**（ADR-0031 §1~§3）：参数与返回的每一格都能表示；
2. **调用约定同一格**：都落成方言的 `(fn …)` / `(ccall …)` 之一；
3. **错误模型同一格**（ADR-0007）：要么都用可失败调用，要么两侧显式适配（生成一层薄壳）。

三条里第 1 条最容易缺，而且**缺的地方是已知的**：`C_ABI` 那七格标量、`sx` 缺聚合按值拷贝。
于是这一档的进度不由"又接了一门语言"衡量，而由 **ADR-0031 那几格补齐了多少**衡量。

### 5.1a 尺子：编得动它们自己的编译器

go / nim / v 的编译器都是**用它们自己写的**。所以这一档有一把现成的、不掺水的尺子，
分四级（与我们自己那条 N1/N2 自举链同一形状）：

| 级 | 判据 | 说明 |
|---|---|---|
| ① | 编得过它们 stdlib 的**一个**模块，输出与官方编译器一致 | 语法与降级的第一道真墙 |
| ② | 编得过**整棵** stdlib | 这一级会把泛型 / 效应 / 生命期那几栏逼出来 |
| ③ | 编得过**编译器自己**（一遍） | 这是"完整解析"这句话唯一的证明 |
| ④ | 编出来的那个编译器**能再编一遍自己**，两代产物逐字节相同 | 闭环；与 `OMNI_CC=self` 那条链是同一条纪律 |

**不许把 ③ 当下一步**：它是尺子，不是任务。任务是 §7 那张表。

**（2026-09-17 量的第一遍，那三门自己的编译器）** —— `node bench/tograph.js`。

`ext/go/examples/vardecl.go`（第二十个家族，go 独一份）—— 它同时把**模块级变量**压在

**第二刀（同日，同一份文件）**：`switch` 55 那一条 —— go 的 switch **没有隐式贯穿**，
所以它就是一串 if / else if / else，落的是现成的 branch 链（主语只算一次 -> 一格 `bind`
到 `__swN`；一个 case 几个值 = `lazyOr`；`default` 是最里那一层 else，写在中间也垫底）。
这一刀顺带钉住两处**答案错而不报**：switch 里的 `break` 在 go 里是跳出 switch，落成
branch 链之后会变成跳出循环 —— 当场报；带标签的 `break L` / `continue L` 跳的不是最近
那一层，原来把标签直接丢了 —— 也当场报。判据是 `ext/go/examples/switch.go`（第二十一个
家族），**六条腿全绿**。

**第三刀（同日，同一份文件）**：`for-range` 58 那一条 —— 落的是现成的 `counted`

序列与长度**都只算一次**（规范的原话）、第一格是下标第二格是元素（`index-get`）、
`:=` 出 bind 而 `=` 出 set。**判得出来的两种当场报**：range 一格 map（要按键遍历，
图上没有那一格，而次序在 go 里本来也是不定的）与 range 一格整数字面量（1.22 起的写法）。
**判不出来的两种明说了**（写在 `ext/go/tograph.js` 末尾）：串（go 给 rune，`s[i]` 给字节）
与通道 —— 这一格沿用 `MAPS` 那条既有约定"没登记成 map 的当序列"。判据是
`ext/go/examples/forrange.go`（第二十二个家族），四条腿绿、两条腿按名有姓地跳过

这一刀只多 1 份（58 -> 59）：`range` 那 58 份里绝大多数还压着别的墙。这个数**本来就该
这样读** —— 下面那句话说的正是它。

**注意这把尺子的读法**：补掉一条墙，那些文件只是走到**下一条**墙 —— 所以 `addr` 45 -> 74、
`fnlit` 22 -> 55 都是**涨了**的。唯一算数的分子是"整份落成图"那一栏（31 -> 53 -> 58 -> 59）。

**vlang 那一刀（同日，`ext/vlang/tograph.js`）**：前四条墙里有三条是同一族"顶层的声明与
修饰"，而最高那条 `typedecl` 283 **又是死代码**（标签是 `typedecl`，写的是 `type-decl` ——
与 go 那两条一个错）。这一刀判的是"该丢还是该拆"，只有这门语言说得清：`pub` 与 `@[inline]`
**不产生代码**（与 `mut` 同一类）所以拆一层接着走；`type X = A | B` 与 `interface` 是
**类型的声明**所以整格丢掉；`const a = 1` / `const ( … )` / `__global ( … )` 落一串 bind
（V 这一格比 go 干净：语法里就写着 `IDENT "=" expr`，没有"省略初值重复上一条"与 `iota`）；
`true` / `false` 在 V 里是自己一条产生式（`(bool …)`）不是名字。顺带堵了 `const m = map[…]{…}`
不进 `MAPS` 表那个"答案错而不报"。判据 `ext/vlang/examples/decls.v`（第二十三个家族）。
量：**75 -> 197（3.5% -> 9.3%）**。

**这两次"死代码"催生了一格判据**（`tests/graph/deadcase.js`）：映射里每一格
`case '标签'`，那门语言的语法都得**出得来**这个标签。出不来就是死代码 —— 要么标签写错了
（背后一定有一批文件在墙上），要么那条产生式没了。反方向（语法出得来但映射没接）不在那儿：
那正是墙，`bench/tograph.js` 在量。**这两次都是靠外部尺子才发现的**，例子与判据全绿 ——
因为例子里正好没有那一格。

这格判据一上来就又找出四处，其中两处是**真缺口**：lua 与 awk 的 `case 'un'` ——
两门的语法给一元算子**各自一条产生式**（`(neg …)` / `(not …)` / `(len …)`），
所以 `-x` / `not x` / `#s` 从来没落成过图。补上之后又撞出**core 后端发的 `(not …)`
方言不认**（方言写的是 `(un "!" …)`，`sexpr/lower.js:2894`）—— 一条错了很久、
没有任何判据碰得到的路。另两处（mojo 的 `from-import` / `alias`、cpp 的 `name`）
是标签改过名留下的空壳。

**vlang 第二刀（同日）**：`match` 95 与 `for-in` 87 —— 与 go 那两刀是同一个形状
（branch 链 / `counted`），差别正是"归语言的那几条"：

  * **`match` 还是表达式**（go 的 switch 只是语句）。语句位置上主语落一格 bind（只算一次）、
    各支的体是 region；表达式位置上每一支要交出一个**值**，而 bind 摆不进表达式位置 ——
    那一路把主语原样抄进每格比较，所以只接主语是名字或常量的（别的当场报"主语要算好几遍"
    —— 抄一个带作用的表达式进去就是多算几遍，那是错而不报），而且**必须有 `else`**
    （掉出去那一路没有值）。分支左边是类型的那一族（sum type）当场报。
  * **`for x in xs` 里 x 是元素**，两个名字才是"下标 + 元素" —— 与 go **正相反**
    （`for i := range xs` 里 i 是下标）。`for i in 0..4` 是区间：没有序列，终点只算一次，
    上界不含。

判据 `ext/vlang/examples/match.v`（**六条腿全绿**）与 `forin.v`。量：197 -> 201 ——
**只多 4 份**，那 180 多份里绝大多数还压着 `assert` / `ctime` / `addr`。

**vlang 第三刀（同日）**：位置型结构字面量（`Point{1, 5}`）。它只给了**值**，而
`record-new` 要的是**字段名** —— 所以名字与顺序从**声明**来（`STRUCTS` 那张表）。
这条路子不是这一门特有的：mojo 的 `@value struct`、CL 的 `defstruct`、Scheme 的
`define-record-type`、FB 的 `Type … End Type` 都是同一条"名字与顺序从声明来"，V 是
第五个提供者。V 特殊的只有一样：**同一条产生式两种写法**（位置型出 `(positional …)`、
带名字的出 `(f 名 值)`），混着写 V 自己也不许 —— 这儿当场报。声明不在这一份文件里、
或者那个 struct 有**嵌入字段**（嵌入的那一格在构造顺序里占几格要展开被嵌类型才知道），
也都当场报。判据 `ext/vlang/examples/posinit.v`，**六条腿全绿**。量：201 -> 205。

**`assert` 那一刀做完了（2026-09-18）**：它成了节点清单里的**第 28 格**，也是这份清单里
**第一格"账上算出来的"节点** —— 量到 578 份文件的第一堵墙是它（占还没落成图的 1918 份的 30%），
才决定给它一格。接上之后 vlang 那一栏 **205 -> 594（9.7% -> 28.0%）**：一格节点拉了
18 个百分点，因为它挡在最前面，那 578 份开始走到下一条墙。
判据三格（缺一不可）：`ext/{vlang,mojo}/examples/assertok.*`（断言成立那一路、两门共一族）、
`tests/graph/assertfail.js`（**不成立那一路** —— 那句话印出来了没有 + 后面那一句真的没跑；
各腿的"停下来"不同形、退出码不在图上，所以矩阵那张表比不了它）、`delete.js` 里那一行。
两条腿有名有姓地不接：wat（`unreachable` 会把已经印出去的话一起吞掉）与 core
（**核心方言里没有"停下来"那一句话** —— 词汇表在下一层也欠一格）。

下面这一段是**那一刀之前**的记录，留着当由头：vlang 那时最高的墙是 `assert` 578—— 它要的是一格
"停下来"的内建，图上的 prim 表里没有，所以**那也不是映射的账**（与下面这句同一类）。
**这一格已经定了怎么落**（2026-09-18 的决定）：一格**专用的 `assert` 节点**，

assert 是一句**断言**（可以按开关整格删掉、可以带消息），而 abort 只是"停下来"。
做那一刀要动 prims.js / 六条腿 / 契约那五问 / delete.js 的账。

**nim 那一刀（同日，`ext/nim/tograph.js`）**：`for … in` 落 `counted`（区间在 nim 里是

`case` 落 branch 链（nim 的 case 里除了 `of` 还能有 **`elif`** —— 那一支走自己的条件，
go 的 switch 与 V 的 match 都没有这一格）、`(nil)` 与 `discard` 与 `from` / `export`。

    回的就是 undefined —— `.slice` 当场炸成看不出所以然的 TypeError。**一句"报"炸成崩溃**，
    八份一起改成 `String(JSON.stringify(x))`。
  * 那个崩溃的根在 nim 的 `bracket`：`p[]`（解引用）的下标那一格是空的，原来把 undefined
    一路往下传。现在当场报"图上没有指针那一格"。

**第三类账：编译期求值。** nim 的 `when` 27 与 V 的 `ctime` 142 / `ctconst` 100 既不是
映射的账也不是词汇表的账 —— **它们不能丢**（`when defined(windows): …` 丢掉就少一段代码，
顶层的 `when` 里还装着声明），**也不能落成运行期 branch**（没走的那一支在 nim 里根本不
要求编得过）。那是 §7 第 9 步（过程宏 + `--macro-eval`）那一刀的事。

**尺子会骗人的一次（2026-09-18）**：`<<` 那 98 份印的是"这个算子还没接"，看着是**位运算**
—— 我据此估过一句"位运算那一刀最便宜"。**抽一遍语料才知道那句话是错的**：V 自己的编译器里
3228 行含 `<<`，其中只有词法表那几行是位移，其余全是 `nodes << x` / `lines << continued`
这种**数组追加**。所以那 98 份要的是"追加"，与位运算无关。

落法：**一格内建 `prim push`，不是一格节点**。两格实参都是普通的值（要追加的那格表、
要追加的那个东西），没有"哪一格是什么角色"要分 —— 与 `len` 同一类，是列表上的一个库函数
（`nodes.js` 文件头那条：给库函数开节点等于给每门语言的每个库函数开节点）。
这也正是它与 `assert` 的分界：那一格的消息是**自己的端口**，所以那一格才是节点。
五条腿接了（core 那条走方言现成的 `(apush …)`），wat 那条有名有姓地欠着。
判据 `ext/vlang/examples/push.v`（第三十个家族）。量：**594 -> 653（28.0% -> 30.8%）**。

**又一刀映射（同日）**：`none` 93 与 `array-fixed` 88 —— 两条都便宜，而且各带一条要说清的话：
  * `[10, 20, 30]!` 是**定长数组**字面量，落的还是那一格 `list-new`："定长"是**类型上**的
    性质，而类型不进图。
  * `none` 是 V 的 Option 空值 -> 落 nil。**它与三段 `for` 里那个空格子是同一个标签
    `(none)`** —— 所以 `for` 那一格要先把空格子滤掉：条件落成 nil 就是"条件为假"，
    `for ;; {}` 会一次都不跑，那是错而不报。（go 那一份先踩过同一个坑。）
再补两格（同一族的账，所以并进同一个家族）：
  * `{'a': 1, 'b': 2}` 是**不写类型的 map 字面量** —— 与 `map[string]int{…}` 落同一格
    map-new。**同一个标签 `map` 还是那格类型**（`map[K]V`），靠"孩子全是 kv"分开；
    而"这名字装的是 map"那张表要**两种写法都认** —— 漏一种，后面 `m['b']` 就静静落成
    列表下标（又一次同族的错而不报，这次是在做判据的时候自己撞出来的）。
  * `unsafe { … }` 是一格块：`unsafe` 本身**不产生代码**（只放开指针那几样的检查），
    拆成一格 region —— 与 `mut` / `pub` 同一类。
判据 `ext/vlang/examples/litnone.v`（第三十一个家族，六行）—— 五条腿绿，core 那条按名有姓地
跳过（nil 在方言里说不出类型）。量：**653 -> 736 -> 796（30.8% -> 37.5%）**。

**这儿有一个数要说清**：接上 map 字面量那一刻是 **798**，把 `isMapLit` 那个错而不报补掉之后
变成 **796** —— **少了两份，而那是对的**。补上之后有更多名字被认成 map，于是那两份文件里的
`for k in m {}` 从"静静按下标走"变成了当场报（`for … in` 一格 map 那条墙现在是 6 份）。
**尺子的分子降下来常常是好事**：它量的是"落成图"，而落成图的前提是**没在猜**。

**映射那一层的最后一刀（同日）**：`evariant` 45 与 `cast` 52。
  * **枚举的值**：枚举的声明在图上是丢掉的（类型不进图），可 `.red` / `Color.red` 要拿到
    **值** —— 所以名字与值从**声明**登记（`ENUMS` / `EVARIANTS`），与"字段名与顺序从声明来"
    （`STRUCTS`）是同一条既有路子的第六个提供者，图上一格新节点也没加（落的全是 `const`）。
    V 的值规则：默认从 0 数上去，写了 `= N` 就从那儿接着数（只接整数字面量那一档）。
    `.red` 的**类型从上下文来**而这一层看不见 —— 办法与方法重名那一格同一条：变体名在整份
    文件里唯一就用它，撞了当场报。
  * **`?int(…)`**：Option 那一层的类型丢掉了（§五第 1 项），所以 `?int(7)` 就是 7、
    `?int(none)` 就是 nil（实参是 `none` 时**不能**走 conv —— 那会把 nil 变成 0，是错而不报）。
判据 `ext/vlang/examples/enumval.v`（第三十二个家族）。量：**796 -> 832（37.5% -> 39.2%）**。

到这儿 **vlang 那一门映射那一层就补完了** —— 剩下最高的八条墙没有一条是映射的账。

**go 那一门的第四刀（同日）**：`make(…)` 与定长数组的零值。三件事各带一条：
  * **`make(map[K]V)` / `make([]T, 0)`**：`make` 的**第一格实参是一格类型**，所以这一格要在
    "先算实参"之前拦 —— 头一版正是放在了后面（`argNodes` 先算就先炸），于是那 20 份一份
    都没动，**尺子当场说了话**（改完才 20 -> 0）。`make([]T, n)`（长度不是 0）当场报：
    它要的是"按长度造一格新列表"，而图上的 `list-new` 收的是元素表 —— 那是另一格节点。
  * **`var arr [3]int` 的零值是 N 格元素零值各一格**（数组是值语义的）。每格**各算一遍**
    而不是复制同一格：`lit(0)` 出的是 `{lit: 0}` 不是一格节点，复制那条路要分两种形状。
  * **`len(x)` 落 `prim len`** —— 与 lua 的 `#s`、awk 的 `length(s)`、V 的 `.len` 同一格节点。
    原来它落成"调一个叫 len 的函数"，而那个函数不存在。
  又堵一个**答案错而不报**（与 V 那一侧同一天、同一族）：`mapBindName` 只认字面量那种造法，
  于是 `m := make(map[string]int)` 之后 `m["k"] = 5` 会静静落成**列表下标写**。
  抽出 `isMapCtor` 让两种造法共用一个判据。
判据是 `ext/go/examples/vardecl.go` 扩到九行。量：**59 -> 61（7.9% -> 8.1%）**。
go 那一栏涨得少是**语料的样子**：它的墙前三名是指针、闭包、位运算 —— 都不是映射的账。

**下一条墙 `addr` / `deref` / `fnlit` 不是映射的账**：指针（`&x` / `*p`）与函数值在
节点清单里本来就没有那一格，`<<` 那一族也一样（图上的 prim 表里没有位运算，而 `^` 已经
占给了幂）。它们该留在墙上等**词汇表**那一刀，不该靠映射猜过去。

**这三行是①之前那一格的账**（"整棵编译器有多少份连图都落不成"），不是①②③④里的任何一级 ——
①要的是"输出与官方编译器一致"，那还隔着后端与它们的 stdlib。摆在这儿是为了让下一刀有个
分母：每补一格映射，这三个数就该动。

### 5.2 第二档：跨层 FFI（大部分在 js 层，一格在 C）

已有的两半：

- **声明从哪来**：`import "libfoo.dylib" with "foo.h"` —— 头文件里的函数声明逐条变成
  `(cabi …)`（`frontend-jnc/lower.js:9845` 起），解析用的是**这个仓库自己的** C 前端
  （`cap('c.declsOf')`）。不外挂 clang，也不另写一个 C 解析器。
- **库怎么装**：`C_SYSLIBS`（`hir/c_abi.js`）分"进程里已经有的"（`RTLD_DEFAULT`）与
  "按路径 dlopen 的第三方"两类 —— macOS 上 `libSystem` 不是磁盘上的文件那一格坑已经踩过并写在那儿。

**决定：把 `with` 从 jancy 提到 omni 自己那门语言**，同一格 cap，不重写实现
（`parser.js:277` 那个 `parseImport` 加一格可选的 `with "…"`）。

还欠的两格（写清楚，别让借用这条路自己发明一套）：

- **聚合与回调**：`c_abi.js` 头上明写"结构体按值、数组、回调一律不支持"。这两格该落在
  ADR-0031 §2/§3（`slice` / `struct` / `fnptr`）上，**不是**在 FFI 这一层另写一套 marshal；
- **node 那一侧**：跑在 node 上时"调 native"走的是我们自己的宿主桥
  （`runtime/omni_js_host.c` 与 `plugins/*.dylib`，ADR-0021），不是 node 的 N-API。
  同一句 `import … with` 在两条腿上落法不同、语义必须相同 —— 这是这一档的第二条判据。

### 5.3 第三档：语法空间 `as g`（同像能力）

语法契约不一致时（python 的缩进块、rust 的生命期标注、go 的 `:=`）**没有自动转换可谈**。
这一档给的是"你自己动手"，而且是**可判定**的那种动手：

```
import "./x.py" as g;
```

`g` 上四格操作（先落只读那两格）：

| 操作 | 形状 | 说明 |
|---|---|---|
| **查** | `g.forms`、`g.find(sort, kind)` | 按 ADR-0029 的 sort/kind 查，不是按字符串 grep |
| **展开** | `g.lower(form)` | 按那门语言自己的 L5 规则把一段树降到 sx |
| **改** | `g.rewrite(pattern, template)` | 树到树的重写；**不带卫生**（见 §8） |
| **拼** | `g.splice(hole, ourForm)`、`g.bind(name, ourRef)` | 把我们的树塞进它的洞；名字必须**显式绑** |

三条设计要点：

1. **表示就是现成那一份**：`g` 交出来的就是 `read.js` 那三种节点（+ `scopes`）。
   用户那句"类似 json 一样"在这棵树里是**字面成立**的 —— s-expr 就是那份 json，
   不为这一档新发明一种表示；
2. **合法性可校验**：塞进去的树按那门语言的 Σ（多类签名，ADR-0033 §2.1）当场校验，
   而不是等降级时报一句"洞名对不上"；
3. **名字不共享**：两门语言的作用域图是两张图。`g` 上塞进来的标识符**不会**自动看见我们的绑定，
   所以有 `g.bind`。少了这一条，跨语言拼树就是隐式捕获 —— 而它连报错的地方都没有。

### 5.4 第四档：进程边界（`via rpc`）

```
import "./x.py" via rpc;                  ;; 协议默认 json-rpc/stdio
import "./x.py" via rpc with "x.pyi";     ;; 接口描述从哪来（可选）
```

- **起进程**：`spawn`（`src/core/host/native.js` 已有，两条腿都有）；解释器与参数由
  `via` 那一格的适配器说（`python3 -m omni_rpc x.py`），**不猜 PATH 里有什么**：找不到就报。
- **协议**：JSON-RPC over stdio（一行一条，`Content-Length` 不要 —— 我们已经有 JSON
  编解码：`src/lib/json.omni`）。**同步调用**先落；异步与流式留位置不定语义。
- **契约**：一份接口描述，字段按方言词汇写（`i64` / `f64` / `bool` / `string` / `slice` / `struct`）。
  没有描述时**不许**动态猜签名 —— 那是第二档 `with` 那条教训的同一条（`lower.js:13828`
  那句"猜错了那一端会崩"）。
- **语义差异必须写在文档与诊断里**：
  - **值语义**（ADR-0005）在进程边界上只能是**拷贝**；
  - **句柄**（对面的对象）走一张对象表，我们这侧只拿一个不透明 id（`ptr` 那一格的老办法）；
  - **错误**映射到 ADR-0007 的错误模型：对面的异常 = 这侧一个可失败调用的错误分支；
  - **生命期**：进程活多久、谁关它 —— 一格显式的 `close`，别指望 GC。

## 6. 语法总表（一处说清）

```
import "./util.omni";                    // 今天就有：同层、同一门语言
import "./x.nim";                        // 第一档：同层，另一门语言（认语言按后缀 / #lang）
import "libfoo.dylib" with "foo.h";      // 第二档：跨层 C ABI（从 jancy 提上来）
import "./x.py" as g;                    // 第三档：语法空间（同像）
import "./x.py" via rpc;                 // 第四档：进程边界
import "./x.py" via rpc with "x.pyi";    // 第四档 + 接口描述

#lang omni                               // 事情一：读入器指令（默认关）
template 名(形参) { 体 }                  // 事情一：卫生模板，**omni 主语言那一份**（同一格开关）
(define-template 名 (形参…) 体…)          // 事情一：同一件事在中间格式 `.sx` 上的样子
define-macro                             // 事情一：过程宏（另一格开关 --macro-eval，**还没有**）
```

`as` / `with` / `via` 可以叠（`as g` 与 `via` 互斥：一个要树、一个要活进程）。
**每一格都报错优先**：语言拿不到、契约算不出、开关没开、档位选不了 —— 一律当场一句话，
带上"装着的有哪些 / 怎么开 / 另一条路是什么"。这条纪律是这一整份 ADR 的底线，
它已经在 `--profile` 那三档上被证明过（收下开关一声不响，用户会以为量过了）。

## 7. 落地顺序（每一步一个可执行判据）

**优先级已定**：先事情一的头两格（`#lang` 与卫生模板），再借用那三门（go / nim / vlang）。

| # | 步 | 判据 |
|---|---|---|
| 1 | `#lang` 指令 + 两处开关 + `langNames()` 印表 | 关着时报那三行（含开法与装着的读入器）；开着时 `.omni` 里写 `#lang sx` 能编能跑 |
| 2 | `--as <名字>` 与 D3 那张优先级 | 三处冲突时报"三处各说了什么"；单处给时按它走 |
| 3 | **定义期那半趟**（局部标 gensym、自由名字在定义处绑定、routine 默认 inject） | §4.3 第 2 条用例（`let + = *` 时模板里的 `+` 仍是定义处那个） |
| 4 | **展开期那半趟**（按位置替形参 + per-展开 mapping 换名） | §4.3 第 1、3 条用例；同一模板展开两次，两次的 gensym 名**不同**（`instID`） |
| 4b | **同一件事落在 omni 主语言上**（`template 名(形参) { … }`，§4.1 末尾） | 三条性质写成 omni 的语法一份文件跑完（`10 / 5`、`1 / 1`、`2 / 1`）；两次展开两个号；四处拒绝各说到原因；关掉开关语料逐字节相同 |
| 5 | 借用第一档的出口：`tograph` 的产物接到 `sx`（§5.1 的 B 路） | `ext/{go,nim,vlang}/examples` 每份跑出来的输出与官方编译器一致 || 6 | `with "h"` 从 jancy 提到 omni | 同一份头，jnc 与 omni 两侧收到的声明与常量集合**逐条相同** |
| 7 | `as g` 只读两格（查 + 展开） | 拿一份 `.jnc` 当 `g` 读进来，`g.lower` 出的 sx 与直接编那份 `.jnc` **逐字节相同** |
| 8 | `via rpc`（同步调用） | 先拿 `.js` 当"假 python"（它两条路都有）：第一档与第四档**答案相同** |
| 9 | 过程宏 + `--macro-eval` | 编译期跑用户代码那一句诊断在；关着时 `define-macro` 报错 |
| 10 | `g.rewrite` / `g.splice` / `g.bind` | 塞进去的树按 Σ 校验；未绑的名字**报错**而不是静默解析 |
| 11 | 聚合与回调进方言词汇（挂 ADR-0031 §2/§3） | `C_ABI` 那句"聚合一律不支持"删掉的同时，六条腿逐字节判据不许变差 |

**初版那个"第 1 步：三种节点各加一格 `scopes`"删掉了** —— D5 改成 Nim 那两趟之后不需要它
（省掉的正是"给每个节点挂集合 + 写子集最大匹配解析器"那一整块）。

## 8. 明着欠着的（不许悄悄）

- **过程宏要跑用户代码**：默认关；它与"编译一份文件是纯函数"这件事天然冲突，
  缓存的键里必须带上宏代码本身（否则改宏不重编 —— 与 `.grammar` 那格内容寻址同一个理由）。
- **Nim 那套卫生要求"定义处查得到名字"**：所以第一格落在 `sx`（顶层名字与算子表读完就齐）。
  asy / jnc 那两门的名字解析在各自 5000~15000 行里，要等 ADR-0029 的 L3（作用域图）才好接。
- **omni 主语言那一份差两格**（§4.1 末尾详记）：调用处的局部遮住模板体绑到的模块级变量时
  **报**而不是不遮（要补齐得先给 `hir/check.js` 加一趟 alpha 改名 —— 现在遮蔽的声明原名入表）；
  模板只在**语句位置**上展开（体是一串语句，塞不进表达式；要接得让体只有一格表达式）。
- **`g.rewrite` 不带卫生**：跨语言的树没有共同的作用域图，所以名字要显式绑。
  这不是"以后补上"，是这一档的**定义**：要卫生就用第一档（同一棵 sx 里的宏）。
- **值语义在第四档只能是拷贝**（ADR-0005 那套在进程边界上无从谈起）。
- **go / nim / vlang 缺的是"到 js"那一格出口**，不是语法（`ext/` 里三份 `.grammar` 与三份
  `tograph.js` 都在，节点图那层只有 c 与 wat 两个后端）。python 那门连 L0 都还没有。
- **`C_ABI` 的聚合与回调今天没有**：第二档能借的还只是标量签名那一层。
- **项目清单还不存在**：`PACKAGES` 是写死的一格（`module/load.js:35` 上那句注释自己说了
  "将来会被真正的项目清单文件取代"）。所以 §3.2 的开关只有命令行与环境两处，
  **不写"清单里配"** —— 清单来了再加。
- **标准库仍旧只有 `json.omni`**：这一份 ADR 不承诺任何自带库，它承诺的是借用的四条路。

# ADR-0014：两个新执行后端 —— S 表达式闭包解释器与 copy-patch JIT

状态：提议
日期：2026-08-26
相关：ADR-0013（执行引擎分层与 C-FFI 契约）、ADR-0010（函数值）、ADR-0011（JS 降级）

## 背景

ADR-0013 的阶段 1（OIR 树遍历解释器）已经落地并量过。数字把问题指得很死
（基准负载：编译器自己 link + lower + emit-js 一遍 `frontend-js/lexer.js`）：

- node 直跑这段 JS：0.77e9 条指令
- node 里跑解释器：15.5e9（20x）
- 原生构建里跑解释器：40.1e9（53x）
- 同一份代码走 C 后端编译执行：**61ms**

上一轮把编译期能算的都挪到了编译期（字面量池、UTF-16 op 名分派、属性键的 UTF-8 孪生体、
单次哈希探测、`x === "字面量"` 特化、常量下标特化），从 101s 压到 9~14s。**再往下挤不动了**：
剩下的成本不是某几个函数写得笨，是形状本身错了。profile 上排头两位是
`omni_js_obj_getk`（把 OIR 节点当 dict 读，`e.kind` 每次一次哈希）和
`omni_js_arr_get`（每次调用把实参装成一条 list 再逐个读回来）。

这两条都不是能优化掉的，是**表示决定的**。所以要换表示。本 ADR 定两个新后端，
共用同一个新的中间形态。

## 决策 1：两个后端共用前半段 —— OIR → SEXPR

新增一层 `SEXPR`：把 OIR 摊平成一份**已解析、已定型、可按下标寻址**的表示。
两个新后端都从它出发，OIR 本身不动（`hir/` 与两个现有后端零改动）。

SEXPR 相对 OIR 的三件事，全部在这一层一次做完：

1. **符号全部消掉**。`kind` 变成小整数 opcode；变量名变成帧内槽位下标；属性名变成
   驻留字符串的 id。执行期不再有字符串比较，也不再有 dict 查找。
2. **形状定死**。节点是定长记录（opcode + 至多三个操作数下标 + 一个常量池下标），
   存在一个平坦数组里，`n` 是下标而不是指针。子节点靠下标引用。
3. **检查全部前移**。arity、槽位越界、闭包捕获是否成立，在这一层验掉；执行器不再复查。
   这是 wasm 的口径：**先验证，再执行；执行器里没有检查**。

这层是纯函数（OIR in，SEXPR out），所以它也能被 diff 出快照，进 `tests/oir` 那条轴。

## 决策 2：解释后端 = 闭包编译，不是 opcode 分派

拿到 SEXPR 之后**不写解释循环**。每个节点在装载期一次性编译成一个函数值 ——
按 ADR-0013 决策 3，函数值就是"第一个字段是 `omni_fnptr fp` 的闭包记录"。
执行一个节点就是 `n->fp(n, frame)`。

也就是说，**分派只付一次，在装载期付**。没有 `switch`，没有计算 goto，
没有 opcode 读取。这是 Feeley/Chez 那套"编译成闭包"的做法。

对我们尤其合适的原因是：这条路**不需要新的值表示，也不需要新的调用约定**。
闭包记录、`omni_dyn`、`omni_fnptr` 这三样已经在 ADR-0013 决策 3 里定好了，
闭包编译只是把它们用在解释器自己身上。C-FFI 契约一个字都不用改。

节点上顺带挂两样东西（都是编译期填好、执行期只读）：

- **特化后的 fp**。类型已知时选专用实现：两个 real 相加发 `real_add` 的 fp，不发
  `js_add` 的 fp（tag 分派在装载期就做完了）。这是 SBCL 的口径 —— 同一个源码算子，
  按类型选不同的实现，而不是在运行期问"这是什么类型"。
- **单态内联缓存**。取属性/调方法的节点上留一格 `(shape, slot)`；命中直接取槽位。
  现在的 `builtin.js` 已经有个雏形（`memberOp` 上的 `ctag/cop/cabi`），
  搬到 SEXPR 上才能真正省掉哈希。

## 决策 3：调用帧是值栈上的一个窗口，实参不再每次分配

现在每次调用都新建一条 `omni_list` 装实参，被调方再 `arr_get(args, k)` 逐个读回来。
换成：一条大的 `omni_dyn` 值栈，帧是它上面的一个窗口，实参就写在窗口里对应的槽位上。
被调方读第 k 个形参就是 `slots[k]` —— 一次数组访问，不是一次调用加一次装箱。

帧布局照抄 Cyber 的形状（见下方借鉴与对照）：前若干槽固定放返回地址、调用者帧指针、
调用信息，实参从固定偏移开始。这条同时也是 ADR-0013 里"阶段 2 应该换成 args 是槽位
数组上的一个窗口"那句话的落地。

注意这**不**改 C-FFI 契约：跨界调用（解释器 ↔ 运行时 `omni_js_*`）仍然是普通 C 调用、
`omni_dyn` 按值传。变的只是解释器内部怎么摆实参。

## 决策 4：JIT 后端走 copy-patch，桩由我们自己的 C 后端在构建期生成；不引入 LLVM

JIT 的形态是 **copy-patch（stencil）**：每个 SEXPR opcode 在**构建期**被编译成一小段
机器码模板，JIT 时按序 `memcpy` 这些模板并回填立即数与跳转目标。

关键的一步是模板从哪来：**用我们自己的 C 后端生成**。每个 opcode 的语义写成一个小的
C 函数，构建期编一遍，从目标文件里把它的机器码和重定位点抠出来，做成一张桩表编进产物。
于是：

- **不写汇编器，不写寄存器分配器，不写 ABI 分类**。这三样是自己写后端里最贵的部分
  （见借鉴与对照里 tinycc 的行数），copy-patch 把它们全部让给构建期的 C 编译器。
- **运行期不需要 cc**。这是 ADR-0013 立起来的性质，不能丢。构建期需要 cc —— 但构建期
  本来就需要（`bootstrap` 那条链就是 clang 编出来的）。
- **调用运行时零成本**。桩里对 `omni_js_*` 的调用就是 C 编译器发出来的那条 call，
  重定位时填上真实地址。不需要 trampoline，不需要搬值。ADR-0013 决策 3 原样成立。

分层触发按 ADR-0013 阶段 3 的口径：先全部走闭包解释器，函数级计数器过阈值再 JIT，
不做 OSR（循环内切换）—— 那是后面的事。

## 决策 5：值表示不动，不抄 NaN boxing

Cyber 用 8 字节 NaN boxing，quickjs 用 16 字节带 tag 的联合。我们已经选了后者
（ADR-0013 决策 3：16 字节 `omni_dyn` 按值传）。**这条不因为 JIT 而改**：

NaN boxing 省的是内存带宽，代价是每次跨 FFI 边界都要拆包/装包 —— 而 FFI 直调正是
ADR-0013 的第一约束。16 字节按值传在 arm64 上是两个寄存器，C 编译器直接用
`x0/x1` 传回，桩里读 `.tag` 就是一条 `ldr`。省不出来的那点带宽，换的是"C 结构体
就是我们的值"这条性质，值得。

## 决策 6：验收门槛 —— 比对轴从四方扩到六方

现在 `tests/js-exec` 是四方逐字节比对（node / omni-js / omni-c / interp）。
两个新后端各加一方：

- **五方**：`sexpr` 闭包解释器的输出必须与现有树遍历解释器逐字节相同。
- **六方**：`jit` 的输出必须与前五方逐字节相同，且**同一个进程内**解释执行与 JIT 执行
  混合（同一函数在计数器跨阈值前后各跑一遍）结果一致。

外加两条：

- SEXPR 这层进快照测试（`tests/oir` 那条轴），OIR → SEXPR 是纯函数，能钉住。
- `tests/bootstrap` 加一条：`N1 sexpr cli.js == C0 emit-js cli.js`。JIT 那条等能自编译
  再加 —— 内存是当前的硬边界（见下）。

## 借鉴与对照

量过的三份本地源码，逐条写实（行号是这些快照里的）。**wasm / SBCL / Chez 本地没有快照**，
上文引用的是它们的公开做法（先验证后执行 / 类型驱动特化 / 编译成闭包），不是读码所得，
落地前需要各自找一份源码核对。

### Cyber（`reference/cyber`，Zig + C）

- **它的 "JIT" 不是分层 JIT**。是构建期用 `CL_JIT` 选中的整程序 copy-patch 后端，
  与解释器不共存：没有 OSR、没有调用计数器、没有 deopt。这条纠正了"抄 cyber 的分层
  JIT"这个前提 —— 可抄的是它的 **copy-patch 形态**，不是分层机制。
- **值是 8 字节 NaN boxing**（`src/value.zig:44..56`，`@sizeOf(Value) == 8` 断言在
  `:552..563`）。指针里还塞了一位"是否可能成环"（`src/vm.h:55..61`），于是
  `isPointer()` 是一次无符号比较。我们不抄（决策 5），但那个"把 GC 元信息塞进值本身
  换取一次比较"的手法，将来 ARC 落地时值得再看。
- **ARC 为主 + 只对可能成环的对象跑标记清扫**（`src/arc.zig:222..241`）。根不是靠
  句柄，是靠**编译期发出的 unwind 表**走栈找出来的（`src/arc.zig:329..355`），
  同一张表也用于异常展开时的 release。**没有 write barrier，没有 handle scope**
  （全仓库无此概念）。这印证了 ADR-0013 决策 3 的选择：非移动式收集器 + 编译期
  元数据，native 代码持有值不需要登记。
- **帧布局值得照抄**：固定槽 0..4（1 = 调用信息、2 = 返回 pc、3 = 调用者帧指针），
  实参从槽 5 开始（`src/vm.h:203` 的 `CALL_ARG_START 5`，用法在 `src/vm.c:1147..1152`）。
  `CallInfo` 被打包进一个 `Value`（`src/fiber.zig:543..559`），里面连
  "call 指令有多长"都存了，好处是 pc 在调用前就推进完，单步天然落在正确位置。
  这正是决策 3 要的形状。
- **字节码是变长、寄存器式（帧指针相对槽位）**，130 个 opcode
  （`src/bytecode.zig:1142..1332`，`getInstLenAt` 在 `:968..999` 按 opcode 返回长度）。
  解释循环用 C 写的，计算 goto + switch 兜底（`src/vm.c:519`、`:540..542`、`:674..705`），
  `-DCGOTO=1` 无条件打开（`build.zig:592`）。我们选闭包编译，连这个跳转表都不需要。

### Jancy（`reference/jancy`，C++ + LLVM）

- **ORC 集成本身很轻：345 行**（`jnc_ct_OrcJit.h` 79 + `jnc_ct_OrcJit.cpp` 266），
  三套后端（Legacy/MCJIT/ORC）共 1104 行。手工拼 ExecutionSession + IRCompileLayer +
  RTDyldObjectLinkingLayer + JITDylib，没用 `LLJIT`（`jnc_ct_OrcJit.cpp:104..164`）。
- **但重量不在这里**。三处代价说明为什么我们不走 LLVM：
  - `createBareJITDylib` 不挂进程符号解析，于是**每个 libcall 都得手工登记**：
    `memset`/`memcpy`/`__divdi3`/`__aeabi_ldivmod`…（`jnc_ct_Jit.cpp:94..143`）。
    codegen 可能发出什么，你就得先知道什么。
  - **十六个手写的调用约定类**（`jnc_ct_CallConv.h:27..44`，msc/gcc/arm × 32/64 展开），
    在 IR 层重做 sret/byval/coerce —— 本该由 clang 完成的活。这块比 JIT 集成重得多。
  - 强依赖 typed pointers，LLVM 15/16 上要 `setOpaquePointers(false)`
    （`jnc_ct_Module.cpp:201..211`）。跟着上游走的长期债。
  - ORC 不支持 `addGlobalMapping`，全局变量得改写成 `ExternalWeakLinkage` 的
    `.mapping` 声明再让符号解析器接住（`jnc_ct_Jit.cpp:146..167`）。
- **可抄的一条**：JIT 代码回调宿主运行时，用的是"显式注册的字符串→函数指针哈希表"
  （`jnc_ct_Jit.h:26..28`，查表在 `jnc_ct_Jit.cpp:74..92`，运行时库靠宏批量登记，
  `jnc_ExtensionLib.h:178..191`）。我们的桩重定位需要同一张表 —— 但我们的表可以在
  **构建期**从 `JS_ALL` 生成，不需要运行期注册（和 205 路 op 分派器同一个套路）。
- **它是全静态类型、无装箱**（每个 `ct::Type` 缓存一个 `llvm::Type*`，
  `jnc_ct_Type.h:158`、`:410..414`），用的是胖指针
  （`jnc_DataPtr` = 指针 + validator，`jnc_RuntimeStructs.h:94..137`）。
  和我们的动态值域不是一回事，不可直接类比。

### TinyCC（`reference/tinycc`，C）

- **单趟发射，没有 IR**。发射原语是 `g()`（一个字节）/`o()`（打包多字节），
  `x86_64-gen.c:172..190`；arm64 上 `o()` 直接写一个 32 位指令字（`arm64-gen.c:115..124`）。
  死代码消除就是在发射原语里查一个 `nocode_wanted` 标志 —— 全部机制。
- **寄存器分配是 38 行**（`tccgen.c:1489..1527` 的 `get_reg`）：拿值栈当占用表线性扫，
  没有空闲寄存器就从栈底开始溢出一个。值的位置抽象是 `SValue.r` 一个小整数带标志位
  （`tcc.h:487..501`），值栈是定长 512 项（`tccgen.c:48..50`）。调用前
  `save_regs` 无条件全溢出，完全不管 callee-saved。
- **后端行数**：`x86_64-gen.c` 2313、`arm64-gen.c` 2209、`i386-gen.c` 1306、
  `riscv64-gen.c` 1434；目标无关的驱动 `tccgen.c` 8920。必须实现的后端接口约 25 个函数。
- **难以重做的两处**（这是我们选 copy-patch 的直接理由）：
  - **ABI 实参分类**（`gfunc_call`/`gfunc_prolog`，每个目标约 350 行）是从 ABI 文档
    推出来的琐碎逻辑，写错了只在特定实参组合上崩。
  - **内存内执行骑在一整个 ELF 链接器上**（`tccelf.c`，4116 行）。我们不需要它 ——
    `mmap` 一块可执行内存、按自己的重定位表回填就够，前提是我们不生成目标文件。
- **可抄的一条**：前向跳转用"把待回填的位移串成链表，链表就存在代码缓冲区里那些还没
  填的位移字段上"。零额外分配，回填时一遍走完。桩之间的跳转正好用这个。

## 被否决的方案

- **引入 LLVM（ORC）做 JIT**。集成代码确实只有几百行，但它把"产物自带执行器、
  运行期不需要 cc"这条性质换掉了，还带来手工 libcall 登记、手写调用约定层、
  typed pointers 的上游债（都在上面引了行号）。我们的动态值域也用不到 LLVM 的优化
  ——热点是 tag 分派和内存分配，不是标量优化。
- **自己写汇编器 + 寄存器分配器（tinycc 路线）**。可行，但按 tinycc 的行数，
  每个目标 2.3k 行加 350 行 ABI 分类，而且崩起来极难查。copy-patch 用构建期的 C 编译器
  把这两块换掉，代价是桩的粒度粗一些（跨桩不做寄存器分配）—— 对第一个 JIT 层可以接受。
- **在现有树遍历解释器上继续微优化**。上一轮已经拿了 16x，profile 排头的两位
  （节点当 dict 读、实参每次装 list）是表示决定的，不换表示挤不动。
- **保留 opcode 字节码 + 计算 goto（Cyber/quickjs 路线）**。可行且成熟，但它需要一个
  解释循环、一张跳转表、一套指令编解码；闭包编译在我们这里能直接复用已有的函数值
  表示（决策 3），少一整层机制。字节码的好处是紧凑、可序列化 —— 我们暂时不需要。

## 后果

- **多两个后端，但只多一个中间表示**。SEXPR 一层同时喂闭包解释器和 JIT；OIR 与现有
  两个后端零改动。
- **语义实现从三份变三份**。这是刻意的：SEXPR 的两个后端不重新实现语义，它们发的仍然是
  对 `omni_js_*` 的调用（ADR-0013 决策 5「语义只有一份」原样成立）。所以新后端不会
  引入新的语义分叉点，只会引入执行机制的 bug —— 而那种 bug 六方比对当场就抓。
- **内存是 JIT 之前必须先解决的**。当前解释器在整个自编译上被 OOM 杀掉（arena 不回收）。
  决策 3 的值栈把每次调用一条 list 变成窗口，正是冲这条；但 arena 回收本身要单独一条 ADR。
- **构建期依赖增加**：桩表要在构建期从目标文件里抠机器码，意味着 `bootstrap` 多一步，
  且这一步是平台相关的（arm64/x86-64 各一份桩表）。运行期依赖不变（仍然是零）。

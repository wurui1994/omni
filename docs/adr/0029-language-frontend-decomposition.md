# ADR-0029：语言前端的形式化分解（一个平台，多门语言）

状态：**提议**（本文是分析与设计，落地路线在最后一节；未改一行代码）

关联：ADR-0014（sexpr 前端与 LLVM 后端）、ADR-0016（jancy 前端，260 刀的账本）、
ADR-0021（分语言插件）、ADR-0025（jancy 泛型）、ADR-0026/0027/0028（方言的值表示）

---

## 1. 病历：为什么现在这套走不下去

事实先摆出来，不加修辞。

- `src/core/frontend-jnc/lower.js` **15,343 行**，一个类里装着：说明符解析、声明符解析、
  名字登记、命名空间解析、类型构造、转换判定、重载决议、属性/事件/反应器的改写、
  格式化字面量的第二遍词法、诊断措辞、以及最终的 sexpr 文本拼装。
- 五门语言各写了一份同构的东西：`frontend-c/tccgen.js` 8,243 行、`frontend-js/lower.js`
  4,472 行、`frontend-asy/*` 约 9,000 行、`frontend-glsl/lower.js` 2,327 行。
  它们**各自**实现了：作用域栈、名字查找、类型相容判定、诊断发射、临时量命名。
- ADR-0016 的账本有 260 条。抽样分类（第 248~260 刀这十三条，是刚做完、记忆最准的一段）：
  - **矩阵漏格**：第 219（体里 typedef）、250（体里 enum）、260（体里 struct）——
    同一句祸根"名字那一遍只走顶层与类体"，撞了三次。
  - **认错人的诊断**：第 248（`return <void 调用>` 被报成 main 的退出码）、
    第 251（字段表还没摊开被报成"0 个字段"）、第 253（union 里的方法被当成字段）——
    诊断措辞与真实原因脱节，因为诊断是**手写字符串**而不是规则的产物。
  - **量法噪音**：第 243/245/255/257（扩展库与 ioninja 按目录成组、`-I` 少了一个目录）——
    尺子不是规格说明，是"错误消息的直方图"，于是噪音与真账混在一起排名。
- 后果：一门新语言（C++）在这套结构下等于**再写一遍 15,000 行**，而且它自己的账本会长成
  另外 300 条。这不是平台，这是五个孤岛。

**根因一句话**：我们把"语言的规格"编码成了**控制流**（if/else 的位置与顺序），
而没有编码成**数据**（可枚举、可查询、可校验的表与规则）。控制流不能被枚举，所以洞只能靠撞；
数据可以被枚举，所以洞可以被**列出来**。

## 2. "形式化设计"在这里的四条最小要求

不是要论文，是要四件可执行的事。任何设计若不满足这四条，就还是老路：

**R1 位置可枚举**：给定"语法范畴（sort）× 要素（declaration kind）"，能机械回答
  三个问题：允许吗？谁登记它的名字？它落到哪个容器里？
  ——满足 R1，"函数体里的 struct" 就不是发现，是矩阵里一格从 `?` 变 `✓`。

**R2 名字绑定是数据**：作用域与可见性是一张**图**（声明、引用、边），解析是图上的路径查询。
  不是 `this.ns` 字符串拼接 + 七八张 Map + 每处各自的 `resolve`。

**R3 类型关系是判定表**：转换（隐式/显式/拒）、重载择优、赋值相容，都是**关系**，
  用表与偏序表示；语言之间只换表，不换求解器。

**R4 降低是小步重写**：每一步只做一件事、只消除一种构造，步与步之间有**可检查的不变式**。
  不是"一个 15,000 行的 visitor 一次到底"。

补一条工程要求：

**R5 诊断由规则生成**：每一条拒绝都是矩阵/规则里的一格，带稳定的**账号**（account id）。
  尺子量的是"矩阵覆盖率"，不是消息字符串的频次。

## 3. 分层分解

七层，每层只有一个职责。**右边一列是关键**：哪些东西一门语言只填数据、哪些是共用的求解器。

| 层 | 职责 | 语言给什么 | 平台给什么（共用） |
|---|---|---|---|
| L0 词法/语法 | 文本 → CST | `.grammar`（已有 GLR） | GLR 表生成、词法、错误恢复 |
| L1 具体→抽象 | CST → AST（去噪、定形） | 一张 **产式 → 节点** 映射表 | 通用折叠器、span 传播 |
| L2 位置代数 | 哪种要素能出现在哪种位置 | **Sort × Kind 矩阵**（R1） | 矩阵求值器、缺格报告、拒绝措辞模板 |
| L3 名字绑定 | 声明/引用/可见性 | 每种 Kind 的**登记规则**（放哪张范围、边怎么连） | **scope graph** 求解器（R2） |
| L4 类型与关系 | 类型构造、转换、重载、赋值相容 | **类型词汇** + **转换偏序表** + 签名表 | 转换判定器、重载择优器（R3） |
| L5 语义降低 | 语言构造 → 核心方言 | **一串小步重写规则**（nanopass） | 遍历驱动、不变式检查、临时量供给（R4） |
| L6 核心方言 | 已有的 `sexpr` + HIR/MIR | 无 | 已有（ADR-0014） |

这层次不是新发明：L6 就是 Racket 的 "core forms" / MPS 的 BaseLanguage 的位置，
而 L2~L5 正是那两套系统里**被显式建模**、我们这边**被写死在控制流里**的四件事。

## 4. 四个形式（这一份的核心）

### 4.1 位置代数：Sort × Kind 矩阵（回答"函数体里的 struct"）

**规格形状**（每一格是一条记录，不是一段代码）：

```js
// langdef/jnc/positions.js
export const POSITIONS = [
  // sort            kind            allowed  registrar        container      account
  ['module',        'struct',        'yes',   'typeName',      'module',      null],
  ['module',        'enum',          'yes',   'enumName',      'module',      null],
  ['module',        'typedef',       'yes',   'typedefDecl',   'module',      null],
  ['class-body',    'struct',        'yes',   'typeName',      'module@host', null],   // 嵌套类型提到顶层
  ['class-body',    'union-named',   'no',    null,            null,          'A-013'],
  ['struct-body',   'union-anon',    'yes',   'unionMembers',  'inline',      null],
  ['union-body',    'method-proto',  'yes',   'protoRegister', 'host-face',   null],   // 第 253 刀
  ['union-body',    'alias',         'yes',   'aliasDecl',     'module',      null],   // 第 254 刀
  ['fn-body',       'typedef',       'yes',   'typedefDecl',   'enclosing',   'C-219'],// 名字外泄的代价
  ['fn-body',       'enum',          'yes',   'enumName',      'enclosing',   'C-250'],
  ['fn-body',       'struct',        'yes',   'typeName',      'enclosing',   'C-260'],
  ['fn-body',       'class',         '?',     null,            null,          null],   // ← 还没填的格
  ['prop-body',     'field',         'cond',  'autogetField',  'prop',        'A-031'],
  …
];
```

三件事随之变成机械的：

1. **缺格可枚举**：`positions.js` 里 `'?'` 的格子就是待办清单。第 250/260 刀是同一列
   （`fn-body` 行）里的两格 —— 有这张表，它们**一起**出现在清单上，不需要靠撞。
2. **登记那一遍自动生成**：`registrar` 一列就是"名字先坐下"那一遍的调度表；
   今天那一遍是手写的 `for (const e of items) if (head === 'type-decl') this.typeName(…)`，
   只走顶层，所以体里那三种全漏。表驱动之后**没有"只走顶层"这回事**。
3. **拒绝措辞由 `account` 生成**：`A-013` 这种账号一次定义、处处引用；措辞在一个地方，
   附带出处（jancy 源码行）与"要落它得先有什么"。第 248/251/253 刀那种"认错人"
   不会再发生 —— 因为报的不是手写句子，是矩阵格。

### 4.2 名字绑定：scope graph（把 `this.ns` 那一摊换成一张图）

今天 jnc 里管名字的有：`this.ns` 字符串 + `qual()` + `resolve()` + `aliases` +
`structs` / `classes` / `enums` / `fns` / `methods` / `protoMethods` / `exposedMems` /
`badNames` / `sctorOf` … 十几张 Map，每处查名各自决定"往哪几张里看、按什么顺序"。
第 256 刀（`static construct` 的体不在类那一层）就是这种散装查名的必然产物：
挪 `ns` 的只有 `methods` 那一支，别的支路谁想起来谁挪。

**换成三种节点的图**（Néron/Visser 的 scope graph，Statix 用的那一套）：

```
scope   S₁ ── LEX ──▶ S₀          // 词法父边（块 → 函数 → 命名空间 → 模块）
decl    D(name, kind, type) ∈ S    // 声明落在某个 scope 里
ref     R(name, kind) @ S          // 引用从某个 scope 出发
imp     S₁ ── IMP ──▶ S₂          // import / using namespace / 基类 / exposed enum
```

- 解析 = **正则路径查询**：`R` 沿 `LEX*·IMP*` 找可见的 `D`，遮蔽规则由边的优先序给
  （`LEX` 近的赢、`IMP` 需要显式声明可见性）。
- jancy 的四件怪事全部变成**边的种类**，而不是 if：命名空间成员不看顺序（同一 scope 内无序）、
  `using namespace`（一条 `IMP` 边，作用域进出就是边的生死 —— 第 217 刀那条界自动消失）、
  无名 enum 成员外泄（一条 `IMP` 边从 enum scope 指到父 scope，第 96 刀）、
  基类查名（`IMP` 边到基类 scope，第 52/94 刀）。
- **C++ 也只加边**：ADL 是"从实参类型的 scope 出发再加一条查询"，`using` 声明是一条
  单名字的 `IMP`，模板的两阶段查名是"两次查询、不同的边集"。求解器不变。

现实的代价明写：scope graph 求解器要**支持环**（`import` 互相引用、基类链），
所以查询要记忆化 + 环闸门。这两件事今天在 `impSeen` / `layingStructs` 里各写了一遍。

### 4.3 类型与关系：一张偏序表 + 一个择优器

今天 `argCost()` 是手写的四档打分（第 80 刀）、`assignOk()` 是一串 if、
`cast()` 是三种硬编码。它们各自都在**模仿** jancy 的 `CastKind` 偏序。

**规格形状**：

```js
// langdef/jnc/casts.js —— 只有数据
export const CAST = [
  ['int',   'int',   'implicit', 3],
  ['int',   'real',  'implicit-cross', 1],   // 严格差于 implicit（jnc_ct_CastOp.h:26-35）
  ['enum',  'base-enum', 'implicit', 3],     // 第 247 刀
  ['0',     'bitflag-enum', 'implicit', 3],
  ['class', 'base-class',  'implicit', 3],
  ['ptr',   'void-ptr',    'implicit', 3],   // 第 190 刀
  ['void-ptr', 'ptr',      'refuse',   'A-041'],  // 字节布局那笔账
  ['fat-fn', 'thin-fn',    'explicit-unsafe', 0],
  …
];
```

- **重载择优**器共用：给定候选签名表与实参档次，取"每个实参最差档的最大值"
  （jancy 的 `chooseOverload`，jnc_ct_FunctionTypeOverload.cpp:44-91）。这套逻辑
  今天在 `pickOverload` / `hostPickSigs` / `opPick` / `ctorArgs` 里**存在四份**。
- C++ 要的"偏序更细"（标准转换序列的三段、模板特化偏序）是**同一个择优器换一张更细的表**，
  不是另写一个。

### 4.4 降低：nanopass（把 15,000 行切成 20 个 200 行）

今天 `lower.js` 是一个 visitor 从 AST 直接吐 sexpr 文本，中间没有可检查的落脚点。
**改成一串小步**，每步只消除一种构造，每步之后 IR 都合法可打印：

```
AST(jnc)
 → P01 去糖：属性 → 取/存两个函数（第 68~71 刀那一套变成一条规则）
 → P02 去糖：事件/反应器 → 单子 + 绑定表（第 73/85 刀）
 → P03 去糖：算符重载 → 具名调用（第 130~139 刀）
 → P04 展开：泛型单态化（ADR-0025）
 → P05 定形：声明 → (decl kind name type) 的统一形状（位置矩阵在这里用）
 → P06 绑定：所有 ref 换成 (bound <decl-id>)   ← scope graph 只在这一步跑
 → P07 定型：每个表达式挂上类型，插入显式转换节点（转换表只在这一步用）
 → P08 内存形：类/结构体/union 的布局与 fat 值展开（ADR-0024/0026/0027/0028）
 → P09 控制流：try/catch、errorcode 传播、finally 的路由
 → P10 输出：core sexpr
```

好处不是"看起来整齐"：

- **每步的不变式可断言**（P06 之后不许有裸 name；P07 之后不许有隐式转换），
  于是"降到一半"那类 bug（第 251 刀的"字段表还没摊开"）在**断言处**就炸，不是在下游报错话。
- **语言之间共用后半截**：P05~P10 里只有 P08/P09 带方言味道，P06/P07 是纯引擎。
  C 前端今天那 8,243 行里的绝大部分就是 P05~P07 的手写版。
- **每步可独立测**：给一段 IR、断言下一段 IR（黄金文件）。今天只能端到端跑 `run`。

## 5. 尺子跟着换：从"消息直方图"到"覆盖矩阵"

今天 `tests/lib/jnc-sweep.js` 量的是**错误消息的频次**。它的三个毛病，这一整段账本都能作证：

- 噪音与真账同排名（第 243/245/255/257 刀全在修尺子，不是修前端）；
- 一行消失可能是**露账**（第 249/250/251 刀，对数反而 +8），也可能是真进展，
  只看数字分不出来；
- **不知道还差什么** —— 只知道"撞到过什么"。

换成矩阵覆盖率之后，尺子回答的是三个可判定的问题：

1. `positions.js` 里 `'?'` 还有几格（**规格的未知量**）；
2. `'no'` 那些格里，账号已写清出处的有几格（**已知的边界**）；
3. 语料里每一格被**用到**多少次（用矩阵格给语料打标签，而不是给消息打标签）。

于是"下一刀挑哪个"从"看直方图第一名"变成"看矩阵里覆盖率×使用频次最高的空格"，
而且**新语言第一天就有清单**：C++ 的矩阵一填，缺口就全在那儿。

## 6. 多语言复用：`langdef` 包长什么样

每门语言 = **六份数据 + 一份行为**；平台 = 五个引擎。

```
src/lang/<name>/                      # 语言侧（数据为主）
  syntax.grammar        L0  已有
  ast.map.js            L1  产式 → 节点
  positions.js          L2  Sort × Kind 矩阵（含账号）
  binding.js            L3  每种 Kind 的登记规则 + 边种类
  types.js              L4  类型词汇 + 转换偏序表 + 内建签名
  lower/P0x-*.js        L5  小步重写（只有这里允许写代码）
  accounts.md               账号 → 出处/理由（ADR-0016 的账本搬进来）

src/frontend-engine/                  # 平台侧（求解器，不含任何语言常量）
  cst2ast.js            L1  通用折叠
  positions.js          L2  矩阵求值 + 缺格报告 + 拒绝措辞
  scopegraph.js         L3  图 + 路径查询 + 环闸门 + 记忆化
  casts.js              L4  偏序判定 + 重载择优（一份，不是四份）
  nanopass.js           L5  遍历驱动 + 不变式断言 + 临时量供给
  diagnostics.js        R5  账号渲染、`…` 归一、span
```

**冗余消除的具体清单**（今天各前端里重复的东西，搬进引擎之后各语言不再有）：

| 今天重复的东西 | 出现在 | 搬去哪 |
|---|---|---|
| 作用域栈 / 查名 | jnc、c、asy、js、glsl（5 份） | `scopegraph.js` |
| 类型相容 / 隐式转换 | 同上（5 份） | `casts.js` |
| 重载择优 | jnc 里 4 份、c 里 1 份 | `casts.js` |
| 临时量命名（`$t1`…） | 5 份 | `nanopass.js` |
| 诊断措辞与 span | 5 份 | `diagnostics.js` |
| "名字先坐下"那一遍 | jnc、c、asy | 由 `positions.js` 生成 |

**C++ 落地时要新加的**（说清楚，免得把"复用"说成免费）：模板实例化（P04 换成两阶段查名 +
偏序特化）、重载的标准转换序列（`casts.js` 的表更细，引擎不变）、`ADL`（多一条查询边）、
构造/析构的作用域出口钩子（与 jancy 的 `disposable` / `finally` 同一格，P09）。
估计新增语言侧数据 ~3,000 行、引擎侧改动 ~500 行；**不是再写一个 15,000 行**。

## 7. 与既有元语言系统对照（借什么、不借什么）

| 系统 | 它的形式 | 我们借 | 不借的理由 |
|---|---|---|---|
| **Racket** | `#lang` + 宏展开器 + core forms；语言即库 | L6 作为 core forms 的定位；"语言是库"（已由 ADR-0021 插件化） | 卫生宏展开：我们的输入是既存语言的源码，不是可编程语法 |
| **JetBrains MPS** | 六个 aspect（structure/constraints/behavior/typesystem/generator/editor） | **aspect 分离**就是本文 L2~L5；`constraints`≈位置矩阵、`typesystem`≈判定表、`generator`≈nanopass | 投影式编辑器：我们要吃纯文本源码 |
| **Spoofax** | SDF3 + NaBL2/**Statix**（scope graph）+ Stratego | **scope graph** 与"绑定是规格"这条 | 全套 DSL 栈与 Stratego 重写语言：JS 里用普通数据结构够了 |
| **Nanopass**（Sarkar/Dybvig） | 小步 + 每步语言定义 + 自动 catch-all | L5 的形状与"每步有不变式" | Scheme 的宏生成遍历：手写驱动够 |
| **MLIR** | dialect + 逐级 lowering + verifier | "每级可验证"（我们的 P0x 断言）；已有 sexpr/HIR/MIR 三级 | 全套 C++ 基础设施 |
| **Clang** | Sema 与 AST 分离、DeclContext | `DeclContext` 概念 = 我们的 scope；`Sema` 的位置检查 = 位置矩阵 | 它的手写规模正是我们要避免的 |

**最优雅的那一版**（如果只留一句话）：
**语言 = 六张表 + 十条重写规则；平台 = 五个求解器。**
凡是"这门语言这里为什么这样"的答案，必须落在一张表的一格里，附一个账号与出处；
凡是需要写代码才能表达的，只允许出现在 `lower/P0x-*.js` 里，且每份不超过 ~300 行。

## 8. 迁移路线（不推倒重来，尺子始终在）

绝对不做"停下来重写三个月"。用 **strangler fig**：新引擎在旁边长，旧路径一段段交出去，
每一步的退出判据都是**现有的腿与榜**（343 个 jnc 例子 + 38 个 llvm 例子 + 语料榜）。

**Phase 0（1 天，纯度量，零风险）**
- 写 `tests/lib/jnc-matrix.js`：机械枚举 `Sort × Kind`，对每格**合成一小段源码**、跑 `sx`、
  记录 `accept / refuse(账号) / crash`。产出 `docs/design/jnc-positions.md`。
- 退出判据：矩阵有多少格、`'?'` 有几格 —— 第一次**知道自己不知道什么**。

## 9. 代价与放弃

- **短期变慢**：Phase 0~3 期间榜的数字几乎不动。这是**故意的** —— 那段时间买的是"以后每一刀
  都不用靠撞"。若要边走边出成果，只允许在 Phase 之间插单刀，不允许在 Phase 内插。
- **引擎有自己的 bug**：scope graph 与转换表都是新代码。缓解只有一条：**两路并行比对**
  （Phase 2/3 的做法），以及"每步不变式断言"。
- **放弃**：投影式编辑、可编程语法（宏）、增量式（IDE 级）分析。前两个我们的输入形态不需要，
  第三个等 P2/S 那条线（ADR-0021）真要 IDE 时再说。
- **不放弃**：ADR-0016 那 260 条账不作废 —— 它们是**规格的语料证据**，Phase 1 把它们
  搬成账号 + 出处；每一条都会在矩阵或转换表里找到自己的一格。

## 10. 立刻的第一步

`tests/lib/jnc-matrix.js`（Phase 0）。它不改前端、不动榜，产出的第一张表就直接回答本次质疑里
那句话：**"什么要素能放在什么位置"**。在那张表出来之前，不再按"撞到哪算哪"的方式做下一刀。

### 10.1 第一次跑出来的结果（已落，`docs/design/jnc-positions.md`）

`位置 9 × 要素 40 = 360 格`，49 秒跑完：**✓ 180、N 146、E 19、·（语法不认）6、炸 9**。

三件事一次就看出来了，而且都是**读表**读出来的，不是撞出来的：

1. **9 格是前端自己崩**（`TypeError`，一条诊断都没有）—— 全在 `property-body` 那一列：
   完整声明式属性的体里放字段 / 事件 / 方法原型 / 局部量，都炸在
   `lower.js:4888` 的 `flatMods`（`lst.span` 读到 undefined）。
   **语料榜看不见这一类**（榜只统计诊断行），而它优先级最高：一个 root cause、九格。
2. **E 那 19 格**是"这一层说你写错了"，其中一格立刻可判为认错人：
   `fn-body × alias-method` 报的是"初值的类型是 `int function*(int)`，声明的是 void"——
   `alias twice = probeFn;` 在函数体里被当成了变量声明（第 254 刀在 union 体里刚修过同一族）。
3. **行/列的形状本身是规格**：`union-body` 整列大片 `N18`（"union 体里除字段与匿名 struct
   以外的成员"）—— 第 253/254 刀刚从那一列里挖出两格（方法、alias），表上一眼能看出还剩多少；
   `struct-body` 那一列的 `N12`~`N16` 是"结构体没有构造那条路"这一个根因的五种表现。

对照本次质疑：矩阵**没有**"函数体里的 struct"这种一次性发现 —— `fn-body` 那一行上
`struct / class / enum / typedef` 四格是并排的四个格子，第 250/260 刀补的就是其中两格，
剩下的（`class`）在表上明摆着。这就是"形式化"在这里的全部意思。

### 10.2 矩阵的第一笔产出：第二百六十一刀（不许再炸）

那 9 格 `炸` 是**同一处** root cause：`propDeclOf` 里 `flatMods(sp.items[3], …)` 直接读
`lst.span`，而 `int m_i;` 那种一个修饰词都没写的说明符只有三项，`items[3]` 压根不在。
兜法与同一函数上面十行的 `keep()` 逐字一样（没有就在 core 的位置上合成一格空 `(mods)`）。

改完：矩阵 `炸 9 -> 0`（那一列变成 N/E —— 说不收是话，抛异常是 bug，两回事）；
腿 344/0；语料榜**一个数都没动**（3430 对、59、90）—— 正是预期：这一格语料里没人写，
所以榜量不到它。新墙 `bad/prop-full-plainfield` 钉住"不许再炸"。

这一刀的意义不在那 9 格，在**它是怎么被找到的**：不是撞语料，是读表。

### 10.3 Phase 1 的前半截已落：位置层变成**可执行的规格**

三样东西进了树（都不碰 `lower.js`）：

- `src/core/frontend-engine/feature.js`：**特性**（feature）与组合的三条规矩 ——
  显式优于通配、冲突即错（两个特性给同一格不同结论当场抛，两边名字都印）、依赖显式（`requires`）。
  一个特性是一束贡献：`positions` / `accounts` 现在填，`binding` / `types` / `lower` 留给 Phase 2~4。
- `src/core/frontend-engine/positions.js`：位置代数的**求解器**（`compose` / `lookup` / `gaps` /
  `diff`），里头没有任何一门语言的常量。另加两条一致性检查：账号必须合式（`X-000`）、
  **引用到的账号必须有人定义**（一个账号只在一个特性里定义，别处引用 —— 于是"这句话什么意思、
  出处在哪"只有一处答案）。
- `src/lang/jnc/features/`：jancy = **5 个特性的组合**（`fields`、`named-types`、`members`、
  `props`、`module-items`），27 个账号，声明满 360 格。

对账用的是同一把尺子：`node tests/lib/jnc-matrix.js --check` 先把每一格真跑一遍，再与声明比。
第一次跑的结果：

```
规格：5 个特性、27 个账号、声明了 360 格
还没定（todo）2 格：module × import、namespace × import（S-005：探针没给 -I）
对上了 358 / 360 格　分歧 0、todo 2、缺声明 0
```

这一步买到的三件事：

1. **漂移是测试失败**，不是"下一次撞出来的发现"。表若与实现不一致，`--check` 当场列出
   `规格说 ok、量出来 refuse` 这样的行。
2. **组合的规矩当场生效**：第一次 `compose` 就抛了错 —— `S-002` 被 `members` 与 `props`
   定成了两句话。这正是"不可复用"的病灶被机器抓住的样子（先前这种重复散在 15,000 行里没人管）。
3. **认错人的账被单独标出来**：`M-006`（函数体里的 `errorcode` 报"只能写在函数上"）与
   `A-001`（函数体里的 `alias` 被当成变量声明）在表里是 `error` + 账，**下一刀读表就能挑**。

另外，这一轮把探针本身的两个假账也修了（属性的 `set` 要带形参、`alias` 的目标在类体里该是
自己的方法）—— 量法自己的噪音同样要记账，否则规格会把探针的错当成语言的事实。

### 10.4 第二百六十二刀：**第一刀是读表挑出来的**

矩阵 E 那一栏当时剩两格标着"认错人"，这一刀把它们一起结了：

- `fn-body × alias-method`（账号 A-001）：`alias plus = add;` 写在函数体里，先前报的是
  "初值的类型是 int function*() ，声明的是 void"—— 被当成一格带初值的量。
  **落法与体里的 typedef / enum / struct（第 219/250/260 刀）一句对一句**：交给现成的
  `aliasDecl`，只是要传 `late = true`（体是在所有签名登记完之后才降的，目标当场查得着；
  顶层那一遍排队是因为它跑在签名之前）。代价同那三刀（T-005：名字提到外面那层）。
- `fn-body × method-errorcode`（账号 M-006）：`bool errorcode f(int);` 报"'errorcode'
  只能写在函数上"—— 话说到了别处。真身是"函数体里写了个原型"。改法两处：`localDecl` 里
  `specs` 收下 `errorcode`，再把"声明符上带括号"那句话改成**同时说两种读法**
  （函数原型 / 局部量挂构造实参），于是 M-006 退役、并进 S-003。

规格跟着改（`props.js` 那一格 `error → ok`、`members.js` 那一格 `error → refuse/S-003`，
两个账号退役），`--check` 回到 `分歧 0`。

- 新例子 `cases/197-localalias`（函数别名 + 类型别名；孪生 `/tmp/c205.c`）。
  顺带量到一格语法事实：`alias Num = int;` **语法不认**（目标得是个名字，内建类型不是），
  已写进例子的注里。
- 旧墙 `bad/local-formals` 的话跟着改（同一笔账、两种读法一起说）—— 墙是账本，改话要改墙。
- 腿：`node tests/jnc/run.js` 345/0、`node tests/llvm/run.js` 38/0。
- 语料榜：`3430` 一个数都没动 —— 这两格语料里没人写。**这正是位置矩阵存在的理由**：
  它量"规格里可能写什么"，榜量"语料里真写了什么"，两把尺子分工。

### 10.5 对账再进一格：不只比**结论**，还比**理由**（R5 的后半截）

先前的 `diff` 只问"这一格该 ok / refuse / error 吗"。可 ADR-0029 第 1 节那三类账里最多的一类
是**"结论对、话说错"**（第 248/251/253/261/262 刀都是）：不收是对的，可发出来的那句话把这一格
归到了别的账上。只比结论，这一类永远抓不住。

于是 `diff` 多问一句：`refuse` / `error` 那两栏，实际发出的那句话里要认得出**声明的那个账号**。
账号可以给一格 `match`（子串或正则）说明它在措辞里长什么样；不给就拿 `text` 前 8 个字当特征。
比之前两边都去掉 `` ` `` 与 `*`，因为账的 `text` 是给人读的 Markdown、诊断是给终端看的纯文本。

第一次跑：**分歧 38 格**，全是同一个形状 —— "结论对、理由认不出"。逐格看下来，38 格里没有一格是
实现漂了，全是我给账写的 `text` 与诊断实际的措辞不是一句话（`text` 写"结构体里的 `static
construct` / `destruct`"，诊断说"结构体里的 `…`"）。所以修的是**数据**：给 F-003、M-001…M-005、
S-002、S-003 这 8 个账补上 `match`。补完 `分歧 0`（`对上了 358 / 360`，余下 2 格是 `todo`：
探针没给 `-I`，`module|namespace × import`）。

顺手在 `compose` 里加了一道**元检查**：`match` 里若带 `` ` `` 或 `*` 就当场炸 —— 那种特征永远命中
不了，而对账会把它算成"实现漂了"，比没规格更坏。规格自己也要有验证器（MLIR 的 verifier 那一条）。

- 腿：`node tests/jnc/run.js` 345/0、`node tests/llvm/run.js` 38/0；榜 `3430` 未动（这一步没碰前端）。
- 位置：`src/core/frontend-engine/positions.js`（求解器，仍然没有一门语言的常量）+
  `src/lang/jnc/features/{fields,members}.js`（数据）。**这就是分层想要的样子**：一条新的一致性
  规则加在引擎里，语言那边只加数据。

### 10.6 Phase 1 落完：**那 24 句话搬进了账本**

先前 `lower.js` 里的"不收"是**手写的字符串**，账本是另一份文档 —— 两边靠人对齐（第
248/251/253/261/262 刀那五条"认错人"就是没对齐的产物）。这一步把它掉了个方向：

- 引擎多两样：`say(spec, id, vars)` 按账号的 `say` 模板渲染出那句诊断（多填一格、少填一格
  都当场炸）；对账的特征从 `say` 第一个 `{` 之前那截字面**自动取**（`matchOf`），
  于是"话"只写一处。
- `lower.js` 多两句：`this.acct(node, id, vars)`（还不收）与 `this.acctErr(node, id, vars)`
  （普通错 —— 不是欠账，是这门语言本来就写不得）。
- 24 个账号里凡是**会发话**的都搬完了：F-001…003、T-001…004、M-001…005、S-001…004、
  P-001…007 共 24 个发话点。T-005 只是一笔"代价"，不发话，也就不用 `say`。
- `compose` 再加一道元检查：被 `refuse` / `error` 那两栏引着的账号**必须**有 `say`。这道检查
  当场逮住了 S-002 / S-003（那两格先前只有账、没有话），逼着把兜底那句
  `语句 '…'` 也认成账号 —— 它本来就是账（"函数体里的成员声明落到这句兜底上"）。

意义不在少写几个字符串，而在**话与账在加载期就绑住了**：往后新加一格拒绝，"忘了记账"或者
"记的账与发的话不是一件事"都过不了加载；换措辞只改 `features/*.js` 一处，`--check` 的特征
跟着变。这正是 R5 说的"诊断从规则生成"。

- 行为一格没动（措辞逐字保持）：`node tests/jnc/run.js` 345/0、`node tests/llvm/run.js` 38/0、
  矩阵 360/360 分歧 0、榜 `3430` 未动。
- 还没搬的：属性那一族里更细的十几句话（"两个 get"、"两格字段"…）—— 它们比矩阵的格子更细，
  等 Phase 2 把属性拆成自己的几格要素时一起立账。

### 10.7 Phase 2 起步：查名变成**作用域图上的一次路径查询**

`lower.js` 的 `resolve` 是一段字符串手术：往外退一层层、体外方法那一层、基类那一层、
`using` 那张表 —— 四种"往哪儿看"混在一个函数的控制流里。**次序**（谁先谁后）与**歧义规则**
（同一类里撞了第二格才算撞）藏在那段控制流里，别的语言想复用只能照抄一遍。

拆成两半：

- 引擎（`src/core/frontend-engine/scopes.js`，无一门语言的常量）：`lookupName(name, {path,
  has, join, ambigOn, onAmbig})` —— 顺着一串**惰性的**候选作用域 `{label, ns}` 走，
  第一格命中的赢；`ambigOn` 说哪几类边上要查歧义。四类边先立了名字：`LEX` / `EXT` / `INH` /
  `IMP`。另给一个 `lexChain(from, out)`：往外退那一段最常见，`out` 由语言给。
- 语言（`lower.js` 的 `scopePath()` / `basePath()`）：只回"候选序列"。jancy 的次序写成了
  四行 —— `LEX` 链（`instNs` 那一跳照旧）→ `EXT`（体外方法的签名那一层）→ `INH`（每层按
  声明顺序 BFS 走基类）→ `IMP`（可见的 using），`ambigOn: [IMP]`。

**迁移法是两条路并排跑**：老那条算法留成 `resolveRef`，`OMNI_SCOPE_DIFF=1` 时每次查名都跑
两遍、答案不同就当场炸。这道闸门下跑过：`NOCACHE=1` 的 jnc 腿（554 次子进程全真跑）345/0、
`NOCACHE=1` 的语料榜（286 份真跑）`3430` 未动、一次不一样都没有。llvm 腿 38/0。

于是"C++ 的查名与 jancy 差在哪"第一次有了能写下来的答案：差在 `path` 的次序与 `ambigOn`
那两格数据，不在另写一个四十行的函数。这是 R2（binding-as-data）落的第一步；下一步是把
`this.ns` 那一串 save/restore 换成图上的节点，再把十几张 Map 收成一张带 label 的表。

### 10.8 名字类也变成**特性拼出来的**数据

紧接着的一步：54 个查名点先前各自带一个临时闭包（`(k) => this.classes.has(k) ||
this.structs.has(k)`），"这一问要的是哪一类名字"藏在闭包里 —— 数不出来、拼不起来，
更没法让特性各自贡献。两步走完：

1. 全部改成 `this.find(nm, kinds, not)`，`kinds` 是名字类的清单；`not` 是语料里真有的
   问法（`fn` 但不是 `method`、`struct` 但不是 `class`）。`this.resolve` 只剩 `find`
   一个调用者。
2. 那张表不再写在 `lower.js` 里，而是**各特性的 `binding.names` 并起来的**：
   named-types 带 struct / class / enum / alias / template / ns / exposed，
   members 带 fn / method / proto-fn，props 带 prop / reactor-top，fields 带 global。
   `compose` 并表时一个名字类只许一个特性定义（撞了当场炸）。`reactor-top` 那一类还带一格
   `keep`（`cls === null`）—— 过滤是**名字类自己的**事，不是调用点的后处理，否则走作用域链
   的时候就挑不掉类里那些。

结果："这门语言有哪些名字类"是那几份 features 的并集（13 类），C++ 是另一份并集，而查名点
写的 `find(nm, ['class', 'struct'])` 两边通用。底下那十几张 Map 往后并成一张带 label 的表时，
改的是 `binding.names` 里的 `store` 那一格 —— 54 个查名点一个字都不用动。

- 腿：`NOCACHE=1` 的 jnc 554 次全真跑 345/0（`OMNI_SCOPE_DIFF=1` 同过）、llvm 38/0；
  矩阵 360/360 分歧 0；榜 `3430` 未动。

### 10.9 L4 的第一半：**一个**挑重载的机器（四份抄件收成一份）

第 3 节那张冗余表里"重载决议 5 份"这一条，实际数出来是 4 份同样的循环：调用点的同元重载、
属性的多格存值器、`operator :=` 那一族、宿主面的同元原型。四处**打分**不同（各自的实参与
形参怎么对），可"怎么挑"是同一句话：

> 每个候选取各实参里**最差**的那一档当它的分；0 分 = 合不上；取最高分；并列 = 分不出来。

引擎新增 `src/core/frontend-engine/overload.js`：`pick(cands, scoreOf)` 与
`worst(n, costOf)`。打分（`argCost`，照 jancy 的 `CastKind` 排）留在语言那边 —— C++ 的转换
偏序与 jancy 的不同，但那三条规矩共用。四处调用点各自只剩两三行。

抄四遍的坏处不是行数，是**四份会各自漂**：其中一份要是把"并列"当成"取第一条"，那就是悄悄
猜了一条，而另三份会照实说分不出来 —— 这种不一致榜上看不见，因为它不报错。

- 腿：`NOCACHE=1` 的 jnc 554 次全真跑 345/0、llvm 38/0；榜 `3430` 未动。
- 还欠 L4 的另一半：`argCost` 那五档（4 完全一样 / 3 整数间与上转 / 1 拓宽 / 0 不合）还是
  写在代码里的 `if` 串，该变成一张 `CAST` 偏序表（ADR-0029 第 4 节那个形状），
  这样"jancy 允许 int→real 隐式、C++ 还允许 …"是两张表的差，不是两段 `if` 的差。

### 10.10 L4 的另一半：转换关系变成**一张有序的表**（两列结论）

`assignOk`（装不装得进）与 `argCost`（重载决议排第几）是**同一个关系的两个分辨率**，
先前是两串 `if`。摊成 `JNC_CASTS`：每行一个 `when(from, to, L)`，带两列 ——
`assign`（隐式装得进吗）与 `cost`（那一档，可以是"按是不是字面量给分"的函数），
**第一行命中的赢**，次序就是那个偏序。引擎那边只有 `castRow(rows, from, to, ctx)`
（`src/core/frontend-engine/casts.js`）。

最值钱的一点是**差异变得读得出来**：`int8 -> int32` 那一行 `assign: false` 而 `cost: 3` ——
装不进，可调用那一处给 3 分（jancy 的整数隐式转换正是在调用那一处才允许的）。先前这条差
只存在于两段控制流的差里：没人读得出来，也没法与 C++ 的那张表对照。八行表就是这门语言
**全部**的隐式转换：int 之间、Identity、数据指针→`void*`、类的上转、枚举→基枚举、
int→real、bool→int、枚举→int，每行都带出处。

顺带把 `assignOk` 里那段枚举链的循环收成 `enumChain(from, to)`（表里那一行调它）。

- 腿：`NOCACHE=1` 的 jnc 554 次全真跑 345/0、llvm 38/0；榜 `3430` 未动。

### 10.11 Phase 3 的第一列：**名字落在哪**也量出来了（`escapes`）

Phase 3 要"位置矩阵生成名字登记那一遍"。第一步不是改前端，是把那一遍**要生成的东西**
先变成可量的：矩阵的每一格除了"收不收"，再问一句"声明出来的名字，在写它的那层作用域
**外面**认不认得"。

量法：`KINDS` 多一格"用一下那个名字"的话（`Nested v;`、`twice();`…），探针把它塞进
**后面一个函数体**里再编一遍 —— 编得过就是漏出去了。为什么是"后面一个函数"而不是模块顶层：
登记发生在**降那个体的时候**，模块级那些声明的类型在那之前就解完了，拿模块顶层去问量到的是
**遍的次序**、不是作用域（第一版就是这么错的：9 格里只报出 1 格漏）。

量出来：`fn-body` 那一列 9 种命名类型**全部**漏到外面那层（正是 T-005 那笔代价），
类体 / 结构体 / union / 命名空间那几列**一格都不漏**。规格里那一列写成 `escapes: true|false`
（`module` 不声明 —— 它外面没有别的层），`--check` 跟着比：`360 / 360、分歧 0`。

机器还顺手抓出一格**探针自己的 bug**：`fn-body × enum-bitflag` 先前报"没漏"，其实是
`Flags v;` 撞上了另一笔账（"局部量不写初值"）—— 名字明明认得。改成 `Flags v = Flags.A;` 之后
那一格与另外 8 格一样。**这正是"可执行的规格"该有的样子**：不一致要么是实现漂了、要么是尺子
错了，两种都得当场看见。

- 腿：jnc 345/0；矩阵 360/360 分歧 0（新增 61 次名字探测，多 8 秒）。
- 下一步（Phase 3 的正文）：把 `escapes` 那一列**反过来用** —— 由它生成"谁在哪一层登记名字"，
  删掉 `run()` 里那三处按 `head === 'type-decl'` 的手写遍。

# ADR-0020：把 JS 前端从"编译器自己够用的子集"推到 QuickJS 那一档（≈ES2025）

状态：进行中（2026-09-08 立）。前身是 ADR-0011（JS→OIR 的降级策略）——那一份的边界是
**"能解析仓库里所有自己写的 js"**，这一份把边界换成**"QuickJS 能跑的都能跑"**。

参考实现：`/Users/wurui/Documents/Lang/reference/quickjs-2026-06-04`（`quickjs.c` 的对象模型
与 builtins、`libregexp.c` 的正则、`libunicode.c` 的字符表、`dtoa.c` 的数字打印）。

## 背景：现在这一档在哪儿

ADR-0011 那套是**编译器自用**的子集，量的是"仓库里写过什么"。于是：

- 对象 = `dict<string, dynamic>`：没有原型、没有描述符、没有 Symbol 键、没有 getter/setter
- 类 = "造实例的函数"，方法 = 每实例一份闭包（决策 13）；`extends` 只给 Error
- `this` 是**捕获的 cell**，不是调用接收者 —— 没有 `call`/`apply`/`bind`/方法借用
- 没有：生成器、async/await、Promise、for-in、finally、labels、tagged template、
  Proxy/Reflect、TypedArray 全家、任意精度 BigInt、Date、eval/`Function(src)`、
  迭代器协议（`js_iter` 是按标签硬派发的）
- 标准库是一张**封闭 op 表**（`hir/js_abi.js`，两份实现：`backend-js/prelude.js` 与
  `runtime/omni_js*.c`；解释器那条腿靠 `host/native.js` 的 `callJsOp` 复用 prelude）

三处刻意留下的边界（都是"当场报错"而不是悄悄给个错答案）：`matchAll` 交出来的是数组而不是
迭代器对象（数组/Map/Set 上的 `keys`/`values`/`entries` 同一口径 —— `for…of` 照样跑，
`a.entries().next()` 就是运行期"undefined is not a function"；C 那条腿上它们本来就是 list，
换成真迭代器对象要等对象那一族落到 C）；`Set` 的集合运算只认真 `Set`（规范里 set-like 是
TypeError）；空 `reduce`、负的
`take`/`drop`、`with` 越界在规范里是 TypeError / RangeError，这个值域里没有"可 catch 的宿主错"
那一格。`localeCompare` **刻意没做**：qjs 返回码元差（`"A".localeCompare("a")` 是 -32），
node 走 ICU 给 -1 —— 两把尺子不一致，实现哪一边都会让另一条腿分叉。

第三、四轮又量出这些（都补了，各带一个用例）：`Array.from` 的 mapFn 与类数组、

`Math.round`（自己的选择子 `'R'`：floor 再看小数部分，**不写 floor(x+0.5)**）、
`console.log` 印 `-0`（新的 `js_disp` op —— qjs 与 node 都印 `-0`，而 `String(-0)` 是 `"0"`）、
串模式的 `replace`、正则的 `replaceAll`、`new RegExp(src, flags)` 与 `source`/`flags`/`test`、
`toFixed`/`toExponential`、**`split` 的 `limit`**（这一轮唯一一处 silent 的错答案）、

拿到 undefined）与**静态方法里的 `super`**（该指父类**对象**，从前指了父类原型）。

**Number 上的位运算**（`~5`、`5 & 3`、`1 << 31`、`"5" | 0`）：两边先 ToInt32（规范 7.1.6），
结果是 Number；从前整族当场报 "requires bigint operands"，而位运算在 JS 里满地都是。
bigint 那一支照旧按 64 位算 —— JS 里 bigint 与 number 混着做位运算是 TypeError，而这个
值域里两者同一个标签，所以判据只能是"两边都 int 才走 64 位"（`$js_toi32` / `to_i32`）。
`>>>` 早先就走 i32 那两条 op，不在这一刀里；数组当操作数（`[] | 0`）只在 JS 那条腿上成立
（C 还没有对象到原始值的转换）。**内建函数当值用的身份**：`Number.parseInt === parseInt`
该为真 —— 缓存的键从"写法"改成了"op + name + argc/len"（`builtinFnValue`），从前同一个
内建取两次得到两个闭包，`===` 悄悄给 false。

**迭代方法的 thisArg**（`[1,2,3].map(cb, ctx)`）：回调的 this 就是它。从前这一格被丢掉 ——
编译期把"实参比 op 多一个"当成"用户自己的同名方法"，转去运行期的原型派发，而原型上那几格
只看第一个实参。现在 `Array.prototype` 上的 map / filter / forEach / some / every / find /
findIndex / findLast / findLastIndex / flatMap 都收第二格，回调先过 `$js_bind_this`。
这条只在 JS 那条腿上（C 还没有真函数对象，走到那儿是 loud）；`Map`/`Set` 的 `forEach` 的
thisArg 也还是 loud。

两把尺子的**严格/宽松**之差要记住：qjs 把文件当**脚本**跑（宽松），所以 `withThis()` 里的
`this` 是 globalThis、`withThis.call(5)` 会装箱成 Number 对象、顶层箭头里的 `this` 也是
globalThis；我们与 node 的**模块**语义一致（undefined / 原样的 5 / undefined）。这一族断言
因此只放在五条腿（尺子是 node）那边，不进 js262。

**构造器 `return {…}`**：`new C()` 的值是返回的那一格（规范 10.2.2 第 13 步 —— 返回数组、
函数也算，返回数/undefined/null 就还是实例）。从前 `$init` 的返回值整个被丢掉，`new F()`
悄悄给出一格空实例。判据是新的 `js_is_obj`（prelude 的 `$js_is_object`：不是那七格原始值
就算），跟着真对象那一族进 P1_JS_ONLY。顺手把 `class G extends Array {}` 从**内部崩**
（`this.globals.get(...)` 上的 undefined）改回一句 loud：`extends` 只认本文件里声明的类。

**for-of 换成惰性形态**（这一刀做完了）：`js_iter_open` 交出"list 或一格迭代把手"、
`js_iter_done` 一轮往前走一格（每轮**恰好一次** next —— cond 在体之前跑，`continue` 也走
step 再 cond）、`js_iter_cur` 取当前那一格、循环后面补一次 `js_iter_close`。三样都对上了：
`next()` 的次数、提前退出时的 `it.return()`（带 finally 的生成器于是跑得到清理）、以及
**无穷生成器 + break**（从前是一路 next 到 done，也就是**挂住** —— 量出来的 30s 超时，
比"多调几次"严重得多）。内建容器（list / string / Map / Set / bytes）照旧摊成 list：它们
本来就是抽干的语义，而且是热路径（自举出来的编译器满是数组遍历）；把手就是那个 list，所以
体里往数组上追加时下标是**活**的（两把尺子都这样）。C 那侧只有 list 这一支 —— 真迭代器是
JS 那条腿独有的（P1-c），走到那儿本来就是 "not iterable"。出口不只有 break：`return` 与
"带标签跳到外层去"都跳过了循环后面那一句 close，所以那两处按**内层到外层**补上
（`iterCloses`）；带 finally 的 try 夹在中间时，close 挂在**真发 Return 的那一处**，
于是次序是"先跑 finally，再关迭代器"（量出来的，与规范一致）。还漏的一格是**抛出去**那条路：
pending 检查那一跳不补 close。**数组解构**（`const [a, b] = it` 与 `[a, b] = it`）用同一副
形状：一格取一次就走一格、取完了没有 rest 就补一次 `return()` —— 从前它也是先抽干，
所以在无穷生成器上一样挂住。`js_iter_rest` 那一格照旧抽到 done（规范也是抽干），
展开（`[...it]`）同理。

**别名那一族**（四处，都是 silent）：`[...a]` 与 `f(...a)` / `Array.of(...a)` 只有一段展开时
整段就交回去了，而 `js_iter` 在 list 上是恒等 —— 于是"拷贝"拿到的是原数组本身
（`[...people].sort(…)` 把 people 也排了、rest 形参 push 会改到调用方）；`a.concat()` 不给
实参时那格补成 undefined，拷贝因此多一格；Map 的 `entries` 把内部存的 pair 漏了出去。
判据记在明处：**凡是"该给一份新容器"的地方，头一段是展开时先垫一格空字面量**。
同一族里还有 `Object.isFrozen(数组)`：从前跟着"不是真对象就算冻住"给 true，而
`Object.freeze(数组)` 其实是空操作 —— 现在数组 / Map / Set 上照实说"没冻住、可扩展"。

**下标形状的字符串键**（`a["1"] = x`）在数组上就是下标：从前落进旁表，那次写静静地丢了
（读那一边在 JS 腿上是对的，所以更藏得住；C 腿两边都不对，一起补了）。

**Map/Set 的 `clear`**、**`new Set(串)`**（按码点）、**JSON 里的 Symbol**（跳过那一格，
与 undefined / 函数同一档）、**`new Date(串)` 与 `new Date(y, mo, …)`** 加上 `Date.parse`、
`instanceof Date`、以及 Date 的**写方法**那一族（`setFullYear` / `setMonth` / `setTime` /
`setUTC*`：现搭一个宿主 Date、改完把毫秒写回隐藏槽）都补上了。

跳转与 try 的交叉这一格现在是完整的（`lower.js` 的 `breakAt` / `continueAt` /
`labelJump` / `finLabelAbrupt`）：`break L` / `continue L` 跨过带 finally 的 try 时，
unwind 那一格记的是"跳哪个标签"（4 起，一个目标一格），清理跑完了在 try 后面照着再跳一次；
外面还套着带 finally 的 try 就再记一次、再 break 一层，于是一层层的清理都跑得到。只有
catch 的那层 try 夹在中间就是"多跳一层"—— 它合成循环后面那句 pending 检查只在真有异常时
才进，而跳转这会儿槽是空的。反过来，跳转目标在 finally **里面**时（`try { switch { case:
break } } finally {}`、`try { for(){ break } } finally {}`）清理不能提前跑，所以
`finAbrupt` 现在要收目标那层的 OIR 深度：比 finally 那层深就不接。这之前的形状是：跨 try
的带标签跳转当场报错，而"内层只有 catch、外层有 finally"会 silent 少跳一层（量出来的：
node 印 `fin0`，我们印 `after-inner0,fin0`）。

还没做、已经量清楚的（都是loud 的，不是悄悄错）：

- **模块**：`import * as ns from "m"` 还没有（命名空间对象要是**活绑定** —— 一格访问器对象，
  而那在 C 那条腿上没有落点），在收集期当场报。另外三种已经收下了：`export { x as y }`
  与 `export default …` / `import def from "m"` 都摊成模块级绑定（改名那一句排在模块体之后；
  默认导出落成一个**带模块路径的**专属名字，导出表记在 'default' 这一格）—— 整棵 import 树
  是拼成一个程序的，顶层名字共用一个空间，所以带路径。
- **类表达式**（`const C = class {}` / `new Proxy(class {}, …)`）：类的原型与类对象现在是
  按名字建在模块的全局槽里（ADR-0011 落地第 6c 步），表达式位置要改成"建在临时量里再交出来"。
- 类对象不是函数：`typeof A` 给 `"object"`（qjs 给 `"function"`）。`A.name` / `A.length`
  两格已经补上（不可枚举的自有属性，与规范同一格），内部那格"初始化实例的闭包"也换成了
  **符号键**（`Symbol.omni.classInit`），所以 `Object.getOwnPropertyNames(A)` 与
  `JSON.stringify(A)`（= undefined，因为 JS 里类是函数）都对得上；剩下的差别只有 typeof
  与"类当函数调用"那一族。
- TypedArray 上**结果是 TypedArray** 的那几格（`map` / `filter` / `slice`）—— 成员派发器
  的 bytes 那一支已经补了结果是原始值的四格（`join` / `at` / `indexOf` / `includes`，
  先摊成字节的数组再走 list 那一格）；map / filter / slice 摊成 list 会在打印与 JSON 上
  撒谎（`[1,2]` 而不是 `Uint8Array`），所以照旧当场报错
- `RegExp.escape`：量过 qjs 的口径 —— 语法字符加反斜杠；`\t\n\v\f\r` 用短写；**码位
  小于 0x100 且不是 `[0-9A-Za-z_]` 的一律 `\xHH`**（空格、标点、控制符、`é`、nbsp 都算）；
  `\u2028`/`\u2029` 用 `\uXXXX`；首字符是字母或数字时也 `\xHH`；`中`、`😀` 照原样。
  0x7F 那一格 qjs 给的是"反斜杠 + DEL"（不是 `\x7f`），是它自己的怪癖。要做就得照这张
  表逐格复刻，不然会在"多数时候对"上分叉 —— 所以现在照旧当场报错。
- **带小数的** `toString(radix)`（`(0.5).toString(2)`）：两把尺子量过是一致的，而口径是
  "在那个进制下**能往回读出同一个 double 的最短数字串**" —— `(1/3).toString(3)` 给 `0.1`
  （不是精确展开），`(0.1).toString(2)` 却给全 53 位（那一档最短就是精确）。要做就得照
  Steele-White 那一套在任意进制上找最短，还得配一个任意进制的小数解析器往回验，两条腿
  逐字节一致才算。整数那一档早就对上了，小数这一档现在照旧当场报错。
- **Unicode 大小写表**：`toUpperCase` / `toLowerCase` 只折 ASCII。以前非 ASCII 是**悄悄**
  按码元折（量出来的：`"Straße".toUpperCase()` 给 `"STRAßE"`、`"é".toUpperCase()` 原样、
  `"ΣΟΦΟΣ".toLowerCase()` 原样），现在换成"碰上**有大小写映射的**码点就当场报错"：
  两条腿各带一张同样的范围表（129 段，prelude 的 `$JS_CASED` 与 `omni_js_str.c` 的
  `CASED`），判据是 `String.fromCodePoint(cp).toLowerCase() !== ch || .toUpperCase() !== ch`。
  不在表里的非 ASCII（CJK、标点、emoji）照原样留着 —— 那本来就是两把尺子的答案，
  编译器自己的源码（满是中文注释）也正走这条路。真要做就是 677 + 789 段的映射表加
  102 格会变长的特例（`ß` -> `SS`、`ﬁ` -> `FI`），两条腿共一份数据才不会分叉。
- `localeCompare`：现在是运行期"undefined is not a function"。做的话口径只能是**码元序**
  （node 带 ICU、qjs 不带，非 ASCII 上两把尺子本来就不一致），所以它只能算"ASCII 上对"。
- `normalize`（NFC/NFD/NFKC/NFKD）：也是运行期"undefined is not a function"。这一格要的是
  UCD 的分解/合成表（`"\u00e9".normalize("NFD").length` 是 2），与上面那张大小写表同一类
  活儿 —— 两条腿共一份数据才不会分叉，所以现在没有。
- **孤立代理**（lone surrogate）印出来的字节：我们与 node 一致（U+FFFD，`ef bf bd`），
  qjs 印的是 WTF-8 的原始三字节（`ed b8 80`）。这是 qjs 自己的怪癖，所以这类断言只放在
  五条腿（尺子是 node）那边，不进 js262。
- `console.log` 的**检视**格式：数组/对象/Map/Set/函数/Symbol 照 `String()` 走，不追
  node/qjs 的 `[ 1, 2 ]` / `{ a: 1 }`。两把尺子自己就不一致（node 印 `[ 'a' ]`、qjs 印
  `[ "a" ]`，嵌套深了 qjs 还印 `[Array]`），没有"唯一的对"。同一格里 bigint 也不补 `n`
  （两把尺子都印 `30n`）：C 那条腿上 JS 的 bigint 与方言的 int64 是同一个标签，补了 n
  方言自己的 println 就全错（量过：tests/oir 的 whole program 印成 `77n`）。所以 5 条腿的
  用例里 bigint 要用模板串印。
- `null.x` / 调用 undefined 这类**运行期类型错**是进程级的 abort，不是能 catch 的
  TypeError（每个 op 都要走 pending 槽才能改，量级在决策 14 那一档）。`JSON.parse("{bad}")`
  与循环引用的 `JSON.stringify` 同一档：规范里是可 catch 的 SyntaxError / TypeError，
  这儿是 abort。JS 那条腿单独改成可 catch 会与 C 那条腿分叉，所以两条腿一起留着。


**接收者那一格补齐了**：`js_getp` 收第三格、`js_setp` 收第四格（就是规范 OrdinaryGet /
OrdinarySet 的 Receiver）。于是 `super.x`、`super.x = v`、`Reflect.get(t,k,recv)`、
`Reflect.set(t,k,v,recv)` 四处都对上了 —— 访问器的 this 是接收者，数据格写在接收者身上
（`super.d = "own"` 落在实例上，父类原型不动）。`Reflect.set` 另有一格 op（`js_reflect_set`）
因为它交出的是**布尔**（写不进去是 false），而赋值表达式交出的是 v。
顺手修了代理那一格：接收者是代理时新属性要落到它的**目标**上（没有 defineProperty 陷阱
时规范就是这么转的）—— 不然 `p.w = 8` 写在代理对象自己身上，读回来走陷阱又成 undefined。


**私有名 `#x` 现在是符号键**（原来是叫 `"#x"` 的字符串属性，于是 `o["#x"]` 读得到、
`Object.getOwnPropertyNames` 也列得出 —— 那是这一轮最后一处 silent 分叉）。键由
`js_sym_for("#x")` 给，所以：`o["#x"]` 是 undefined、`Object.hasOwn(o, "#x")` 是假、
own-names / `Object.keys` / `JSON.stringify` 都看不见它，`#x in o` 走 has_own（brand check）。
代价写在明处：`Object.getOwnPropertySymbols` 还看得见它，而且两个类里同名的 `#x` 共用
一格键（规范靠词法作用域禁跨类访问，这个值域里没有那一层）。



`tests/js262/` 那道门现在 **34 passed / 0 known-red**（基线是 12 条全红）—— known-red.txt
里一条不剩。最后清掉的两条：`this-call-apply-bind`（Array.prototype 上摆了借得最多的
那几个方法 —— 数组的方法平时按标签派发，原型上本来一个都没有）与 `class-extends`
（`x instanceof Object` 走 js_instanceof_p，拿 realm 上那一格 prototype 比原型链）。


**内建函数当值用**（`const f = Object.keys` / `[1,2].map(Number)` / `Math.abs.name`）：
降级出一个薄包装闭包，体就是那一句 ABI 调用，所以补 undefined、lit、pre、usesJobs 还走
`abiCall` 那条路，五条腿都通（`tests/js-exec/cases/21-builtin-fn-value.js`）。两处边界：
`STATIC_CALLS` / `GLOBAL_CALLS` 里**标了 `len` 的名字才有这一格** —— `len` 是 JS 那侧的
arity，与 op 的形参个数不是一回事（`js_math` 收 2 个，而 `Math.abs.length` 是 1）；没标的
（`console.log` / `String.fromCharCode` 那些收可变实参的）照旧当场报错，不给一个 length
会撒谎的值。包装是**单件**（`Object.keys === Object.keys` 要为真）—— 顺手补上的一格：
闭包解释器从前在 JS 那条路上提前 return，单件缓存落不下去，于是 `f === f` 在那条腿上是假
而两个后端是真（`src/core/interp/eval.js` 的 makeClosure）。

已经落地的（P1/P2/P3/P4/P5 里的大件）：真对象（原型 + 描述符 + Symbol 键 + 访问器）、
`this` 是真接收者、类改原型链（static / 字段 / 访问器 / `extends` / `super` /
私有名 `#x` / static 初始化块）、迭代器协议、for-in、可选调用、tagged template、
`arguments`、解构赋值、**switch 穿透**、**try/finally**、**惰性位置里的后缀自增**、
Error 全家 + `{ cause }`、Object/Reflect/Symbol 的静态面、内建原型当值、
JSON 的 replacer / reviver / toJSON、Math 全族 + clz32、parseFloat、Array/String 的新方法、
DataView 的定宽整数与 float32、Uint8Array 的下标读写、WeakMap/WeakSet、
**Date（毫秒那一档）**、**Proxy 的五个陷阱**、**globalThis**、正则的 lastIndex 与
**具名捕获组**、**Promise + 微任务队列**、**生成器（`function*` / `yield` / `yield*` /
生成器方法 / `it.return` / `it.throw`）**、**async（`async function` / `await` /
`for await` / async 生成器 / async 方法与箭头）**、**`fn.name` / `fn.length`**、
**普通函数当构造器（`new f()` / `f.prototype` / `new.target`）**、**`eval` 与 `Function(src)`**。

还差的一条（要另立决策，不在这一轮里）：

1. `lib/BigInt 任意精度`：这个值域里的 `int` 是 **int64**（ADR-0005），所以 `2n ** 64n`
   是 0 —— **五条腿一致地是 0**，不是某条腿偷偷不一样（量过：node/qjs 给
   18446744073709551616）。要真做需要在值域里加一格"任意精度整数"：C 侧一套 bignum
   （加减乘除模幂位移比较与十进制/任意进制打印）、JS 侧不再截成 64 位、`typeof` 与打印
   （qjs 印 `1n` 那个后缀）都要能把它与 int64 分开，MIR/原生两条腿也要跟着走。
   这一步改的是**语言的值模型**而不是 JS 前端，与 ADR-0005 直接冲突，所以要单独立一节。
   已经顺手补齐的相邻那格：`(5n).toString()` / `true.toString()` 原来落到"取属性再当函数调"
   的兜底上给出 `[object Number]`，现在两条腿都按接收者的标签走 `js_num_to_string`
   （int 不先转 double —— 2^53 之上的 int64 转过去要掉精度）。

`eval` / `Function(src)` 的落点（P6）：这两样要**编译器在运行期在场**。约定是一格运行期的
钩子 —— `host/src_eval.js` 的 `installSrcEvalHook()` 把它装到宿主全局上，产物里的
`$js_src_eval`（prelude）顺着它找。装得上的场合只有"在本进程里跑"这一条：`omni run` 的
JS 腿与 REPL；`omni build` 出来的独立产物、C 那条腿、解释器腿都装不上，那时这两个 op
**当场报错**，不假装能跑（这是刻意的：产物自己是自洽的一份，不该偷偷依赖工具链）。
认下来的是**全局 eval** 那一档（规范里的 indirect eval）：每次编一段独立的模块，
所以看不见调用者的局部量 —— `let x = 1; eval("x")` 在 qjs 里是 1，在这儿是一句编译期的
"unresolved identifier"，冒到 JS 那侧是 ReferenceError（别的编译期毛病算 SyntaxError）。

`fn.name` / `fn.length` / `f.prototype` 的落点：函数不是真对象，这几格因此不是自有属性，
而是 `Function.prototype` 上的访问器 —— name/length 存在**闭包记录**里（`$nm` / `$ln`，
由 lower.js 的 closureOf / topFnValue 填，emit.js 的 closureMake 发），prototype 存在一张
按闭包记录身份查的 side table 上（prelude 的 `$FNPROTO`）。所以"具名函数取出来的值"
必须是**单件**（`single: true`，与 sexpr 的 fnref 同一格）：不然 `f === f` 与
`new f() instanceof f` 都会是假 —— 这一条是量出来的。
`new.target` 走一格运行期的槽（放的人只有 `js_fn_construct`，取的人是函数入口），
窄口记在 prelude 那一段注释里。箭头的 name（规范里来自赋值目标）与内建静态面的取值
（`Object.keys` 当值用）还没有。C 那条腿：这一族 op 都在 `P1_JS_ONLY` 里，发射时就拒。

生成器/async 这一刀的形状与它认下来的子集写在 `src/core/frontend-js/genfn.js` 的文件头上。
try / catch / finally 三种形状都通了：这个值域里的异常是"挂起槽 + 提前 return"
（ADR-0007），所以接手要**驱动**帮一把 —— 它看见挂起槽满了就把那格值送回 step（mode 2，
与 `it.throw` 同一条路），step 开头那一段先看有没有活着的 catch（`_g_cat`）、再看 finally
（`_g_fin`），都没有才原样往上冒。finally 体因此**发两份**（正常路 + 非正常路），所以它
自己不许有 yield / await，也不许有 break/continue/return。`yield*` 是先把内层收齐再一格
一格转发（`js_iter` 的老账）。拍数是量出来的：`await` 一拍，async 生成器的 `yield`
多一拍（规范 27.6.3.8 先 Await 让出去的值）。

## 决策

### 1. 走"扩现有降级器"，不另起一台引擎

不新建 `js-vm/` 子系统。理由：五条腿的差分（解释器 / JS / C / LLVM / 原生）是这棵树唯一
可靠的正确性来源，另起一台引擎等于把它作废，而且编译器自己的 JS 往返轴（`tests/js-roundtrip`）
还得留在这条路上。代价写在明处：**能挂起的控制流**（生成器、async）没有运行期栈可用，
只能在降级里做**状态机改写**（regenerator 那一套）；`eval` 与 `Function(src)` 需要编译器
在运行期在场，非 node 宿主上仍然只能报错。

### 2. 尺子是 qjs 的 stdout，逐字节

编 `reference/quickjs-2026-06-04` 出 `qjs`，同一份 `.js` 两边各跑一趟比 stdout（新门
`tests/js262/`）。test262 的 checkout 本机没有，先不进门；阶段验收时再补。
QuickJS 自己 `test262.conf` 里标 `skip` 的那些（Intl、Temporal、decorators、
ShadowRealm、explicit-resource-management、tail-call…）**我们也不做** —— "QuickJS 那一档"
就是这条线。

### 3. 对象模型是地基，先它，别的都排在后面

真对象一格值：`{proto, 有序属性表, 描述符, Symbol 键, extensible}`。`js_obj_*` 全家改走它，
`dict<string,dynamic>` 退成实现细节。`this` 随之从"捕获的 cell"改成**调用接收者**——
这一刀牵动调用约定（现在每个 JS 函数是 `fn(list<dynamic>)->dynamic`，没有 this 槽）。

### 4. 阶段顺序（按依赖排，不按难度）

- **P1 对象模型**：真对象 + 描述符 + 原型链 + Symbol + 访问器 + 迭代器协议 +
  `this`/`call`/`apply`/`bind`/`new.target` + 类改成原型链（static / 字段 / 访问器 /
  任意 `extends` / `super`）+ 对象字面量补全 + `ToPrimitive`/`instanceof`/`typeof` 对齐
- **P2 可挂起的控制流**：生成器（状态机改写）、Promise + 作业队列、async/await、
  for-await、async 生成器
- **P3 语法补全**：for-in、finally、labels、tagged template、可选调用、逗号表达式、
  `arguments`、解构与默认值补全、可选 catch 绑定、私有字段 `#x` 与 static block、
  数字分隔符与 BigInt 字面量、严格/宽松模式的差异
- **P4 标准库推到 QuickJS**：String/Array/Object/Number/Math/JSON/Date 全方法、
  Map/Set/Weak*/WeakRef/FinalizationRegistry、Proxy/Reflect、TypedArray 全家 +
  DataView + ArrayBuffer/SharedArrayBuffer + Atomics、任意精度 BigInt、Error 全家（cause /
  AggregateError）
- **P5 正则与 Unicode**：照 `libregexp.c` 复刻字节码 + 回溯引擎（命名组、lookbehind、
  sticky/dotAll、`u`/`v` 标志、Unicode 属性），字符表照 `libunicode.c`
- **P6 运行期编译**：`eval` / `Function(src)` / 动态 `import` / `import.meta`（node 宿主
  有引擎的那一路先通，别的报错）

### 5. 封闭 ABI 的成本照旧，但允许"一族一个 op"

每个 op = `js_abi.js` 一行 + prelude 一份 + C 运行时一份。P4 那一堆方法要是一人一个 op，
表会涨到上千行 —— 所以**同族方法合成一个 op + 一个 `lit` 选择子**（`js_arith` 的 `op`
字段就是这个先例）。判据：签名相同、语义同族。

## 已知风险

- `this` 那一刀会动到每一处成员调用的降级，而编译器自己的源码就跑在这条路上：
  改坏了是"编译器编不出自己"。所以 P1 内部还要再分片，每片都能单独跑 `tests/js-exec`。
- 状态机改写会让生成器函数的 OIR 体积涨几倍；C 后端那边是几万行生成 C，编译时间会涨。
- 任意精度 BigInt 要在值域里再加一格（现在 `BigInt` 就是 int64 回卷，ADR-0011 决策 5），
  那与 ADR-0005 的值语义有冲突，得单独立一节。

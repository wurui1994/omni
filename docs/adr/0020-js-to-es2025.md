## 背景：现在这一档在哪儿

ADR-0011 那套是**编译器自用**的子集，量的是"仓库里写过什么"。于是：

- 对象 = `dict<string, dynamic>`：没有原型、没有描述符、没有 Symbol 键、没有 getter/setter
- 类 = "造实例的函数"，方法 = 每实例一份闭包（决策 13）；`extends` 只给 Error
- `this` 是**捕获的 cell**，不是调用接收者 —— 没有 `call`/`apply`/`bind`/方法借用
- 没有：生成器、async/await、Promise、for-in、finally、labels、tagged template、
  Proxy/Reflect、TypedArray 全家、任意精度 BigInt、Date、eval/`Function(src)`、
  迭代器协议（`js_iter` 是按标签硬派发的）
- 标准库是一张**封闭 op 表**（`hir/js_abi.js`，两份实现：`backend-js/prelude.js` 与
  `runtime/omni_js*.c`；解释器那条腿靠 `host/native.js` 的 `callJsOp` 复用 prelude）

**Number 上的位运算**（`~5`、`5 & 3`、`1 << 31`、`"5" | 0`）：两边先 ToInt32（规范 7.1.6），
结果是 Number；从前整族当场报 "requires bigint operands"，而位运算在 JS 里满地都是。
bigint 那一支照旧按 64 位算 —— JS 里 bigint 与 number 混着做位运算是 TypeError，而这个
值域里两者同一个标签，所以判据只能是"两边都 int 才走 64 位"（`$js_toi32` / `to_i32`）。
`>>>` 早先就走 i32 那两条 op，不在这一刀里；数组当操作数（`[] | 0`）只在 JS 那条腿上成立
（C 还没有对象到原始值的转换）。**内建函数当值用的身份**：`Number.parseInt === parseInt`
该为真 —— 缓存的键从"写法"改成了"op + name + argc/len"（`builtinFnValue`），从前同一个
内建取两次得到两个闭包，`===` 悄悄给 false。

**迭代方法的 thisArg**（`[1,2,3].map(cb, ctx)`）：回调的 this 就是它。从前这一格被丢掉 ——
编译期把"实参比 op 多一个"当成"用户自己的同名方法"，转去运行期的原型派发，而原型上那几格
只看第一个实参。现在 `Array.prototype` 上的 map / filter / forEach / some / every / find /
findIndex / findLast / findLastIndex / flatMap 都收第二格，回调先过 `$js_bind_this`。
这条只在 JS 那条腿上（C 还没有真函数对象，走到那儿是 loud）；`Map`/`Set` 的 `forEach` 的
thisArg 也还是 loud。

两把尺子的**严格/宽松**之差要记住：qjs 把文件当**脚本**跑（宽松），所以 `withThis()` 里的
`this` 是 globalThis、`withThis.call(5)` 会装箱成 Number 对象、顶层箭头里的 `this` 也是
globalThis；我们与 node 的**模块**语义一致（undefined / 原样的 5 / undefined）。这一族断言
因此只放在五条腿（尺子是 node）那边，不进 js262。

**构造器 `return {…}`**：`new C()` 的值是返回的那一格（规范 10.2.2 第 13 步 —— 返回数组、
函数也算，返回数/undefined/null 就还是实例）。从前 `$init` 的返回值整个被丢掉，`new F()`
悄悄给出一格空实例。判据是新的 `js_is_obj`（prelude 的 `$js_is_object`：不是那七格原始值
就算），跟着真对象那一族进 P1_JS_ONLY。顺手把 `class G extends Array {}` 从**内部崩**
（`this.globals.get(...)` 上的 undefined）改回一句 loud：`extends` 只认本文件里声明的类。

**for-of 换成惰性形态**（这一刀做完了）：`js_iter_open` 交出"list 或一格迭代把手"、
`js_iter_done` 一轮往前走一格（每轮**恰好一次** next —— cond 在体之前跑，`continue` 也走
step 再 cond）、`js_iter_cur` 取当前那一格、循环后面补一次 `js_iter_close`。三样都对上了：
`next()` 的次数、提前退出时的 `it.return()`（带 finally 的生成器于是跑得到清理）、以及
**无穷生成器 + break**（从前是一路 next 到 done，也就是**挂住** —— 量出来的 30s 超时，
比"多调几次"严重得多）。内建容器（list / string / Map / Set / bytes）照旧摊成 list：它们
本来就是抽干的语义，而且是热路径（自举出来的编译器满是数组遍历）；把手就是那个 list，所以
体里往数组上追加时下标是**活**的（两把尺子都这样）。C 那侧只有 list 这一支 —— 真迭代器是
JS 那条腿独有的（P1-c），走到那儿本来就是 "not iterable"。出口不只有 break：`return` 与
"带标签跳到外层去"都跳过了循环后面那一句 close，所以那两处按**内层到外层**补上
（`iterCloses`）；带 finally 的 try 夹在中间时，close 挂在**真发 Return 的那一处**，
于是次序是"先跑 finally，再关迭代器"（量出来的，与规范一致）。还漏的一格是**抛出去**那条路：
pending 检查那一跳不补 close。**数组解构**（`const [a, b] = it` 与 `[a, b] = it`）用同一副
形状：一格取一次就走一格、取完了没有 rest 就补一次 `return()` —— 从前它也是先抽干，
所以在无穷生成器上一样挂住。`js_iter_rest` 那一格照旧抽到 done（规范也是抽干），
展开（`[...it]`）同理。

**别名那一族**（四处，都是 silent）：`[...a]` 与 `f(...a)` / `Array.of(...a)` 只有一段展开时
整段就交回去了，而 `js_iter` 在 list 上是恒等 —— 于是"拷贝"拿到的是原数组本身
（`[...people].sort(…)` 把 people 也排了、rest 形参 push 会改到调用方）；`a.concat()` 不给
实参时那格补成 undefined，拷贝因此多一格；Map 的 `entries` 把内部存的 pair 漏了出去。
判据记在明处：**凡是"该给一份新容器"的地方，头一段是展开时先垫一格空字面量**。
同一族里还有 `Object.isFrozen(数组)`：从前跟着"不是真对象就算冻住"给 true，而
`Object.freeze(数组)` 其实是空操作 —— 先改成照实说"没冻住、可扩展"，**现在整格补上了**：
见下面"`Object.freeze` 落在数组上"。

**下标形状的字符串键**（`a["1"] = x`）在数组上就是下标：从前落进旁表，那次写静静地丢了
（读那一边在 JS 腿上是对的，所以更藏得住；C 腿两边都不对，一起补了）。

**Map/Set 的 `clear`**、**`new Set(串)`**（按码点）、**JSON 里的 Symbol**（跳过那一格，
与 undefined / 函数同一档）、**`new Date(串)` 与 `new Date(y, mo, …)`** 加上 `Date.parse`、
`instanceof Date`、以及 Date 的**写方法**那一族（`setFullYear` / `setMonth` / `setTime` /
`setUTC*`：现搭一个宿主 Date、改完把毫秒写回隐藏槽）都补上了。

跳转与 try 的交叉这一格现在是完整的（`lower.js` 的 `breakAt` / `continueAt` /
`labelJump` / `finLabelAbrupt`）：`break L` / `continue L` 跨过带 finally 的 try 时，
unwind 那一格记的是"跳哪个标签"（4 起，一个目标一格），清理跑完了在 try 后面照着再跳一次；
外面还套着带 finally 的 try 就再记一次、再 break 一层，于是一层层的清理都跑得到。只有
catch 的那层 try 夹在中间就是"多跳一层"—— 它合成循环后面那句 pending 检查只在真有异常时
才进，而跳转这会儿槽是空的。反过来，跳转目标在 finally **里面**时（`try { switch { case:
break } } finally {}`、`try { for(){ break } } finally {}`）清理不能提前跑，所以
`finAbrupt` 现在要收目标那层的 OIR 深度：比 finally 那层深就不接。这之前的形状是：跨 try
的带标签跳转当场报错，而"内层只有 catch、外层有 finally"会 silent 少跳一层（量出来的：
node 印 `fin0`，我们印 `after-inner0,fin0`）。

**模块的四种形状**都在链接期摊平了，`lower.js` 一格模块的事都不知道。`import { a as b }` 与
`export { x as y }` 摊成模块级绑定（改名那一句排在模块体**之后** —— 本地那一格可能是 `const`）；
`export default …` 落成一个**带模块路径的**专属名字（整棵 import 树拼成一个程序、顶层名字共用一个
空间，所以要带路径），导出表记在 `'default'` 这一格，`import def from "m"` 再摊成一句绑定；
`import * as ns from "m"` 摊成一格**取值器对象**（`const ns = { get A() { return A; }, … }`）——
规范要的是**活绑定**，`ns.mut` 得看得见后来的改动，所以每一格都得是 getter 而不能是当时的值。
这一格因此天然只在有真对象的腿上成立（C 那条腿上访问器没有落点，发射时会拒）。

**类表达式**（`const C = class {}`、`return class {}`、`[class{}, class{}]`）与类声明**共用
同一段降级**（`classProtoStmts`）；差别只在"类对象与原型那两格住哪儿"。声明住模块级全局 ——
方法只能建一次，不然 `getPrototypeOf(a) === getPrototypeOf(b)` 就假了；表达式住一对**临时量**，
于是每次求值都是一格新的类。后者是可观察的：`mk(1) !== mk(2)`，两次求值造出来的实例互不
`instanceof`（qjs 就是这样，量过）。运行期 `new C()` 那一格不用改 —— `$js_fn_construct` 早就
认"身上带 `Symbol.omni.classInit` 的对象"，于是 `new pair[0]()` 这种写法自然成立。
有名字的类表达式（`class Named {}`）差一格：名字只落到类对象的 `name` 上，**不**在类体内部
当一格绑定用（规范里它是的）—— 要那一格得多开一层作用域。

**可调用的代理**（`new Proxy(函数, { apply, construct })`）：目标是函数（或类对象）时，代理
自己也得**可调用** —— `typeof p` 给 `"function"`、`p(…)` 走 apply 陷阱、`new p(…)` 走 construct
陷阱（第三个实参是 newTarget，就是代理自己）。所以这一支**不造真对象**，而是造一格闭包记录
并把 `px` 挂在它身上 —— `$dynTag` 的兜底认的正是 `{ fp, … }` 那个形状，`typeof` 于是自然对上；
`$js_px_trap` 只问 `o.px.h`，不在乎宿主是真对象还是闭包记录，两种形状因此共用同一套陷阱。
顺带补上的一格：函数值上的 `f[k]`（陷阱里 `t[k]` 是最常见的转发写法）现在落到
`Function.prototype` 那张面上，从前是"cannot index a function"。这一格在 C 那条腿上仍然
当场报（函数在那边不是真对象），与 P1 那一族同一个口径。

**宿主抛出来的错要能 catch**（JSON 那一族先落地）。`try { JSON.parse(s) } catch {}` 是真实
代码里最常见的一格写法，从前它是**硬错**（`omni: runtime error` + 退出码 70），整个进程就没了；
`JSON.stringify` 碰上环（`o.self = o`）更糟 —— 一路递归把**宿主的栈**撑爆，那是崩。现在两样都
翻成 pending 的 Error 值：`js_json_parse` / `js_json_stringify` 在 ABI 表里本来就是
`throws: true`，调用点的 pending 检查早就发了，缺的只是"别调 `$rt_error`"。
实现上这一族函数互相递归、错误点有十几处，所以内部用**宿主自己的 throw** 把栈剥到入口那一层
（`$JsonBad` 只是个信号，不是 JS 可见的值），再在入口翻成 `SyntaxError` / `TypeError`。
环的判据是**当前路径上的容器栈**，不是"见过的全部" —— `{a: x, b: x}` 里同一格对象出现在兄弟
位置上是合法的，只有落在自己的祖先里才是环。
报错**文本**不追齐：三个引擎各写各的（qjs 说 `expecting property name`、node 说
`Unexpected token b`），我们照自己那套写，只有 `name` 与可 catch 性对齐。
同一条路上还有两族：**URI 那四个全局函数**（`decodeURIComponent("%")` 是 `URIError`，编码
那侧的落单代理项也是）与**位数/进制那四格**（`toFixed` / `toExponential` / `toPrecision` 的
位数、`toString(radix)` 的进制越界是 `RangeError`）。URI 的错误点在 enc/dec 里有九处，走信号；
数那四格的错误点就在入口那一句，直接放一格 pending 的 Error（`$js_range_err`）。
这几条 op 因此都在 ABI 表里标了 `throws: true` —— 调用点的 pending 检查由它发。
C 那条腿也跟上了：JSON 那两段配了一格 `setjmp` 落点（`omni_js_json_jb`），出错点 `longjmp`
回入口 —— 与 JS 那侧用宿主 throw 剥栈是同一个形状。错误对象在 JSON 那个宏段里就地拼
（`$cls` / `name` / `message` 三格，因为 `omni_js_err_new` 住在排在后面的 `STR_ARR` 段）。
环的祖先表借 `depth` 当下标，`OMNI_JS_JSON_MAXDEPTH`（512）同时是"环能看多深"与"递归有多深"
的闸门。`jmp_buf` 是静态量，所以两个入口都先存一份再装自己那一份 —— replacer / reviver 是
用户代码，里面完全可以再调一次 `JSON.stringify`。

**待决槽有两份，边界上要互搬**（解释器那两条腿）。这是同一轮里量出来的、最隐蔽的一格：
被解释程序的 `throw` 落在**解释器**自己的待决槽（`interp/builtin.js` 的 `pendingVal`），而
prelude 那份 `$js_throw` 写的是**它自己闭包里**的 `$pending` —— 两个槽刻意分开（原生构建里
解释器自己就是编译出来的代码，共用会让被解释程序的一次 throw 把解释器的控制流也带走）。
不搭桥的后果全是**静默**的：
- 宿主 op 自己抛的错（`JSON.parse("{")`）：OIR 里那句 `js_pending` 问的是解释器这一份，
  于是 `catch` 一格都进不去，`JSON.parse` 悄悄给 `undefined`。搬的地方是 `invoke`（只在
  表里标了 `throws` 的那些上问一次）。
- 回调里的 throw（`xs.forEach(f)` 的循环住在 prelude 里）：循环问的是 prelude 那一份，
  于是剩下的圈照样跑完。搬的地方是 `wrapFn` 那一层（`mirrorPendingToHost`），两个解释器
  各一处。

顺带把**迭代方法在回调抛之后立刻停**这一条补齐了（三份实现一起改）：`map` / `filter` /
`forEach` / `some` / `every` / `find` 那四格 / `reduce` / `reduceRight` / `flatMap` 每调一次
回调之后都问一句 pending。JS 那侧因此不能再借宿主的 `.map` / `.forEach` —— 它们没有"半路
停下来"这一格。量出来的：`[1,2,3].forEach(x => { seen.push(x); if (x === 2) throw … })` 在
node 上 `seen` 是 `1,2`，我们从前是 `1,2,3`。

**数组上的 `Object.defineProperty`** 现在收"能原样表达出来"的那一种：下标在长度里的
`{ value }`（那正好就是 `a[i] = v`，三个位本来都是 true）、以及非下标键上三个位明写成 true 的
那一种（等于 `a.tag = v`）。别的一律当场报 —— `writable/enumerable/configurable` 里有 false、
访问器、下标越过长度、`length`。有一格特别容易看漏：**新键的默认是 false**，所以
`defineProperty(a, "tag", { value: v })` 在 JS 里建的是一格**不可枚举**的属性，而旁表没有这
一层 —— 收下来就会让 `Object.keys(a)` 多出一格，那是悄悄的错答案，所以新键必须明写
`enumerable: true`。从前整支落在 "defineProperty on list" 上，连 `{ value }` 这一种也不收。

同一族里还补上一格：**`Object.getOwnPropertyNames` 在真对象以外也要有答案**。数组与串在 JS 里
都是对象，`length` 是它们的一格自有属性（不可枚举），下标也是 —— 从前非真对象一律给空表，
那是悄悄的错答案（`getOwnPropertyNames([1,2,3])` 该给 `0,1,2,length`）。次序照规范：整数下标
升序在前，然后是别的字符串键（`length` 是建得最早的那一格，所以排在旁表那些前面）。
Symbol 那一档在这几格上确实是空的：旁表只收字符串键。

**`match` / `matchAll` / `search` 收非字面量正则**：`const re = /…/g` 带了 g（那一格进不了
`regexConsts`）、或者 `new RegExp(s)` 存进了变量时，从前是**编译期硬报错**
（"needs a regex literal as its first argument"）。现在把那一格实参**在运行期**摊成
`(源, 旗标)` 再交给同一格 op —— 与 `$js_str_replace` / `$js_str_split` 那一族早就在用的办法
一字不差（`$js_re_source` / `$js_re_flags` 因此有了第二个身份：非正则照规范 ToString 当
**模式**收，`undefined` 当空模式）。差的一格写在明处：`matchAll` 照规范该从实参的
`lastIndex` 起走，这儿总是从 0 起 —— 那三个方法里只有它看 `lastIndex`。

**`.source` 是 escape 过的那一格，`new RegExp(re)` 照抄源与旗标**。规范 22.2.6.13.1
（EscapeRegExpPattern）要的是"交出去的那一格能塞回 `/…/` 里再读一遍"：裸 `/` 写成 `\/`、
换行写成两个字符的 `\n`、空模式写成 `(?:)`。从前 `new RegExp("a/b").source` 给 `a/b`，
`new RegExp("").source` 给空串 —— **静悄悄的错值**，`String(re)` 跟着印成 `/a/b/`（塞回去
是另一个正则）。现在两侧各有一格 `$js_re_esc_src` / `omni_js_re_esc_src`：反斜杠后头那一格
照抄（`/a\/b/.source` 不会再 escape 一遍成 `a\\/b`），字符组 `[...]` 里的 `/` 不动
（`[/]` 照原样），`\u2028`/`\u2029` 不 escape —— 后两条都是**量 qjs 量出来的**，规范文本
偏严，尺子是 qjs。escape 过的模式塞回引擎还是同一个正则（`\/` 与 `(?:)` 引擎都吃），
所以上面那条"把运行期实参摊成 (源, 旗标)"的路照用不误，不必为 `.source` 另开一格 op。

顺着这一格把构造器也补齐了（规范 22.2.4.1）：**实参本身是正则就照抄它的源**（旗标缺席时
连旗标一起抄，给了就用给的那个），**模式缺席是空模式**而不是 `"undefined"`。这三条要让运行期
看见**原样**的实参才分得清，所以降级器不再在 `new RegExp(...)` 上套 `js_str`，ToString 挪进了
`$js_re_new` / `omni_js_re_new` 自己手里；`new RegExp()` 零实参也跟着能用了（从前是编译期
"takes one or two arguments"）。C 那一侧从前撞在 `omni_js_as_s16` 的 "regexp is not a string"
上 —— 响是响的，但两条腿的答案不一样，现在同一格。

**`split` 收运行期的正则**也跟着补齐了：`"a-b".split(new RegExp("-"))` 从前撞在
`omni_js_as_s16` 的 "regexp is not a string" 上（响是响的，但 `replace` / `replaceAll` 早就按
标签转给正则那一支了，同一个位置两种脾气）。现在 `$js_str_split` / `omni_js_str_split` 里也有
那格 `regexp` 分支，与 `replace` 一字不差。

**内建构造器当值用，与 `x.constructor`**。从前两头都不成：`Array` 当值用是编译期
"can only be used as a member base"（响的），而 `[].constructor` **静静地给 undefined** ——
`if (x.constructor === Array)` 悄悄为假，这是最坏的一种。现在 realm 上每个原型都坐着一格
构造器对象（`$js_mk_ctors`），`constructor` 是它们身上的一格普通数据属性，而 `Array` 当值用
走 `js_realm_ctor` 取**同一个**对象 —— 于是 `[].constructor === Array`、`A.prototype`、
`[] instanceof A`、`Array.name` / `Array.length` 全都对。顺手修掉一格静默：`$js_instanceof`
从前只从"真对象"起步走链，`[] instanceof A` 因此给 false；现在与静态那条路
（`$js_instanceof_p`）共用一份走法，数组 / Map / Set / 正则这些在 JS 里是对象的东西都算。

三条边界写在明处。一，**静态面挂不到函数值上**：函数在这个值域里还不是真对象，所以
`A.isArray` 是运行期 "undefined is not a function"（`Array.isArray(x)` 那条**成员写法**照旧
好用）。二，**`Function` / `Map` / `Set` / `Date` 当值用只能取不能调**：前者要编译器在场，
后三个的实参面（可迭代物、七个时间格）还没有运行期那一格，一律当场报，不给半对的值。
三，这两格 op 只有 JS 那条腿（构造器住在 realm 里，而 realm 是真对象那一族）：`.constructor`
因此单独占一格 `js_ctor_get`，让 C 在**发射期**就拒，而不是走 `js_obj_get` 静静地给
undefined。代价记在这儿：`String` / `Number` / `Boolean` 当值用（`xs.map(Number)`）从前在 C
那条腿上是能跑的（降级出来的是一格编译好的薄包装），现在为了 `"".constructor === String`
为真，这三个名字也走 realm 那一格，于是 C 上成了发射期的拒 —— 五腿用例
`21-builtin-fn-value` 里那两行因此挪去了 js262。计算写法 `o["constructor"]` 不走这条路，
那是留着的一格窄口。

**模块级 let / const 的 TDZ 在编译期拒了**。这个值域里模块级的 `let` / `const` 是**全局槽**
（后端各发一个真全局），所以"声明之前读它"从前静静地给 `undefined` —— 规范 9.1.1.1 那儿是
`ReferenceError`。函数体里的同一件事早就是响的（名字还没进作用域，报 "unresolved
identifier"），差的只有顶层这一格。判据只看**词法**：同一格顶层语句表里，读它的那句在声明
那句之前；闭包体不算 —— 它什么时候跑是运行期的事（`function g() { return B; }` 写在
`const B` 前面是合法的）。选编译期而不是运行期，理由与 `null.x` 同一条：要在运行期抛，
每一格模块级 `let` / `const` 的读都得带一句"初始化了吗"。编译期拒是**更强**的保证 ——
那段源码在真 JS 里必然抛。这也给 `tests/errors/` 开了收 `.js` 的口子：JS 前端那批**编译期**
的拒（TDZ、封闭 ABI 之外的名字、带 `extends` 的类表达式…）在 js262 / 五腿那两道门里量不到，
那两道门比的是跑出来的输出。

**几格从前把进程崩掉 / 硬错的，现在是能 catch 的错**：
- `new Date(NaN).toISOString()`（规范 21.4.4.36 第 3 步是 RangeError）。从前直接转手宿主的
  同名方法 —— 宿主抛的是**宿主**异常，一路冒到顶，印出一整片 node 栈。**崩成宿主错误是最坏
  的一档**（比静默错值还难查现场），所以这一族全数排查了一遍。`toJSON` 顺手也对上：
  规范 21.4.4.37 第 3 步在无效日期上交 `null`，不抛。
- `"x".padStart(2**31)` / `"x".repeat(2**30)`：宿主的 "Invalid string length" 同样会崩上来。
  现在先自己拦一道（上限取 node 那一档 2^29-24），交能 catch 的 RangeError。
- `new Array(-1)` / `new Array(2**33)` / `a.length = -1`（规范 23.1.1.1 / 10.4.2.4 的 RangeError）：
  两条腿都改了 —— C 那侧新加一格 `omni_js_range_err_c`（与 type 版同一套
  `{ $cls, name, message }`，同样是"ARR 段先声明、STR_ARR 段定义"）。
- `BigInt("x")` 是 SyntaxError、`BigInt(1.5)` 与 `BigInt(Infinity)` 是 RangeError
  （规范 7.1.14 / 7.1.13）。串那一支自己先验一遍形态（可选符号 + 十进制，或
  `0x`/`0o`/`0b` 前缀 + 至少一位）—— 底下那个 `$js_str_to_int` 是**方言共用**的转换原语，
  它报硬错是对的，不能改。`BigInt("")` 是 `0n`，两把尺子一致。

**`Number` 那几格与 `Math.*` 的实参也照规范强制**。`toFixed` / `toPrecision` /
`toExponential` / `toString(radix)` 的实参是 **ToIntegerOrInfinity**（21.1.3.x 每一格的第一步），
`Math.*` 的是 **ToNumber**（21.3.2.x）—— 从前两族都是严格的标签检查、当场报：
`(1.567).toFixed("2")`、`(255).toString("16")`、`Math.abs("-3")`、`Math.max("2", 1)` 全跑不了，
而两把尺子上它们都是正常值。四条腿一起（`$js_math` 与 `omni_js_math` 同一条口径）。
越界照旧是**能 catch** 的 RangeError（`toFixed(101)` / `toString(1)` / `toPrecision(0)`）。

`"x".repeat(-1)` 也改成能 catch 的 RangeError（规范 22.1.3.18）—— 但**只有 JS 那条腿**：
C 那侧 `omni_js_str_repeat` 住在普通 `.c` 里，造异常对象要 list 的类型实例（`$cls` 是一条
list），那儿拿不到，所以 C 上它还是硬错。两边都响，差别只在"catch 得住吗"，
所以这一格只在 js262 里量。

**写属性抛出来的错不再慢一拍。** `js_obj_set` / `js_setp` / `js_idx_set` 从前都不带 `throws`，于是"报了不马上查"：抛的设值器上先印了 `after-write`、错到**下一句**才被接住，`a.length = -1`
同理。这三格现在带 `throws` 了 —— 每句写属性之后多一句 `js_pending`，换的是"错落在写的那一句上"。

这一改从前翻在 **interp** 那条腿上（`08-throw-try` / `16-try-finally` 异常漏出来），根因是
**两格待决槽的搬运漏了两条边界**（两格槽刻意分开，理由见 `interp/builtin.js` 的 `pendingVal`）：

- `mirrorPendingToHost()` 往宿主那格抄一份，是**为了让宿主自己的循环停下来**（`xs.forEach(f)`
  的循环住在 prelude 里，问的是 prelude 那格）。可 op 返回之后没人把它收回来 —— 宿主那格就
  一直是脏的，后面**随便哪一句**带 `throws` 的 op 都会把那个早就被 catch 过的错当成新的重新捞
  一遍。量出来的：写属性带上 `throws` 之后，`js_idx_set` 把类方法里那次 throw 又捞了一次，
  整个程序以 uncaught 收尾，而输出一行不差 —— 最难查的那种现场。
- 调回调那两格（`js_call_fn`、`memberFallback` 里的 `js_call_this`，类方法与原型上的方法都从
  这儿下去）根本**不经过 `invoke`**，所以连 `abi.throws` 那一次搬运都没有。量出来的：
  `try { f() } catch …` 里 f 是 `() => new Array(-1)`，catch 明明进去了，可宿主槽留着那格错，
  interp 上后面 `new Array(2).length` 那一句就没了（exit 70，`--mir` 上多印一行 uncaught）。

现在：`mirrorPendingToHost` 抄的时候记一格 `hostDirty`，`invoke` 返回前 `settle()` 把它收回来
（热路径上只多一次布尔判断）；两格调回调的边界用 `settleCall()` **无条件**问一次 —— 被调的可能
是宿主自己的函数值，那一路不经过 `mirrorPendingToHost`，标志靠不住。
用例：`tests/js262/cases/write-throw-now.js`（抛的设值器 / `a.length = -1` / 下标写法各一格，
逐字节对 qjs），以及 `tests/js-exec/cases/23-callback-throw.js` 末尾那三行（动态调用那格边界，
五条腿一起）。RangeError 的消息文本两把尺子不一样（node 大写、qjs 小写），我们跟 qjs，
所以五腿那格只量"抛没抛"。

**`Object.freeze` 落在数组上真的生效了。** 数组 / Map / Set / dict / bytes 在这个值域里还不是
真对象（没有真对象那张槽表），从前 `freeze` / `seal` / `preventExtensions` 对它们是**空操作**：
`Object.isFrozen(冻过的数组)` 给 false、往里写还写得进去 —— 两头都是悄悄的错答案，而后者更糟，
因为写的那一句看着成功了。现在三格标记挂在 prelude 的三张弱表上（`$FROZEN` / `$SEALED` /
`$NOEXT`，包含关系：冻住 ⊂ 封住 ⊂ 不可扩展），尺子（qjs 跑脚本，非严格）的口径分得很细，照抄：

- 不可扩展：长不了。`push` / `unshift` 抛 TypeError `object is not extensible`。
- 封住：还删不了。`pop` 抛 `could not delete property`；写现有那几格照旧成立。
- 冻住：连写都不行。`shift` / `reverse` / `fill` / `copyWithin` / `splice` / `sort` 抛
  `'i' is read-only`，而**赋值**（`a[0] = x`、`a.length = 0`、`a.x = 1`、`delete a[0]`）是
  静静地忽略 —— 非严格模式下的赋值就是这样，不是我们漏了一格。
- `sort` 只在真要动格子的时候才撞锁（冻住的数组 `sort()` 在已经有序时不抛、
  `sort((x,y)=>y-x)` 抛），所以先排在拷贝上比一遍。
- Map / Set 冻住之后 `m.set(…)` 照旧成立：内部槽不是属性，两把尺子一致。

`delete a[i]` 顺手也对上了：从前那一格一律当场报"表达不出洞"，而封住的数组上 delete
本来就什么都不做、返回 false —— 洞根本不会出现，所以那句报错不该拦在前面。

**这六格现在 C 那条腿也有了**（P1-c 的第二步）：三档锁的表在 `omni_js_obj.h`，与 `xprops`
同一招 —— 键就是 `omni_js_key` 给引用值发的地址（这个运行时不搬对象也不回收，所以地址在一趟里
就是同一性）。C 上能被锁的只有容器（list / dict / Map / Set / bytes），而**真对象在这条腿上
根本不存在**，所以"真对象那一支"到不了 —— 六格在 C 上是**完整**的，不是半对的。
`omni_js_arr_*` 那十来格改写 op 与 `omni_js_obj_set` / `deletek` / `length = n` 都补了守卫，
消息与 prelude 逐字相同。

**顺手量出一条待定的口径**：`a[0] = x` / `a.length = 0` / `delete a[0]` / `a.x = 1` 落在冻住的
数组上时，**两把尺子是分开的** —— node 按模块（严格模式）抛 TypeError，qjs 按脚本（非严格）
静静地忽略。我们的 JS 是模块，照理该跟 node；可 js262 那道闸要求逐字节对 qjs。现在跟的是 qjs，
所以那几格只在 `tests/js262/cases/freeze-array.js` 里量，五腿用例（`25-freeze-container.js`）
只量两把尺子都同意的部分。这条要单独定：改口径等于把"我们的 JS 是严格模式"这件事贯彻到
赋值失败的路上，牵动的不只是冻住那一族。
代价是数组那些改写 op（`push` / `pop` / `shift` / `unshift` / `reverse` / `fill` /
`copyWithin` / `splice`）都加了 `throws`，每句之后多一次 pending 检查。
用例：`tests/js262/cases/freeze-array.js`（三档锁 × 读写删各一格，逐字节对 qjs）。

**`String.fromCodePoint` 也收可变实参了。** 它与 `fromCharCode` 是同一族"逐个码点拼串"的归约
（规范 22.1.2.2 / 22.1.2.1），可是表里只有后者标了 `fold` —— 于是
`String.fromCodePoint(97, 98)` 在**发射期**就被拒（"takes at most 1 argument"），
而那是再普通不过的 JS。同一格上零实参那一档两个名字都错：落到"缺席的实参补 undefined"那条，
`$js_idx(undefined, 0)` 是 0，印出来多一格 NUL —— **静静地**多一个字符。
现在零实参那档直接给空串。用例：`tests/js262/cases/str-from-code.js`。

**函数体里 / 块里的类声明收了。** 规范 14.7.14 里它就是一格 `let` 绑定加一格类值
（BindingClassDeclarationEvaluation），所以照这个意思降：`class A { … }` ≡ `let A = class A { … }`，
值那一边走 `classExpr` 那条现成的路。从前这儿一律当场报"只支持模块顶层" —— 而函数里放一个
小类是再普通不过的 JS。两处配套的坑都是**捕获**：

- 方法体里的 `new Point(…)` 引用的就是那个名字。按值捕获会在类值装进去**之前**取一次 ——
  量出来的是宿主的 `Cannot access 'v_Point' before initialization`。所以 `preCells` 也认
  `ClassDecl`：先立一格 cell，闭包捕获的是 cell，读是后来的事。
- **字段初始化式**（`#n = start`）那句表达式是在 `$init` 那格闭包里跑的，可 `nestedFns` 只认
  "有 params 又有 Block 体"的节点，字段不算 —— 于是外层不给 `start` 装 cell，报
  `unresolved identifier 'start'`。现在字段也算一格"内层函数"。这一格与类在哪儿声明无关，
  顶层的类也一样修好了。

**局部类的 `extends` 也收了**：父类只认"这个文件**顶层声明过的非 Error 类"—— 原型链要拿父类的
原型对象与 `$init`，那两格是模块级全局，只有顶层声明的类才有。别的（`extends Error`、
`extends Array`、表达式当父类）当场报，话也说准了：
`'extends' here only accepts a non-Error class declared at the top level of this module`。
`super.m()` 与 `super(...)` 靠 `fn.classOf` 去 `classes` 表里问父类名，而类表达式没有自己的表项，
所以配一格**合成的键** `@cls<n>`（不是合法的 JS 标识符，撞不上用户的类名 —— 与模板站点那格
`@tpl<n>` 同一招）。用例：`tests/js262/cases/local-class-extends.js` 与 `07-classes.js` 末尾那一段。

**局部类的 static 块与 static 字段初始化式**（规范 15.7.4 / 15.7.14）还差最后一格：它们在
"类定义那一刻"跑，里面读的类名就是那格 `let` 绑定 —— 等到 `let A = …` 那一句才写就晚了
（量出来的是 `cannot assign to an index of a undefined`）。现在类对象一造好就先往那一格写一次
（`classProtoStmts` 的 `afterCreate`）；规范里类体内部那个类名本来就是**另一格**绑定、这时已经
初始化好，所以这不只是绕开顺序问题，口径也是对的。配套的一格：`nestedFns` 也要把 `staticBlock`
算成"内层函数"（与字段初始化式同一条），不然外层根本不给类名装 cell。
用例：`tests/js262/cases/local-class-static.js`。

**惰性位置里对成员 / 下标目标做 `++` / `--`** 从前整族拒。三元的分支与 `&&` 的右边开不了语句，
而 `lvalue` 对成员目标头一件事就是 `emitPre` 存接收者 —— 于是报
`this expression needs a temporary in a lazily-evaluated position`。量出来的是最常见的手写迭代器：

    next() { return this.i < 3 ? { value: this.i++, done: false } : { done: true }; }

现在"存接收者"与"存计算键"也折进表达式，靠**三元的条件一定先算、两条分支又一样**来定顺序
（名字那一支早就用这一招）。于是 `get` 与 `set` 里读到的是同一格临时量，C 那边实参求值次序
未指定也不再要紧 —— 从前正是因为这一点才整族拒的。前缀那一档更简单：值就是写回去的新值，
`js_idx_set` 正好交出它。用例：`tests/js262/cases/lazy-update-member.js` 与
`19-lazy-update.js` 末尾那一段（五条腿）。

**收可变实参的内建"当值用"从前只拿前两格。** `builtinFnValue` 按 `spec.argc` 定死包装的形参
个数，可 `Math.max` / `min` / `hypot`（`assoc`）与 `String.fromCharCode` / `fromCodePoint`
（`fold`）在 JS 里是可变实参的 —— 于是 `const F = { max: Math.max }; F.max(1,2,3)` 悄悄给 2，
零实参那档给 `NaN`（规范是 `-Infinity`）。这一格是**跑一段真程序才露出来的**：
`max(1, 2, 3) - min(4, 5)` 我们给 -2，两把尺子都是 -1。
现在包成 `(...xs) => Math.max(...xs)` —— 带展开的调用本来就走 `abiSpreadCall`，运行期 reduce，
一格不差。顺手给 `Math.hypot` / `String.fromCharCode` / `fromCodePoint` 补上 `len`，于是它们
也能当值用了（从前是"不在封闭 ABI 里"的拒绝）。用例：`tests/js262/cases/builtin-fn-variadic.js`
与 `21-builtin-fn-value.js` 末尾那一段（五条腿；`f.length` 要函数的原型面，C 上还没有，只在
js262 里量）。

**内部标记不该被观察到。** `JSON.stringify` 从前用 `[[Get]]` 去问"这一格是不是类对象"
（`omni.classInit` 那个符号键），于是**代理的 get 陷阱把这一问也接住了** —— 一个"每个键都答
一句"的校验代理（`get(t, k) { return k in t ? … : "<no " + k + ">" }`，很常见的写法）上
`JSON.stringify(proxy)` 静静地给 `undefined`，而两把尺子都老老实实序列化。现在判据统一走
`$js_is_class`：只看**自有**的槽，不走 `[[Get]]`，所以既碰不上取值器也碰不上陷阱
（`typeof` 那一格本来就是这么写的，这次把两处合成一份）。
用例：`tests/js262/cases/proxy-json.js`（五种陷阱组合 + 非函数的 `toJSON` + 真的类对象）。

**生成器里的 `for-of` 从前会挂住。** 那儿走的是老的 `js_iter`（先把整串收成一格 list 再按下标走），
而生成器外面早就换成了惰性把手。于是这一段 —— 再普通不过的惰性管道写法 ——**永不返回**：

    function* take(it, n) { let k = 0; for (const v of it) { if (k++ >= n) return; yield v; } }
    for (const v of take(nat(), 3)) …          // nat() 是无穷生成器

既不响也不停，比错答案还糟。有限源上同样看得见：`take` 之后源还被一路拉到底
（量出来的：`pulled` 是 100，两把尺子是 4）。现在生成器里的 for-of 用与 `lower.js` 的 `forOf`
**逐行对齐**的四格 op（`js_iter_open` / `js_iter_done` / `js_iter_cur` / `js_iter_close`），
`js_iter_done` 那一问就是"往前走一格"。`return` 穿出去那条路不经过循环出口，所以 `retStmt`
另补一次 `close`（规范的 IteratorClose，见 `genfn.js` 的 `closeOpenIters`）。
`for-in` 照旧是"先收齐键再走" —— 键本来就得先收齐。
用例：`tests/js262/cases/gen-forof-lazy.js`。

**P1-c 的第一步落地了：Symbol 那一族现在四条腿都有。** C 侧新增 `OMNI_DYN_SYM` 标签
（排在枚举**末尾** —— 前面那些的号在老产物里到处写着，插在中间等于把标签全挪一格）与
`runtime/omni_js_sym.c`。三条规矩与 prelude 的 `$js_sym_*` 逐条对齐：

- **同一性就是地址**（`Symbol("a") !== Symbol("a")`）。`omni_js_key` 的兜底本来就按地址给
  引用值发键，所以符号当属性键不必另开一支。
- `Symbol.for` 另有一张全局注册表，同名共用一格；`Symbol.keyFor(Symbol.iterator)` 照规范是
  `undefined`（well-known 那一张与注册表是**分开的**两张）。
- `Symbol()` 与 `Symbol("")` 可观察地不同，所以 `has_d` 单独记一位，不拿空串当哨兵。

顺手给 ABI 加了一位 `litText`：别的 op 的字符串 lit 都是**一个字符**的 op 码（C 那边收 char），
而 well-known symbol 的名字是整个词 —— 塞进 char 里就成了多字符字符常量（实现定义的打包值，
clang 只是警告）。标了这一位的 op，三处发射点都按 `omni_str` 传。

还差 `s.toString()` / `s.description`：那两格住在 `Symbol.prototype` 上，属于真对象那一片
（还在 P1-c 里）。用例：`tests/js-exec/cases/24-symbol-basic.js` —— **五条腿一起**量，
C 那条不再跳过。

**`for-in` 也有 C 孪生了。** 规范是"自有 + 继承来的可枚举字符串键，去重"，而这条腿上
**没有原型链**（真对象还在 P1-c 里），所以只剩自有那一段 —— 正好就是 `omni_js_obj_keys`
的三支（串按下标、list 按下标 + 旁表里的非下标名、dict 按键）。容器之外交空表。
从前 `for (const k in o)` 在 C 上整格拒，而它是再普通不过的 JS。
用例：`03-array-object.js` 末尾那一段（五条腿）。

**自带 `toString` 的对象在 C 那条腿上也能 `String()` 了。** 从前这一格当场报，理由是
"调回调要现拼一条实参 list，而运行时那份 `to_s16` 住在普通 `.c` 里造不出来"。真正的答案是
**把这一格挪进宏段**：`js_str` 与 `js_disp` 两条 op 的 C 名字现在指向 `omni_js_str_v` /
`omni_js_disp_v`（在 `omni_js_str_arr.h` 里），段里 list 是现成的，所以调得动 —— 对象自有
或原型链上的 `toString` 都算，返回的还是对象时落回标签那一句。

`to_s16` 里那两句响错留着当**兜底**：`"" + o`（`js_add`）与 `Array.prototype.join` 在段里
也是直接转字符串，没走 op 层，所以那两条路上自带 `toString` 的对象照旧是一句响错。
这是有意的窄口 —— 把它们也搬进 op 层要动最热的算术路径。
用例：`tests/js262/cases/own-tostring.js`（逐字节对 qjs，四条腿）。

**类在 C 那条腿上跑起来了（P1-c 的第十步的后半）。** 真对象一有原型链，类就只差三样：
`js_obj_def`（属性位齐了，`{ value: 1 }` 造的那格不可枚举／不可写／不可配置现在表达得出来）、
`js_nt_put` / `js_nt_take`（new.target 那格槽，与 this 同一招）、以及 `js_instanceof`
（沿原型链找 `C.prototype`）。量出来的答案：构造器、方法、getter/setter、静态方法与静态
字段、`extends` + `super()` + `super.m()`、`instanceof` 沿链、`Object.keys` / JSON /
for-in / 描述符 / freeze 落在实例上 —— 逐字节对 qjs 一格不差。

路上有两处**表示**要改（都只动 C 那条腿，JS 那条腿上两种写法本来就是同一个 `$js_obj_new`）：

- **类对象**与**带访问器的对象字面量**要一格真对象：前者身上挂不可枚举的 `prototype` /
  `constructor` / 静态方法，`extends` 还要把父类当自己的原型；后者的 `get x()` 住在属性
  槽上。所以多了一条 op `js_obj_slots`（JS 侧就是 `$js_obj_new`，C 侧是"一格空的真对象"）。
  普通对象字面量照旧是 dict —— 那是热路径。
- `setPrototypeOf` 落在 dict 上现在**当场报**。静静地不设等于把继承丢了：`class Q extends P`
  的类对象正是这么串起静态成员的。

**realm 的第一刀落了（P1-c 的第十三步）：`Object.prototype` 那一格是真的可用，别的原型
只提供同一性。** 上面那个"两件事"的拆法就是这一刀的形状：

- **C 侧现在造得出原生函数值**：闭包记录是 `{ omni_fnptr fp; …捕获的 }`，所以一格
  `{ fp, sel, a }` 的记录 + 一个按 `sel` 分派的入口就够（`omni_js_nat_`）。接收者走 this
  那格槽，与别的调用一个路子。
- **`Object.prototype`** 按规范 20.1.3 挂全了六格（`toString` / `toLocaleString` /
  `valueOf` / `hasOwnProperty` / `isPrototypeOf` / `propertyIsEnumerable`），都不可枚举。
  那张表短而封闭，所以"挂全"是能做到的。
- **别的原型**（Array / String / Number / …）是一格**带 `get` 陷阱的代理**：读成员当场报
  （"内建原型上的成员还没搬到 C 那条腿"），而**同一性照旧成立** —— `instanceof` 只比它。
- `omni_js_proto_of_tag_` 把每个标签映到它那格原型上，`js_instanceof_p` 每一步都过它，
  所以 `[] instanceof Array` / `[] instanceof Object` / `p instanceof Object` /
  `Object.create(null) instanceof Object` 这一族全对上了（逐字节对 qjs）。
- 两处连带：`omni_js_obj_new_p(undefined)` 的默认原型改成 `Object.prototype`（与 prelude
  一字不差），普通对象（dict）取不到的名字**接着往 Object.prototype 找** —— 少了后者
  `({a:1}).hasOwnProperty("a")` 会静静地给 undefined。list 那一支刻意不接：数组的原型是
  那格"读成员就报"的代理，接上去会把 `a.zork` 从 undefined 变成一句响错。

一处**闸门当场量出来的自伤**：realm 落地之后每格对象的链上都有 `Object.prototype.toString`，
于是 `String(new Error("x"))` 从 `"Error: x"` 变成了 `"[object Object]"` —— "自带 toString"
的判据必须把**继承来的那一格**排除掉，落回 `to_s16` 那套按标签直说的逻辑。
用例：`tests/js262/cases/realm-object-proto.js`（逐字节对 qjs，四条腿）。

**自举整条链绿了（P1-c 的第十四步）：`node src/cli.js bootstrap` 9 项全过。**
`globalThis` 那一格是最后一道门 —— 量法是把 C 后端那句拒绝临时换成"记下名字接着走"，
整份 `emit-c src/cli.js` 跑一趟，survey 出来**只剩 `js_global_this` 一个 op**。它不难：
这个值域里没有全局环境记录，所以 `globalThis` 就是**一格以 `Object.prototype` 为原型的普通
真对象**（每个 realm 一份，与 prelude 里那格 `gt` 逐条对应）。挂上去的读得回来、`in` /
`Object.keys` 都对；内建（Math / JSON …）不在它身上，那是画出来的边界。

同一刀里修掉的四处（每一处都是"闸门之外的静默错答案"，都带用例）：

- **改名的导入摊出来的绑定没进重名检查**。`import { a as b }` 会摊成一句模块级
  `const b = a;`，可三个文件都写 `import { RELOC_ARM64 as RELOC }` 时就摊出**三句**
  `const RELOC = …`，而 `x64/asm.js` 自己导出了一格**不同**的 `RELOC` —— 同一个全局槽先被
  x64 的表填上再被 arm64 的表盖掉，x64 的代码生成读到的就是 arm64 的重定位号。现在
  `link.js` 里那张 `owner` 表连别名一起管：同名不同源当场报，同名同源只留第一句。
  （症状先露在 TDZ 那道检查上 —— 它报的是"`RELOC` 在声明之前被读"，因为盖过来的那句排在后面。）
- **`a.unshift(x, y)` 悄悄退化成"取属性再调"**。ABI 那格 `js_arr_unshift` 是定长的
  （一次插一格），实参多了就落到"这是用户自己的同名方法"那条兜底路上，而接收者是 list ——
  `js_obj_get(list, "unshift")` 给 undefined，于是运行期一句 `not a function`（C1 跑自己时
  就死在这儿）。现在按 `concat` 那个套路摊：实参**从左到右**先求进临时量（求值次序可观察），
  再**倒着**一格格 unshift，返回值正是最后那次的新长度。带展开的那一支当场报。
  用例：`tests/js262/cases/arr-unshift-many.js`。
- **`String(真对象)` 一律当场报**。`to_s16` 里"自带 toString"的判据走的是自己那份链遍历，
  realm 落地之后链上必有 `Object.prototype.toString`，于是 class 的实例、`globalThis` 全中招。
  这份 `.c` 认不出 realm 那张表（它住在生成单元的宏段里），所以按**链尾**认：最近的那格
  toString 与链尾那格是同一个函数就是继承来的。用例：`tests/js262/cases/str-of-real-object.js`。
  （`"" + obj` 那一格还是响错：`js_add` 不走 `omni_js_str_v`，欠账。）
- 编译器自己源码里三类过不了自举那条腿的写法：`process.env`（改走封闭 ABI 的 `env`）、
  惰性求值位置里的 `new X(…)`（12 处，拆成一句 `if`）、`genfn.js` 里六个与别的模块撞名的
  模块级名字（改名）。

**`f.name` / `f.length` 四条腿齐了（P1-c 的第十五步）。** 这两格在这个值域里不是自有属性，
而是 Function.prototype 上的两个访问器，值住在闭包记录里（`$nm` / `$ln`）。三处补齐：

- **两条解释器腿**的记录是 `wrapFn` 造的、只有 `fp` —— 于是 `f.name` 静静地给空串、
  `f.length` 给 0，连 bind 出来的 "bound f" 也塌成 "bound "。js262 那道门只跑 JS 腿，
  所以这个分叉一直没被闸门看见。现在 `interp/eval.js` 的 makeClosure 与 mir 解释器的
  CLOSURE 都填，MIR 的闭包描述子也把 `fnName` / `fnLen` 带过来。
- **C 那条腿**的记录是"函数指针 + 捕获"，加两个字段就得动每一份记录的布局与每一处捕获的
  下标。所以按**模板**走：同一个模板发出来的每一格函数，名字与形参个数都一样，于是一张按
  `fp` 索引的静态表（`omni_js_fn_meta`，emit.js 的 `fnMetaTable` 发、main 里登记一次）就够
  —— 造闭包那条热路上一点开销都不加，查表是冷路径（线性扫）。表里没有的答 `""` / 0，
  与 JS 腿上读不到 `$nm` 时一致。`call` / `apply` / `bind` 照旧当场报（那要真的
  Function.prototype），所以这条用例进的是五条腿那道门、里头不含它们：
  `tests/js-exec/cases/30-fn-name-length.js`。

**`call` / `apply` / `bind` 也有 C 孪生了（P1-c 的第十六步）。** 有了原生函数值这一格之后
它们只差一张 sel：

- `f.call` / `f.apply` 是**一格捕获了目标的原生**（sel 8 / 9）。call 把第一个实参当接收者、
  其余重新装一条 list；apply 直接把那条数组当实参表（`undefined` / `null` 当空表，
  别的非数组当场报）。
- `f.bind` 出来的那一格（sel 10）把 `[目标, this, 名字, 形参个数, …预置的实参]` 存进载荷 ——
  名字与个数是**每一格自己的**（`"bound f"` / `max(0, len - 预置个数)`），按 sel 查静态表
  查不出来，所以取 `name` / `length` 时读载荷的第 2 / 3 格。bind 链因此也对：
  `g2.bind(…)` 的名字是 `"bound bound f"`（逐字节对上 qjs）。
- 原生自己的 `name` / `length` 按 sel 查一张短表（`omni_js_nat_name_`）：它们共用一个 `fp`，
  按 fp 索引的那张表认不出来 —— 少这一支 `f.call.name` 会静静地给空串。

于是 `Object.prototype.toString.call(x)`、`Object.prototype.hasOwnProperty.call(o, k)`
这一族在 C 那条腿上真的能跑了。用例：`tests/js-exec/cases/31-call-apply-bind.js`
（五条腿逐字节对 node，含借方法、bind 链、`f.call.call(f, o, 5)`）。
`new (f.bind(o))` 这一格两条腿一样地"忽略绑定的 this"（prelude 那份 bind 也是），
记着算欠账。

**`toFixed` / `toExponential` 有 C 孪生了（P1-c 的第十七步）。** 从前这一格是**当场报**，
理由记在代码里：JS 在那个 double 的**精确十进制值**上舍、恰好一半时取绝对值更大的那个
（`(2.5).toFixed(0)` 是 `"3"`），而 C 的 `%.Nf` 是就近取偶（给 `"2"`）—— 只差这一处，
而这一处恰恰会被量到。

现在走精确展开：double 是二进制小数，它的十进制展开**有限**（最长 1074 位小数），而这两个
宿主的 printf 给的就是精确位。所以先 `%.1100f` 印出精确展开，再自己在第 f 位上按
"下一位 >= 5 就进"舍 —— 有了精确位，这条判据与规范逐字等价（"4 后面全是 9" 照样舍去）。
`toExponential()` 省略实参那一档从 0 位起往上试，头一个能 `strtod` 原样解析回来的就是它。
一处量出来的坑：`-0` 那格 printf 会印负号，而 `-0 < 0` 为假 —— 收数字时不过滤的话
`(-0).toFixed(2)` 会给 `"-0.00"`（qjs 是 `"0.00"`）。
用例：`tests/js-exec/cases/32-to-fixed-exp.js`（五条腿对 node，含 2.5 / 9.995 / 999.995
这些平局与"进位推到头"）。

**ToPrimitive 在 C 那条腿上通了（P1-c 的第十八步）**，`"" + obj` 那笔欠账清了。
拦路的是同一个结构问题：`String(o)` / `o + 1` 要**调** o 自带的 toString，而调回调得现拼一条
实参 list —— list 的具体类型只在生成的那个翻译单元里，`omni_js.c` 造不出来。

办法与 `fn.name` 那张表同一个套路：**段那边登记一格钩子**。`OMNI_JS_STR_ARR` 里多一个
`omni_js_prim_v`（调自带的 toString、把**原始值**原样交回），main 里登记一次；
`omni_js.c` 那边 `js_prim1()` 用它，没登记时（不是 JS 那条腿）落回按标签的那串。
三处接上去：`to_s16` 的 OBJ / dict 两支、`omni_js_add`（两边先取原始值**再**看有没有串）、
`to_num1`（`[3] * 2` 是 6、`{} * 2` 是 NaN）。递归那一格有深度守卫：toString 又交回来一个
对象时落回按标签印，正是规范里"再试 valueOf、这个值域里没有那一格"的落点。

于是这一族在 C 上齐了：`[1,2] + 1` → `"1,21"`、`{toString(){return 42}} + 1` → `43`（**数**，
不是 `"421"`）、`` `${obj}` ``、`[obj].join()`。用例：`tests/js-exec/cases/33-to-primitive.js`。

**钩子第一版只看 toString，当场被自己的探针抓住**：`{valueOf(){return 7}} + 1` 给了
`"[object Object]1"`（该是 8）、`* 2` 给了 NaN（该是 14）—— 从"当场报"变成了**静默的错答案**，
比原来更坏。所以钩子按规范 7.1.1 带上 hint：`'s'`（`String` / 模板）先 toString，
默认口径（`+` / `*`）先 valueOf；两个都有的对象在这两条路上答案不同，所以它是一格真判据。
`Symbol.toPrimitive` 还没有 —— **有它就当场报**，不悄悄按 valueOf / toString 走。
**接着把这一格补齐了（同一刀的后半）：带计算键的对象字面量一律降成真对象。**
静态判不出 `{[k]: v}` 里那个键是串还是符号，而这条腿上的"普通对象"是一格 dict —— dict 的键是
UTF-8 串、挂不了符号。字面量里带计算键的写法本来就少，换来的是"符号键的对象字面量四条腿都
成立"。于是 `Symbol.toPrimitive` 也能真的实现（实参是 hint 的**名字**：`"string"` /
`"number"` / `"default"`，三个名字一字不差 —— 回调里按名字分派的写法很常见），
`Number(obj)` 那一侧也接上了（`omni_js_to_prim_c` 从 omni_js.c 导出去给 omni_js_num.c 用）。

三处被自己的闸门 / 探针抓住的坑，都记在这儿：
- `fnMetaTable` 按 `!== undefined` 筛闭包名字，而计算键的方法名字是 **null** ——
  `utf8Bytes(null)` 当场把宿主炸了（最坏的一档）。判据改成"**是个串**"。
- 串口径的 ToPrimitive **只能看 toString**：每个对象的链上都有 `Object.prototype.toString`，
  它永远成功（答案就是按标签那串），所以规范里 valueOf 那一步在串口径上到不了。
  接着问 valueOf 的话 `String({valueOf(){return 7}})` 会从 `"[object Object]"` 变成 `"7"`。
- 链的尾巴可能是一格 dict（`Object.create({…})`）：符号键在那儿是"**没有**"，不是响错 ——
  少这一道 `String(Object.create({…}))` 在问 Symbol.toPrimitive 时就当场报了。
  没有真对象接收者时的符号键照旧当场报，但话说清了是哪条腿缺哪一格。

用例：`tests/js-exec/cases/34-symbol-keys.js`（五条腿对 node）。

**内建原型上的成员在 C 那条腿上通了（P1-c 的第十九步）：照成员表生成。**
realm 的第一刀只给了同一性（`Array.prototype` 是一格"读成员就报"的代理），这一刀把那格陷阱
接到**成员表**上 —— `JS_MEMBERS` 里那 93 格有 C 孪生的方法，emit 期已经各生成了一个
`omni_js_m_*`（memberDispatch），所以只要再发两张表：一张按 (原型名, 成员名) 查号、
一张按号调（`protoMembers`），main 里登记一次。运行时那边只留两格函数指针。

陷阱照表答，**三分**：

- 表里有、且有 C 孪生 → 发一格"第 ix 格原型成员"的原生（`sel >= 1000`，载荷记着名字与形参
  个数）。于是 `arr.map` 取出来是个能调的函数值、`Array.prototype.map.call(x, f)` 成立、
  `m.name` / `m.length` 也对。
- 表里有、但只有 JS 那条腿有实现（`noC`）→ **当场报**，那句话是"成员表缺一格"的固定签名。
- 根本不在表里（`[].zork`）→ **undefined**，那才是这个值域里的答案。少了这一分，
  "缺一格实现"与"这个名字本来就没有"会挤成同一个答案。

于是 `obj_getk` 里 list 与原始值那两支也能接原型了（从前 list 刻意不接、原始值当场报）：
数组走 Array.prototype、串走 String.prototype、数走 Number.prototype……
`omni_js_proto_of_tag_` 把标签映过去，认不出的名字答 undefined，所以 `a.zork` 还是 undefined。

三处量出来的坑：
- **代理陷阱的实参是 (目标, 键, 接收者)** —— 键在**第二格**。从前那句拒绝读的是第一格，
  于是印出来的"成员名"是 `"[object Object]"`，照表查更是一定查不着。
- `valueOf` 不在成员表里（它不是一格 ABI 成员）：这个值域里它在任何原型上都只交回接收者，
  所以直接发那格现成的原生（`sel 3`）。
- **JS 那条腿的 `Number.prototype` 身上一格都没挂**：`(5).toFixed` 在那儿是 undefined，
  而 C 这边照表答"是个函数" —— 五条腿那道闸门当场抓住。prelude 里补上 toFixed /
  toExponential / toPrecision / toString / valueOf 与 Boolean 的两格。

用例：`tests/js-exec/cases/35-proto-members.js`（五条腿对 node）。

**内建构造器当值用也有 C 孪生了（P1-c 的第二十步）——realm 那一步至此收口。**
`const A = Array`、`[].constructor === Array`、`x instanceof A` 这一族：构造器是一格原生
（sel 从 `OMNI_JS_CTOR_SEL` 起，名字与形参个数按 sel 查两张静态表），每个名字**缓存一格**
所以取两次是同一个值；`prototype` 预先坐进 fnproto 旁表（不坐的话 `[] instanceof Array` 会
静静地变成 false）。实参面只做得了 Object / Array / String / Number / Boolean / Symbol /
RegExp 这七格，Function / Map / Set / Date 当场报 —— 与 prelude 里 `no()` 那几行一字不差。

`x.constructor`：真对象走槽表与链，别的按标签走它那格 realm 原型（陷阱认得 `"constructor"`）。
`Object.prototype` 是真对象、不是代理，所以那一格要**真坐一格** —— 少了它
`({}).constructor === Object` 会静静地给 false。

一处段序的坑：`omni_js_s16_lit` 与 `omni_js_str_v` 都住在 OBJ **后面**的段里，
所以 OBJ 段里要么自己造那格名字（`omni_s16_of_utf8`）、要么改用早就在的 `omni_js_str`。

**静态面照旧挂不上去**（`A.isArray`）：函数在这个值域里还不是真对象，那些名字只能从**成员
写法**取。四条腿一致而与 node 不同，所以那一行不进五条腿那道门 —— 记在这儿。
用例：`tests/js-exec/cases/36-builtin-ctors.js`。

**生成器搬到 C 了（P2 的第一步）。** 照上面那张草图落的，一次过：

- `js_gen_new` / `js_gen_res` 出 P1_JS_ONLY。前者是一格带 `$stp` / `$gst` 两槽的真对象、
  后者是一格两个键的普通对象；`Generator.prototype` 是真对象，三格原生 next / return / throw
  都落到同一个 `gen_step`（mode 0 / 1 / 2，规则照 prelude 的 `$js_gen_step` 逐条对齐），
  再加一格 `[Symbol.iterator]` 交回自己。realm 的原型表多两格名字（Generator / Iterator）。
- `Generator.prototype` 的原型是 Iterator.prototype —— 那格还是"读成员就报"的代理，
  所以 ES2025 那批 helper（`map` / `take` …）在这条腿上是一句响错，不是静静的 undefined。
- 连带补上的一格：`yield* [1, 2]` 走的是**手写协议**那条路，要数组的 `Symbol.iterator`
  交出一格**真迭代器对象** —— 于是 C 侧多了 `omni_js_src_iter_`（把来源摊成一条 list 再按下标
  喂，`next` 与 `[Symbol.iterator]` 直接坐在它自己身上）。同时 `omni_js_obj_get` 在
  **非真对象**上碰到符号键时改成往它那格 realm 原型问，而不是当场报 —— 数组的
  `Symbol.iterator` 就住在那儿。

`async` / `await` 与异步生成器（`js_gen_awt` / `js_async_run` / `js_agen_new`）还在拒 ——
它们要 Promise 与作业队列先落地。用例：`tests/js-exec/cases/37-generators.js`
（五条腿对 node：next / return / throw、双向 yield、finally 在 return 上、`yield*`、展开、for-of）。

**Promise 与 async / await 搬到 C 了（P2 的第二步）。** 照上面那张草图落的：

- 一格 promise 是三槽真对象（`$st` 0 待定 / 1 兑现 / 2 拒绝、`$val`、`$cbs`），回调表在这条腿上
  是一格 `LT`（每项 `[f, r, child]`）；作业队列是一格静态 `LT` 加一个游标（不 shift，省得搬），
  `js_jobs_run` 把它排空。
- `then` / `catch` / `finally` 是 `Promise.prototype`（真对象）上三格原生，都落到 `react`；
  每个回调都是**带载荷的原生**（这条腿上没有宿主 lambda），所以 sel 又排了一段 18..28：
  resolve / reject / 跟随 thenable 的作业 / schedule 的作业 / async 的 tick 两格 /
  then / catch / finally / finally 的传递与重抛。
- `js_async_run` 的第一段**同步**跑（规范如此），`await` 收尾发 `js_gen_awt`，
  兑现走 mode 0、拒绝走 mode 2 接回状态机。
- 组合器那五格里有四格紧接着也落了（下一段），只剩 `any` 还在拒。

一处**顺手修掉的老 bug**（C 那条腿上的发射期错，clang 直接骂）：`(v) => console.log(v)`
这种"体是一格 void op"的箭头，发出来是 `return omni_js_println(...)` —— 从返回 `omni_dyn` 的
函数里返回 `void`。promise 的回调里满是这种写法，所以这一刀撞上了。现在先当一句发出去、
再 `return omni_dyn_undef()`（JS 那条腿上这式子的值本来就是 undefined）。

用例：`tests/js-exec/cases/38-promise-async.js` —— 量的是**次序**：同步代码先跑完、已经结算的
`then` 也要排队、`resolve` 收到 promise 多花一拍。五条腿逐字节对 node。

**组合器五格搬到 C 了（P2 的第三步）。** `all` / `allSettled` / `race` / `try` / `any` 全落地。
难的地方只有一处：这四格都要**几个回调共享一份可变状态**，而 C 那条腿上没有宿主闭包 ——
所以状态只能显式摊开：

- 共享状态是一格 `LT`：`[p, vals, 计数盒]`（`p` 是要交出去的那格 promise，`vals` 是结果表，
  计数盒是一格单元素 `LT`，当可变的 `int` 用 —— 这条腿上没有装箱的数，`comb_dec_` 就是
  把它减一再读）。
- 每一项自己的回调载荷是另一格 `LT`：`[状态, 下标]`。下标必须逐项带在载荷里，
  不能靠调用次序推 —— 已结算与待定的项混在一张表里时，回调回来的**顺序**和下标无关。
- sel 又排了一段 29..33：all 的兑现、拒绝即结算、兑现即结算（race 用）、
  allSettled 的兑现与拒绝两格（它包的是 `{status, value}` / `{status, reason}` 那格形状）。
- 空数组要**立刻**兑现（不排队等谁），`all` 只认第一个拒绝，`race` 认第一个结算的那个。
- `any` 也落了：兑现那一半直接借 race 的 sel 31（载荷是 `[p]`），拒绝那一半自己一格 sel 34 ——
  倒数到零时要交的是一格 `AggregateError`（`$cls` 链 `["AggregateError", "Error"]`、
  `errors` 按下标排好），不是那条 vals 表。空数组这一格是**立刻拒绝**。
  顺带量出一处**两把尺子本身不一样**的地方：`message` 照规范（与 qjs）是空串，而 node/V8 塞的是
  `"All promises were rejected"` —— 我们跟规范，用例里那一格印 `typeof e.message` 而不是内容。

用例：`tests/js-exec/cases/39-promise-combinators.js`（五条腿对 node：all / 空 all / all 被拒 /
allSettled 的形状 / race / try）。

**一格错只该有一个主人（解释器那两条腿上的老 bug）。** 组合器落地时量出来的：
`Promise.try(() => { throw "oops" }).catch(…)` 在 node / JS / C 三条腿上都印 `try catch oops`，
而 interp 印 `omni: uncaught: oops`、mir **什么都不印**。根因不在 Promise 那一族，在挂起槽的
**所有权**上：解释器与宿主 prelude 是两份槽（ADR-0013 决策 3），回调抛出来时 `makeClosure`
的包装把它往宿主搬一份（`mirrorPendingToHost`）好让宿主那边的循环停下来，可**没有清掉自己
那一份** —— 对 `forEach` 那种"只停下循环、不取走"的 op 是对的（错要继续往上冒到 catch），
对 `$js_promise_try` 这种"取走并且负责了"的 op 就错了：宿主把它变成了一格 reject，
解释器手里那份副本却接着往上冒。

修法是把这条不变式写进边界：op 回来时若我们搬过去过（`hostDirty`）而宿主槽**已经空了**，
就是宿主取走并负责了，解释器这一份跟着放手（`builtin.js` 的 `settle`）。同一条规矩顺带盖住
`$js_prom_schedule`（处理器抛了 → reject 子 promise）与 `$js_gen_step` 的 mode 3。
用例：`tests/js-exec/cases/40-throw-in-callback.js` —— 正面八行（then / catch / finally /
executor / async 的抛与重抛 / 生成器 throw）加反面两行（forEach 里抛必须冒到 catch、
后面的 `map` 还得照跑）。

### 还欠的那几族（C 那条腿）

生成器那一刀说明这个套路是能一次过的，所以把 Promise 那一族也先量清楚记下来。核心只有四个
函数（prelude 的 `$js_prom_new` / `react` / `settle` / `schedule`）加一格队列：

- `prom_new()`：一格以 `Promise.prototype` 为原型的真对象，三格槽 `$st`（0 待定 / 1 兑现 /
  2 拒绝）、`$val`、`$cbs`（回调表；JS 那边是宿主数组，C 这边就是一格 `LT`，每项是
  `[f, r, child]` 三元组）。`prom_is(v)` = 真对象且有 `$st` 槽。
- `react(p, f, r)`：造一格子 promise，登记 `[f, r, child]`；**已经结算的也要排队**、不能当场调
  —— 微任务的次序（先把同步代码跑完）就是靠这一条。
- `settle(p, st, val)`：已结算就不动。`resolve` 收到一格 promise 时**多花一拍**
  （规范的 NewPromiseResolveThenableJob）：先排一个作业，在作业里才去 react ——
  少这一拍两条独立链的交错次序就与 qjs 不同（量出来过）。
- `schedule(p, cb)`：排一个作业，作业里按 `$st` 选 f / r，没有处理器就把状态直接传给 child；
  处理器抛了就 reject child。
- 作业队列：一格静态 `LT`，`js_jobs_run` 把它排空（降级器在 main 末尾补一句）。

C 那边每一格回调都得是**带载荷的原生**（宿主 lambda 在这条腿上不存在），所以要给 sel
再排一段：resolve(p) / reject(p) / 跟随 thenable 的那格作业 / schedule 的那格作业 /
async 的 tick（兑现走 mode 0、拒绝走 mode 2 两格）/ `then` / `catch` / `finally`。
`js_async_run(step)` 的形状：第一段**同步**跑（规范如此，一直跑到第一个 await），
`await` 那一步收尾时发 `js_gen_awt`，把 `$js_await_then(value, tick)` 那一格接上。

### 还欠的那几族（C 那条腿，2026-09-09 这一档）

**先修掉一处挂死（比错答案更坏的那一档）。** `for (const x of nat()) { if (x > 3) break; }`
（`nat` 是无穷生成器）在 qjs 与另外三条腿上印三行就收，C 这条腿**转到超时** —— 因为那边的
`omni_js_iter_open` 就是 `omni_js_iter`：先把上游整个摊成一条 list。生成器搬到 C 之后
真迭代器在那条腿上第一次成了可能，这一格就露了出来。

现在 C 那条腿也有惰性把手：上游是真对象时 `iter_open` 交一格三槽真对象 `[$it, $d, $v]`，
`iter_done` 每轮**恰好**拉一次 `next`（协议里报的错能 catch，接住就当 done），
`iter_cur` 读 `$v`，`iter_close` 在循环出口补一次 `return()`（于是 break 出来也跑得到
生成器的 finally），`iter_rest` 抽到 done。与 prelude 的 `$JsIterH` 一一对应。
用例：`tests/js-exec/cases/41-lazy-iteration.js`。

生成器与 Promise（含五格组合器）都落了之后，C 那条腿上还在拒的只剩这些 op：
`js_agen_new`（异步生成器）、`js_date_new` 与 `js_date_parts`、`js_str_normalize`、
运行期编译（`js_src_eval` / `js_src_fn`），外加一格只在 prelude 内部用的 `js_to_prim`。

**迭代器 helper 也搬到 C 了。** `Iterator.prototype` 在那条腿上从"读成员就报"的代理换成了
**真对象**：`next` 抽象，另外 11 格（`take` / `drop` / `map` / `filter` / `flatMap` /
`toArray` / `forEach` / `reduce` / `some` / `every` / `find`）是原生，`[Symbol.iterator]`
交回自己。惰性的五格交一格 helper 对象回去，状态全摊在槽里 —— 这条腿上没有宿主闭包：
`$k` 种类、`$up` 上游、`$fn` 回调、`$n` 还要几格、`$i` 计数器、`$f` 上游完了没、
`$c` 自己关了没、`$in` flatMap 的内层；`next` / `return` 两格原生（sel 47 / 48）坐在
helper **自己身上**（与 `omni_js_src_iter_` 同一做法，都不可枚举，所以 `Object.keys` 是空的）。
`return` 要把上游**一层层**关下去 —— 少这一格，`fin().map(f).take(2)` 拉完之后生成器的
finally 不会跑（用例里量了）。用例：`tests/js-exec/cases/42-iterator-helpers.js`。

还欠着、但**四条腿一致地响错**的两处：`[1,2,3].values()` / `keys()` / `entries()`
（数组的三格迭代器工厂，每条腿都是 "not a function"），以及 `Iterator.from(x)`
（`Iterator` 这个名字当值用还没有）。

**一处记在别人头上的错（修掉了）。** C 那条腿上 `omni_js_proto_of_tag_` 的兜底给的是
`null`，而 Uint8Array / DataView / TextEncoder 在 realm 上还没有原型 —— 于是
`typeof b.at` 一边照样印 `undefined`、一边把 "cannot read property 'at' of null" 留在挂起槽里，
**下一句** `console.log` 才炸。错的位置比错本身更难查，所以兜底改成 `Object.prototype`：
读不认识的成员就是 `undefined`（与另外三条腿一致）。同时补上 `OMNI_DYN_INT` / `UINT` 两格 ——
它们本来也落到那个兜底上。用例：`tests/js-exec/cases/43-unknown-member-read.js`。

**原型成员表两边同源了（约 50 格的分叉一次收口）。** 把 `JS_MEMBERS` 里 136 组
（接收者标签, 成员名）逐一读成**值**（`typeof [1,2].at` 这种写法）跟 qjs 比，量出来：
C 那条腿（成员表是 emit 期照 `JS_MEMBERS` **生成**的）跟 qjs 一致，而 JS / 解释器三条腿
有 **约 50 格给 `undefined`** —— `at` / `padStart` / `replace` / `substring` / `push` / `pop` /
`entries` / `lastIndexOf` / `codePointAt` … 全都只在**静态成员调用**那条路上有，
prelude 的 `arrP` / `strP` 上手写的是一小半。这既是与 qjs 的缺口，也是**腿之间的分叉**。

修法与 C 同源：prelude 末尾追加一段**生成**的 `$js_pm_set([...])`，`$realm` 建好原型之后
照它挂一遍（`$js_pm_install`）。三个细节是量出来才定的：

- 摆在 **prelude 的末尾**、不摆在降级器里 —— 这份 prelude 有三个用户（整程序、片段、
  以及解释器那条腿 `host/native.js` 用 `new Function` 跑起来的那一份）。先试的是"降级器发一句"，
  结果 JS 与 C 一致了、interp 还给 `undefined`：第三个用户漏了。
- 每行按**原型**挂，所以实现直接叫那格 op（`$js_arr_at`），不经过 `$js_m_*` 那层按标签分派的
  包装 —— 那一层是降级器生成的，prelude 里没有。
- 生成的那一遍先挂，**手写的排在后面**，于是形状特殊的那些（`Object.prototype` 那一族、
  `f.call` / `f.apply`、`Symbol.iterator`、访问器）照旧说了算。

现在四条腿逐格相同，且除 `bytes` 那一族外与 qjs 相同。`bytes`（Uint8Array / DataView）
realm 上还没有原型，四条腿一致地给 `undefined` —— 那是记在这儿的下一格缺口。
用例：`tests/js-exec/cases/44-proto-member-values.js`。

### 顺手扫了一遍常写的面（2026-09-09）

不是为某个新功能，是**扫**：常写的 ES2020..ES2025 面各写一小段，六族一起量 —— 数值与串、
对象与属性、类（静态块 / 私有字段 / getter）、解构与展开（rest、默认值、嵌套默认）、
可选链与逻辑赋值、标签模板与正则（具名组 / matchAll / $n 替换）。结果：
**五条腿逐字节相同，并且与 qjs 也逐字节相同**。钉成
`tests/js-exec/cases/46-es2025-sweep.js`。

那一轮里唯一一处与 qjs 的差是 `"ß".toUpperCase()`（当年是**响错**：整张大小写表还没有）。
下面那一节把它收了，用例里那一行也放回去了。

### 整张 Unicode 大小写表落地了

从前 0x80 以上凡是有大小写映射的码点一律**当场报错**（"要么整张表要么拒掉，半张表只会在别处
再撒一次谎"）。现在整张都在，四条腿同一批数字。

- **一对一**压成"同增量同步长的连续段"，一段是 `start:count:step:delta`：小写 184 段、
  大写 197 段。**一对多**单独一张小表：小写只有 1 格，大写 102 格（`ß -> SS`、`ﬁ -> FI`
  那族连字，以及带 ypogegrammeni 的希腊字母）。连表带解码约 6.2 KB。
- **Final_Sigma**（规范 22.1.3.28 那条**有条件**的特例）：Σ 在词尾小写成 ς。判据要 Cased 与
  Case_Ignorable 两个性质，这两张也是量出来的（151 段 / 464 段）。少这一条
  `"ΣΟΦΟΣ".toLowerCase()` 给 `σοφοσ` —— 两把尺子都给 `σοφος`，那是**静默**的错答案，
  比原来那句响错更坏，所以这一刀必须连它一起落。
- 三张表都是从宿主量的，判据一行：
  `String.fromCodePoint(cp).toLowerCase() !== ch || .toUpperCase() !== ch`；
  Cased / Case_Ignorable 则用 `(X + "Σ").toLowerCase()` 与 `("Α" + X + "Σ").toLowerCase()`
  是否以 ς 收尾来量 —— 拿宿主自己当尺子，不去抄 UCD 文件。
- **ASCII 那条快路留着**：整串都是 ASCII 时照旧等长一次扫完（编译器自己只用 ASCII，这一族在
  热路径上）。非 ASCII 那条路才摊码点表、一格一格拼 —— `ß -> SS` 会让串变长，等长那条路
  接不住。C 那侧因此没有动 `omni_s16_upper`（那是 Omni 语言自己的语义），另写了一格
  `js_case_map`。

对得有多齐：把 0x80..0x10FFFF 里有映射的 **2985** 个码点逐个印小写与大写、再加 10 种
Final_Sigma 上下文，**四条腿逐字节等于 node**。用例：
`tests/js-exec/cases/47-unicode-case.js`。

### 量清楚了：Error 那一族当值用，卡在"C 那侧异常对象还是 dict"

`const E = Error` / `new T("x")` / `er.constructor === TypeError` 在四条腿上都是编译期
`unresolved identifier`（响的）。补上"名字当值用"本身不难 —— 把 `ERROR_CTORS` 那八个名字也
走 `js_realm_ctor` 那条路，`$js_mk_ctors` 里各加一格落到 `js_err_new`（`$cls` 链的头按名字，
`AggregateError` 的实参次序是 `(errors, message, opts)`）。

**但只加这一半会把一处响错换成静默的错答案**：`mk()` 会往原型上写一格 `constructor`，
八个构造器共用 `errP` 的话最后一个写的赢 —— `new TypeError("t").constructor` 会给
`Error`（node / qjs 给 `TypeError`）。所以得连"每族一格自己的原型（原型的原型是 `errP`）"
一起落，而且 `js_err_new` 要按 `cls[0]` 挑那一格原型。

真正的拦路石在 C 那侧：那边的异常对象是一格 **dict**（`omni_js_obj_new()`），压根没有原型链 ——
`er.constructor` 会走到 `Object.prototype` 上去。要让 `constructor` 在两条腿上说同一句话，
得先把 C 那侧的异常对象换成**真对象**（`OMNI_DYN_OBJ` + 以对应原型为 proto）。那一改的波及面是
所有 throw / catch（`omni_js_is_a` 现在的判据是 `tag != OMNI_DYN_DICT` 就 false，
JSON / keys 的形状也跟着变），所以它自己就是一刀，不该塞在这一刀里。

顺着这条线又量出**一处静默的错答案**（四条腿一致，所以差分测试抓不到，只能对尺子）：

```
new Error("x").constructor.name   // node / qjs: "Error"    四条腿: "Object"
new TypeError("t").constructor.name  // node / qjs: "TypeError"  四条腿: "Object"
```

原因同上 —— 异常对象的原型是 `errP`，而 `errP` 身上没有自己的 `constructor`，链走到
`Object.prototype` 就答了那一格。这说明"每族一格自己的原型"不只是为了让名字能当值用，
它本身就在修一处已经存在的错答案，所以这一刀的分量比原先记的要重。

在那之前保持现状：八个名字**当值用**是响错，`new Error(...)` / `catch` / `instanceof`
（走 `$cls` 链）/ `name` / `String(e)` / `Object.keys` / `JSON.stringify` 照旧全对，
只有 `constructor` 那一格是错的（且四条腿一致）。

### 试过并**回退**：给 bytes 那一族补一格 realm 原型

`typeof b.at` 在四条腿上一致地给 `undefined`，而 node / qjs 给函数 —— 因为 Uint8Array /
DataView 在 realm 上没有原型。照 Array / String 那条路补一格 `Uint8Array.prototype`
（JS 侧 `bufP` + `$js_proto_of_prim` 的 bytes 支，C 侧 realm 表 14 -> 15 格 +
`proto_of_tag_` 的 `OMNI_DYN_BYTES` 支，两个 `protoMembers` 生成器的 TAG_PROTO
加一行 `bytes -> Uint8Array`）落下去之后**四条腿一致、也确实修好了那 4 格**
（`at` / `indexOf` / `includes` / `fill`）。

可是**净账是亏的**：这个值域里 Uint8Array 与 DataView 是**同一个 `bytes` 标签**，于是那 18 格
DataView 专属的 `getUint8` / `setInt32` … 也跟着挂到了 `Uint8Array.prototype` 上 ——
`typeof new Uint8Array(2).getUint8` 从 `undefined`（与 qjs 一致）变成了 `function`。
修 4 格、坏 18 格，所以整个回退了。

真要收这一格，得先让两者在**值的层面**分得开（bytes 值上加一格"是 DataView 吗"的判别，
或者干脆两个标签）—— 那不是原型表这一层能解决的。在那之前这 4 格差留着，
四条腿一致、且是 `undefined` 而不是半对的函数。

### `values()` / `keys()` / `entries()` 交真迭代器了

这三格现在交的是**一条 list**（`js_abi.js` 里 `js_arr_keys` 那段注写着"等 P2 那条线"——
P2 现在落了）。可观测的差：`[...a.keys()]` 与 `for (const i of a.keys())` 都对，
而 `typeof a.values().next` 在四条腿上是 `undefined`、qjs / node 是 `function`；
`[1,2,3].values().map(f)` 那批 ES2025 helper 也就接不上（四条腿一致地 "not a function"）。

落法（四处，缺一处就会有腿分叉或者打转）：

- **两用的那两格先拆开**：`js_set_items` / `js_map_entries` 既是
  `Set.prototype.values` / `Map.prototype.entries`，又是 `omni_js_iter` / `$js_iter`
  把 Set / Map 摊平的那一步。摊平那一半留成内部助手（`$js_map_pairs` / `$js_set_list`、
  C 那侧 `omni_js_map_pairs_` / `omni_js_set_list_`），公开那格 op 再包一层迭代器。
  不拆开的话摊平那条路收到一格真对象、`omni_js_iter` 当场打转。
- **构造器与集合运算改叫内部助手**：`new Map(x)` / `new Set(x)` / 七格集合运算走的是"摊平"，
  不是"迭代器"。顺手把 `$js_map_of_pairs` 的非 Map 分支从 `$js_arr_of` 换成 `$js_iter` ——
  `new Map(m.entries())` 现在送进来的就是一格真迭代器（规范 24.1.1.1 本来就收任何可迭代物）。
- **C 那侧 `omni_js_src_iter_` 的原型换成 `Iterator.prototype`**（原来是 `Object.prototype`）。
  少这一条，`a.values().map(f)` 在 JS 那条腿上有、在 C 那条腿上是 "not a function" ——
  量出来的第一处分叉。
- **段顺序**：C 那侧 `omni_js_arr_*` 住在 ARR 段而 `omni_js_src_iter_` 住在 OBJ 段（在它后面），
  所以 ARR 里补一句前向声明 —— 与 STR_ARR 借 `omni_js_err_new` 同一个做法。

代价量过：`omni emit-js src/cli.js` 从 1.77s 到 1.87s（约 +5%）。编译器自己有 88 处
`.keys()` / `.values()` / `.entries()`，每一格元素多一次 `next()` 调用加一格 `{value, done}`
分配 —— 规范语义本来就要花这个钱，收下。

OIR 那道闸门里有 9 处用例是按老契约写的（op 一层直接把结果当 list 去 join / 取下标），
一律改成先过一遍 `js_iter`——参照那一侧写的本来就是 `[...m.keys()]`，同一件事。
用例：`tests/js-exec/cases/45-container-iterators.js`。

下面这张生成器的草图已经照着落完了，留档免得下一刀再翻一遍 prelude：

- `js_gen_new(step)`：一格真对象，原型是 `Generator.prototype`，两格槽 `$stp`（状态机那个
  闭包）与 `$gst`（0 没开始 / 1 跑过 / 2 完了）。C 侧就是 `omni_js_new_bare_` + 两次
  `def_data_`。
- `js_gen_res(v, done)`：一格普通对象（这条腿上是 dict）两个键 `value` / `done`。最便宜的一格。
- `Generator.prototype`：**真对象**（不是代理），三格原生 next / return / throw，都落到同一个
  `gen_step(g, v, mode)`（mode 0/1/2），再加一格 `[Symbol.iterator]` 交回自己。
  `gen_step` 的规则照 prelude 的 `$js_gen_step` 逐条抄：没开始就 return/throw 或已经完了
  **不进体**；体里抛出来的东西落在挂起槽里，机器里还有活着的 catch 就用 mode 3 送回去
  （genfn.js 的 tryCatch），没有就让它继续往上冒。
- realm 的原型表要多两格名字（`Generator` / `Iterator`）。ES2025 那批 helper（`map` / `take`
  …）住在 `Iterator.prototype` 上，C 这条腿上还没有 —— 让 `Generator.prototype` 的原型是
  那格"读成员就报"的代理，于是 `gen.map(f)` 是一句响错而不是静静的 undefined。
- async 那一半（`js_async_run` / `js_agen_new`）要 Promise 与作业队列先落地，排在后面。

### 顺手量的一轮性能（自举那条链上的真负载）

尺子：`omni emit-js src/cli.js`（编译器编自己）。**去掉紧挨着的第二次 pending 检查**是这一轮
唯一量到收益的一处：13.7MB 的产物里 57487 次检查有 7781 次是冗余的（`guard()` 已经在 sink 里
检查过一次，而 `mayThrow` 看整棵子树、于是语句末尾又补一次）。改完：

- 原生腿 33.5s -> 31.2s（-7%），产物 13.72MB -> 13.23MB（-3.6%）、C 25.93MB -> 25.36MB
- 四道闸门与自举九项都不变（语义上第二次检查恒为假）

**两处试过、量不出收益、已经退回**（记在这儿免得再来一趟）：引用值的 Map/Set 键从
`omni_str_fmt("o%p")` 换成"标签 + 指针八个原始字节"（省掉 snprintf，31.15s vs 31.23s = 噪声）；
摇树那趟的 `Object.keys(v)` + `v[k]` 换成 `Object.values(v)`（32.0s，产物逐字节相同）。

**剩下的差距是结构性的，不是某一个热点**：同一份 `cli.js`，node 直接跑 1.5s、两条降级腿
31s（原生）/ 也是同一档（生成的 JS）。微基准（200 万次循环）说明了原因 ——
字面量键的属性读 node 3ms、生成的 JS 254ms、C 390ms；`Set<对象>` 的 has/add
node 21ms、生成的 JS 185ms、C 143ms。也就是说 **C 后端并不比生成的 JS 慢多少（1.4 倍上下），
慢的是"每个对象都是一张 dict、每次取字段都是一次哈希查找"这套降级口径**（V8 那边是隐藏类 +
内联缓存）。字面量键那一格早就不再做 UTF-8 转换了（`omni_js_obj_getk` 直接收 UTF-8），
所以再往下要的是形状（hidden class）+ 内联缓存 —— 那是 ADR-0014 "天花板"那一节的事，
得单独立一刀，不在这条线上顺手做。

**代理（Proxy）在 C 那条腿上也有了。** `px_t` / `px_h` 两格挂在真对象的载荷上，
`get` / `set` / `has` / `deleteProperty` / `ownKeys` 五个入口各多问一句陷阱，没陷阱就落到
目标上 —— 与 prelude 的 `$js_px_trap` 那五处逐条对齐。代理与普通对象是**同一种值**
（`typeof` 都给 `"object"`）。

**可调用的代理**（`new Proxy(fn, …)`）当场报：它得是一格**闭包记录**（`typeof` 要给
`"function"`、`p()` 要走 apply 陷阱），而闭包记录只有生成的代码造得出来。给一格不能调的
对象就是悄悄的错答案。
用例：`tests/js262/cases/proxy-on-c.js`（逐字节对 qjs，四条腿）。

**下一步（realm）的形状，先记在这儿。** 剩下的 26 格拒绝里压着最多东西的是 realm
（`js_realm_proto` / `js_realm_ctor` / `js_ctor_get` / `js_global_this`）：`Object.prototype.
toString.call(x)`、`[].map` 摘下来当值、`x instanceof Array`、Date 对象（`js_date_new` 要
Date.prototype）都在它后面。

两件事已经不是障碍：真对象有了（原型可以是一格真对象），而 **C 侧造得出函数值** ——
闭包记录就是 `{ omni_fnptr fp; …捕获的 }`，`omni_js_wrap_s`（`omni_js_arr.h`）已经是这个
形状的现成例子，所以再加一种 `{ fp, sel }` 的"原生函数"记录就能把 C 函数包成 JS 函数值。

真正要小心的是**完整性**：原型上少一个名字不是拒绝，而是一格 `undefined` —— 悄悄的错答案。
所以 realm 不该手写，而该**照成员表生成**：`hir/js_abi.js` 的 `JS_METHODS` / `JS_PROPS`
本来就是"这条腿上每个标签实现了哪些成员"的唯一真相，发射器已经照它生成了成员派发器
（`backend-c/emit.js` 的 `memberDispatch`）。让它再生成一遍"每格原型上按名字挂一个原生，
原生转手调同一个派发器"，原型就**天生**与实现一样全，也不会有第二份语义。

拆开来看，realm 其实是**两件事**，可以分两步落：

1. **只要同一性**的那一半：`x instanceof Array` 只问"Array.prototype 在不在 x 的链上"，
   压根不读原型上的成员。所以给每个内建标签一格**规范的空原型对象**就够 —— 便宜、诚实。
   代价是 `js_instanceof_p` 要能把容器标签映到它那格原型上（现在它只从真对象的 `pr` 起步，
   给 list 一律 false —— 那在 realm 落地之后就成了悄悄的错答案，两件事必须同一刀改）。
2. **要读成员**的那一半：`Object.prototype.toString.call(x)`、`[].map` 摘下来当值。
   `Object.prototype` 那一格的成员表是**短而封闭**的（toString / valueOf / hasOwnProperty /
   isPrototypeOf / propertyIsEnumerable / toLocaleString），手写也能写全；别的原型（Array /
   String…）不写全就会静静地给 undefined，所以那几格在生成器补上之前应当**读一下就报**——
   现成的办法是让它们是一格带 `get` 陷阱的代理（代理已经有了），陷阱里当场报。

还有第二处**必须同一刀改**的：C 侧的 `omni_js_obj_new_p(undefined)` 现在给的是 **null 原型**，
而 prelude 那一格给的是 `Object.prototype`。现在看不出来（realm 整格拒），可 realm 一落地，
类的实例（降级器发的正是 `js_obj_new_p(undefined)`）的链就走不到 `Object.prototype`，
`p instanceof Object` 会静静地给 `false` —— 那一句在 JS 腿与两把尺子上都是 `true`（量过）。
代码里那一行上面已经写了这条注。

两步都要先有一样东西：**C 侧的原生函数值**。闭包记录是 `{ omni_fnptr fp; …捕获的 }`，
所以一格 `{ fp, sel }` 的记录 + 一个按 `sel` 分派的入口就够了 —— `omni_js_wrap_s` 是现成的
形状范例。

**迭代协议在 C 那条腿上通了：`[Symbol.iterator]() {…}` 那种可迭代对象现在能展开、能
`for-of`、能解构、能进 `Array.from` / `new Set` / `new Map`。** 真对象有槽、符号键按同一性
发键，所以 `js_iter_proto`（取 `Symbol.iterator` 再调）与 `js_iter_next`（取 `next` 再调、
结果必须是对象）两格都成立 —— 两处报的都是**能 catch** 的 TypeError（规范 7.4.2 / 7.4.4）。
段里多了一格共用的 `omni_js_iter_o_`（走一遍协议、摊成 list），`omni_js_iter` 的真对象支、
`Array.from`、`new Set(x)`、`new Map(x)` 四处都指向它 —— 少了这一步，那几格会撞在
`dynamic value is object, expected list` 上（量出来的）。`Reflect.defineProperty` 跟着落地。

**这条腿上的可迭代对象是"摊开"的**（协议走到底、攒成一条 list），而 JS 那条腿是惰性的：
有限、无副作用的迭代器两边逐格相同，无限迭代器（生成器）在 C 上本来就还在 P1-c 里。
用例：`tests/js262/cases/iter-protocol-on-c.js`（逐字节对 qjs，四条腿）。

**`Object.create(proto, descs)` 与 `Object.defineProperties` 也落地了。** 槽表本来就带
`writable` / `enumerable` / `configurable` 三个位，所以批量描述符只是把 `js_obj_def`
走一圈。落在**普通对象字面量**上的 `defineProperty` 照旧当场报 —— 那一格在这条腿上是
一格 dict，没有属性位，收下就是悄悄的错答案（要 `Object.create` 造的那种真对象）。
用例：`tests/js262/cases/obj-create-descs.js`（逐字节对 qjs，四条腿）。

**局部类与"普通函数当构造器"也通了（第十一步）。** 局部类是一格**局部量**，所以
`new P()` 走的是通用那条 `js_fn_construct` —— 右边是一格**类对象**而不是函数值，
构造要走它身上的 `prototype` 与 `Symbol.omni.classInit` 那格闭包（与 prelude 的
`$js_fn_construct` 逐支对齐）。普通函数那一支的 `prototype` 住在一张按同一性索引的旁表上
（函数不是真对象，与 prelude 的 `$FNPROTO` 对应），`f.prototype` 的读也接到那儿 ——
JS 那条腿上它是 `Function.prototype` 身上的一格访问器，同一件事的两种写法。

**于是 `tests/js-exec` 的 29 份用例现在全部跑五条腿：C 那条腿一个都不跳了。**
用例：`tests/js262/cases/class-on-c.js` / `local-class-on-c.js`（逐字节对 qjs）与
`tests/js-exec/cases/29-class-extends.js`（五条腿）。

**真对象在 C 那条腿上落地了（P1-c 的第十步）：`OMNI_DYN_OBJ` + 有序槽表 + 原型链。**
载荷是 `omni_js_objv { pr, ps, ex }`（原型、槽表、可扩展），一格槽是一条 **8 格的 list**
`[v, a, g, s, w, e, c, key]` —— 用 list 而不是新开一种 C 结构：那一段里 list 现成，
而 arena 不回收，少一种要管的东西。落地的 op：`js_obj_new_p` / `js_obj_create` /
`js_getp` / `js_setp` / `js_obj_proto_get` / `js_obj_proto_set` / `js_reflect_set` /
`js_reflect_proto_set` / `js_reflect_prevent_ext`，外加 `Object.keys` / `values` /
`entries` / `for-in` / `in` / `hasOwn` / `delete` / 描述符 / JSON / `typeof` /
`String()` / freeze-seal 那六格在真对象上的分支。

**两种表示是并存的，这一条是有意的：** 这条腿上"普通对象"照旧是 dict（对象字面量、
`JSON.parse` 摊出来的那些都是），真对象只在**要原型**或**要属性位**的地方出现。
dict 那条路是热路径（取字段最常见），不该为原型链付账。代价写在明处：**原型链的末端
常常是一格 dict**（`Object.create({…})`、类的原型都是），所以取属性、`in`、`for-in`
都要在 OBJ 链走完之后接着在那一格上按容器找一次 —— 少了这一步，`Object.create(p).m()`
会报 "not a function"（量出来的）。

三档锁在真对象上走**它自己的位**（`ex` 与每格槽的 `w`/`c`），不走容器那三张旁表：
`freeze` = 不可扩展 + 每格不可写不可配置，`seal` = 不可扩展 + 每格不可配置，判据反着算。
`String(真对象)` 是 `[object Object]`；自带 `toString` 的那一格**当场报** —— 调它要现拼
一条实参 list，而 list 的具体类型只在生成的那个翻译单元里，`omni_js.c` 造不出来。
`Object.defineProperty` 与 `Object.create(proto, descs)` 也照旧拒（描述符那一族）。
用例：`tests/js262/cases/obj-create-proto.js`（逐字节对 qjs）与
`tests/js-exec/cases/28-obj-create-proto.js`（五条腿）。

**`Date.UTC` 与 `Date.parse` 现在五条腿都有（`src/runtime/omni_js_date.c`）。** Date 这一族
里只有这两格**只算数** —— 它们交出一个毫秒数，与真对象无关。`new Date(…)` 造的是真对象
（prelude 里是 `$JSObj` + `dateP` 原型 + `$ms` 槽），`new Date(y, mo, d)` 还要**本地时区**，
那两格照旧拒。

日期算术不碰 libc 的 `time` / `mktime`：那一族要么带时区、要么在 32 位 `time_t` 上溢出。
用的是 days-from-civil 的闭式解（公元前后都对），全程 int64 + double，所以扩展年
（`±YYYYYY`）、负毫秒、月份溢出（`Date.UTC(2020, 12)` 是下一年的一月）、0..99 映到 19xx
（MakeFullYear）这些边角都是算出来的，不是碰巧对。

`Date.parse` 只认规范 21.4.3.2 那个格式（`YYYY[-MM[-DD]][THH:mm[:ss[.sss]][Z|±HH:mm]]`）。
宿主那条腿借的是 `Date.parse` 本身，它还认 RFC 2822 那一族，而 **node 与 qjs 在那些写法上
互相就不一致**。所以这条腿上：认得的照算，认不得的（以及带了时间却没写时区 —— 那是本地
时间）**当场报**，不给 NaN —— NaN 会让两条腿静静地分叉（一边算出数、一边算出 NaN）。
用例：`tests/js262/cases/date-utc-parse.js`（逐字节对 qjs）与
`tests/js-exec/cases/27-date-utc-parse.js`（五条腿 —— 这一族两把尺子完全一致，量过）。

**`Object.hasOwn` / `in` / `Reflect.has` / `Reflect.deleteProperty` 现在五条腿都有。**
这条腿上"普通对象"是 dict、数组是一段 items —— 没有原型链，所以"自有键"就是全部键，
三格都落回容器那一套。`13-static-calls.js` 因此**不再跳过 C 那条腿**（五条腿的跳过名单
从 4 个缩到 3 个：`07-classes` / `08-throw-try` / `09-modules`）。

两格顺带修掉的错：串上的下标与 `length` 也是**自有**属性（规范 10.4.3），而
`Object.hasOwn("ab", 0)` 在两条 node 腿上静静地给 `false`（两把尺子都给 `true`）；
C 那条腿上删一格不存在的名字给 `false`，而规范说 `true`（"删不掉"才是 `false`）。
用例：`tests/js262/cases/obj-has-own.js`（逐字节对 qjs，四条腿）与 `03-array-object.js`
末尾那一段（五条腿）。

**属性描述符（`getOwnPropertyDescriptor(s)` / `getOwnPropertyNames`）现在五条腿都有，
而且把三档锁算进去了。** 这条腿上"普通对象"是 dict、数组是一段 items —— 都**没有属性位**
（没有访问器、没有不可写／不可枚举的自有槽），所以描述符只能是照实合成的那一格：数据属性，
三个位按值域算。三档锁是唯一能把位改掉的东西（冻住 → 不可写、不可配置；封住 → 不可配置），
数组与字符串则照规范 10.4.2.1（下标可写／可枚举／可配置，字符串上只读；`length` 可写但
不可枚举、不可配置）。

顺带修掉一格**悄悄的错答案**：`Object.freeze([1,2])` 之后，JS 那条腿的描述符还说
`writable: true` —— 而写进去确实被拦下了。两把尺子都给 `false`。

`Object.defineProperty`（`js_obj_def`）**照旧拒**：`{ value: 1 }` 在规范里造的是不可枚举、
不可写、不可配置的属性，dict 表达不出来 —— 收下就是悄悄的错答案，所以它跟着真对象那一族。
用例：`tests/js262/cases/obj-descriptor.js`（逐字节对 qjs，四条腿）与
`25-freeze-container.js` 末尾那一段（五条腿）。

**`matchAll` 现在五条腿都有。** C 那侧的 `exec` 本来就把 `index` / `input` / `groups`
挂在结果 list 的旁表（xprops）上，所以差的只是"惰性迭代器"那一层 —— 而 JS 那条腿上
`$js_re_match_all` 交的是一格真对象（带 `next` 的迭代器）。C 这条腿交的是一条**现摊好的
list**：`for-of` 与展开逐格相同（matchAll 有限、无副作用，摊开与惰性看不出分别），
而手写 `it.next()` 在那儿取不到 —— 那是一句响错，不是悄悄的答案。`js_re_flags_g`
（"这一格的旗标"）跟着落地，它就是读 RE 载荷里的 `flags`。

顺带对齐一句消息：不带 `g` 的 `matchAll` 照规范 22.1.3.14 第 3 步 b 抛能 catch 的
TypeError，qjs 那句话是 `regexp must have the 'g' flag`，我们从前自己写了一句
`matchAll must be called with a global RegExp`（两条腿都改了）。
用例：`tests/js262/cases/re-match-all.js`（逐字节对 qjs，四条腿）与
`18-regexp-groups.js` 末尾那一段（五条腿）。

**`Object.fromEntries` 与 `Object.groupBy` 现在五条腿都有。** 两条都不需要真对象：
`fromEntries` 摊出来的是一格普通对象，`groupBy` 摊出来的按规范是 null 原型的对象 ——
而这条腿上"普通对象"就是 dict，原型那一格（`Object.getPrototypeOf`）本来就还在
`P1_JS_ONLY` 里、问不着。可观察的那几样（取键、`Object.keys`、JSON、分组的原顺序）
逐格相同，所以它们不该跟着真对象那一族一起拒。

一处量出来的坑：键要**自己**过一遍 ToPropertyKey。`Object.fromEntries([[true,"b"]])` 的
键是 `"true"`，而 C 侧成员派发那条路上的 `omni_js_prop_k` 只把数转串，别的标签撞在
`bool is not a string` 上 —— 那句断言是"降级发错了"的固定签名，不该被这一族正常写法碰上。
用例：`tests/js262/cases/obj-entries-group.js`（逐字节对 qjs，四条腿）与
`03-array-object.js` 末尾那一段（五条腿）。

**`null.x` 从前是硬错，现在是能 catch 的 TypeError。** 规范 7.3.2 的 GetV 与 7.3.4 的
SetV 都先 ToObject，所以 `null` / `undefined` 上取属性、写属性一律是 TypeError ——
而我们四条腿上它是 `$rt_error` / `omni_errorf`：`try { null.x } catch {}` 拦不住，
整个进程当场没了。这是最常撞上的一格（`e instanceof TypeError` 那种写法就是为它写的）。

改了五处：`$js_prim_get`、`$js_obj_set`、`$js_idx_get` 与 `$js_idx_set` 的兜底
（prelude），加上 C 那侧同名的四条（`omni_js_obj_getk` / `omni_js_obj_setk` /
`omni_js_idx_get` / `omni_js_idx_set`，消息由新的 `omni_js_nullish_err_` 拼）。消息照
**qjs**：`cannot read property 'x' of null`；算出来的键那条路 qjs 不把键印进消息
（`null[0]` 是 `cannot read property of null`），也照它走。node 那边是另一句话
（`Cannot read properties of null (reading 'x')`），所以五条腿那份用例只量"抛没抛、
是哪一族"。

还有两处连带的：

- `js_obj_get` 与 `js_idx_get` 现在标了 `throws`。取属性会抛了，不标的话那格错要等到
  下一个哨卡才被看见，中间几句照跑 —— 解释器上量出来的样子是 catch 里的 `console.log`
  整句不见了。读比写热，这一格哨卡有代价，可"错落在下一句"是悄悄的错答案。
- `undefined.f()` 是"取属性 + 当函数调"两步，而一句里嵌着的两个 op 中间没有哨卡，
  于是第二步的 `not a function` 会盖掉第一步那句真话。三处 `asFn`（prelude、C 的
  `omni_js_call`、解释器的 `invoke`）现在都先问一句"已经有错在等着了吗"。解释器那格
  还要多做一件事：它的待决槽与 prelude 的是**两份**（有意的，见 ADR-0016），所以
  `invoke` 在调一个会抛的 op 之前，先把手里那格错搬给宿主 —— 不搬宿主就问不到。

用例：`tests/js262/cases/nullish-member.js`（逐字节对 qjs，四条腿）与
`tests/js-exec/cases/26-nullish-member.js`（五条腿，只量族与流程）。

**`String(数组)` / `String(对象)` 在 C 那条腿上从前是硬错。** `String([1,2,"x"])`、
`"" + a`、`` `${a}` `` 三条路都落到运行时的 `to_s16` 上，而那儿的 `default:` 报的是
`cannot convert list to string` —— 三条腿给 `1,2,x`、C 那条当场死。规范 23.1.3.36 说
`Array.prototype.toString` 就是 `join(",")`（`null` / `undefined` 那格写成空串、嵌套的
数组递归下去），普通对象是 `[object Object]`，异常对象是 `Name: message`
（20.5.3.4，message 空时只剩 `Name`）—— 两把尺子在这几格上一致，所以照它走。

难处在**位置**：`to_s16` 住在 `src/runtime/omni_js.c`（一份普通的 `.c`），而 list 与 dict
的具体类型只在**生成的那个翻译单元**里（容器模板摊在宏段里）。所以 `omni.h` 里加了两个
**只读的布局视图**（`omni_js_list_view` / `omni_js_dict_view`），照 `OMNI_LIST_BODY` /
`OMNI_DICT_BODY` 的字段次序原样复述一遍 —— 宏段与生成代码本来就到处直接写
`((LT)v.u.ref)->len`，这儿只是把同一份布局搬到普通 `.c` 里，改模板要同时改这两个视图。

两处刻意的边界：自引用的数组（`a.push(a)` 后 `String(a)`）在两把尺子上都是**栈溢出**，
我们数到 128 层就当场报，不让宿主自己崩；`{ toString() { … } }` 这种自带 `toString` 的
对象要**调**回调，而调回调得现拼一条实参 list（造不出来），所以那一格当场报而不是给
`[object Object]` —— 悄悄的错答案比拒绝坏。
用例：`tests/js262/cases/str-of-container.js`（逐字节对 qjs）与 `03-array-object.js`
末尾那一段（五条腿）。

**`console.log(数组)` 仍然不追检视格式**（`[ 1, 2 ]` 那种）：两把尺子自己就不一致
（node 印 `[ 'a' ]`、qjs 印 `[ "a" ]`，嵌套深了 qjs 还截成 `[Object]`），这一条是老决定，
见下面"口径"那一节。C 那条腿上 `console.log(o)` 于是印 `String(o)` 的结果 —— 与 JS 腿
一致，这次不再是硬错。

**`js_is_obj` 与 `js_obj_to_string` 也有 C 孪生了（`omni_js.c`），但先说清它们现在够不着。**
两条都是照标签直说：前者是规范的 "Type(v) is Object"（不是那七格原始值就算），后者是
`Object.prototype.toString` 的结果串 —— 这条腿上没有真对象，所以既没有 `Symbol.toStringTag`
也没有原型链，一格标签对一句话。落地它们是给真对象那一步铺路：**今天 C 上的用户代码到不了
这两格**，因为唯一发 `js_is_obj` 的地方是类的 `new`（要 `js_obj_new_p`）、唯一发
`js_obj_to_string` 的地方是 `Object.prototype`（要 `js_realm_proto`），两个前置都还在
`P1_JS_ONLY` 里，所以先撞上那两条拒绝。这一条**没有专门的用例**，只有"C 运行期照旧编得过"
（`tests/oir`）—— 记在这里是因为"有孪生但够不着"和"两条腿都有"不是一回事。

**构造器 `return` 一格数组／Map／函数，从前会悄悄变成一格空对象。** 规范 10.2.2 第 13 步：
返回值是**对象**就是 `new` 的结果，是原始值才还给新造的实例。判据是 "Type(v) is Object" ——
这个值域里数组、Map、Set、函数、正则都算。prelude 里问的却是 `$js_isobj`（"是一格 `$JSObj`"），
于是 `function Wrap(v) { return [v, v]; }` 里 `new Wrap(3)` 给出一格空对象，`w.length` 是
`undefined`（qjs 给 `[3, 3]`）—— 最坏的那一档：不报错，答案不对。三处改成 `$js_is_object`：
普通函数当构造器那条、类的 `$init` 返回值那条、代理 `construct` 陷阱的结果检查那条。
用例：`tests/js262/cases/new-return-object.js`（逐字节对 qjs，覆盖八种返回值 × 静态与运行期
两条构造路径）。

**传统八进制转义（`"\101"`）现在当场报。** 从前它落到词法那条"任何其它字符就是它自己"的兜底上，
`"\101"` 于是是三个字符 `101` —— **每一把尺子都不是这个答案**（非严格脚本里是 `"A"`，
模块里是 SyntaxError）。悄悄给出第三种答案是最坏的一档。模块本来就是严格模式，所以照规范
（12.9.4.1：LegacyOctalEscapeSequence 只在 Annex B 的非严格脚本里）整族禁掉，
并把 `\x41` / `\u0041` 两种写法写在消息里。`\8` / `\9` 不动 —— 那两格我们与两把尺子一致。
用例：`tests/js262/cases/local-class.js`（逐字节对 qjs）与 `07-classes.js` 末尾那一段（四条腿，
C 那条本来就跳过这一格）。

**`String.prototype.normalize` 补上了，而且 C 那条腿的拒绝改成了一行话。** 从前 `normalize`
整格不在成员表里，`"a\u0301".normalize()` 落到"取属性再当函数调"的兜底上，运行期报
`undefined is not a function` —— 那句话既没说是哪个成员，也没说是"这一格还没有"。
现在它是一格 op：形态名缺席是 `NFC`，不在四个里是能 catch 的 RangeError（消息跟 qjs 的
`bad normalization form`）。NFC/NFD 那套要 Unicode 的分解与组合表，C 侧没有，所以这一格进
**P1_JS_ONLY** —— 与其两条腿悄悄不一样，不如让 C 整格拒。

顺着这一格修了两处**拒绝的质量**（"响"不等于"看得懂"）：

- `noC` 现在往**成员**上传播：一个成员的每条分支都只有 JS 侧实现时，C 后端连那个派发器都不生成
  （从前照生成，里面调一句不存在的 `omni_js_str_normalize`，于是报错是 clang 的
  `call to undeclared function`，指着生成出来的 `.c` 文件的某一行）。分支混着的那种在发射期
  分不出接收者标签，所以不传播。
- 那句拒绝从裸 `Error` 换成 `OmniError`：CLI 只印 message 一行。从前印出来是一整片 node 栈 ——
  响是响了，可看着像我们自己崩了，而**崩成宿主错误是最坏的一档**。
  `Object.freeze(数组)` 在 C 上那句拒绝一起变干净了。

用例：`tests/js262/cases/str-normalize.js`（含形态名报错那两格，逐字节对 qjs）。

**调用抛出来的错也落在调用那一句上，而且"不是函数"能 catch 了。** 两格都在同一条路上：

- `js_call_this` / `js_call_fn` 从前不带 `throws`，于是**方法调用**也是"报了不马上查"：
  量出来的是 `try { o.m(); log.push("after") } catch …` 里 after 先印了、错到下一句才被接住
  （qjs 直接进 catch）。这两格现在带 `throws`。注意这不是"类的方法"那一格 —— 表外接收者
  （普通对象、原型上的方法）走的就是这两条 op。
- 取到的那一格**不是函数**（`o.foo()` 里 foo 不存在，最常见的一格）：规范里是能 catch 的
  TypeError，从前是硬错，整个程序当场没了，`try/catch` 拦不住。现在放一格待决错误再交出一个
  什么都不做的函数值：调用点照常调它一次（拿到 undefined），紧跟的那句 pending 检查把错送出去。
  两条腿都改了 —— C 侧的检查放在 `omni_js_call`（ARR 段，那儿 `omni_js_type_err_c` 已经先声明过），
  而不是 `omni.h` 的 `omni_js_as_fn`：那个头里造不出异常对象（`$cls` 是一条 list）。
  消息跟 qjs 的 `not a function`。

**两把尺子在消息文本上不一致的那几格**：`not a function`（node 是 `oo.zork is not a function`）、
`invalid array length`（node 首字母大写）。我们跟 **qjs**（js262 那道闸要求逐字节一致），
所以五腿用例里那几格只量类名或"抛没抛"，不量文本。

用例：`tests/js262/cases/call-throw-now.js`（时机 + 五种接收者，逐字节对 qjs）与
`08-throw-try.js` 末尾那一段（四条腿）。

顺着量出来的一格 C 腿差异，也把话说清楚了：**原始值身上表外的成员**（`"s".zork`、
`if (str.normalize)` 这种探测写法）在 JS / 解释器 / qjs 上都是 `undefined`（走 realm 的原型链），
而 realm 是 P1_JS_ONLY —— C 侧一格原型表都没有，从前掉进 `omni_js_dict_of` 的断言，报的是
`dynamic value is str16, expected dict`：响是响了，可像是我们内部炸了。现在照实说是哪个名字、
哪条腿（`backend-c: cannot read 'zork' of a str16 — …ADR-0020 P1-c…`）。
**刻意不给 undefined**：那会把"原型上确实有的名字"悄悄答成没有，而悄悄的错答案比拒绝坏。

**下标那一族的实参照规范 ToIntegerOrInfinity**（规范 7.1.5：先 ToNumber，NaN 当 0，其余截尾）。
从前是严格的标签检查，`"abcd".indexOf("c", "1")`、`[1,2,3].slice("1")`、`arr.at("2")`、
`"a-b-c".split("-", "2")`、`fill(0, "2")` 一律**当场报**（"string index must be a number" /
"fromIndex expects a number"）—— 两把尺子上这些都是正常值。改的是四处口径：prelude 的
`$js_idx` 与 `$js_arr_from_idx`、C 的 `to_int_arg` 与 `omni_js_arr_i`，都改成"先 `ToNumber`
再截尾"。bigint 仍然报 —— 拿 BigInt 当下标在 JS 里本来就是 TypeError。
`a["foo"]` 不受影响：两条腿都先问 `js_num_key`，非索引键早就走属性那条路了。

**空表 + 没给初值的 `reduce` / `reduceRight` 改成能 catch 的 TypeError**（规范 23.1.3.24
第 3 步）。C 那侧要用 `omni_js_type_err_c`，而它定义在 STR_ARR 段、reduce 在 ARR 段 ——
所以 ARR 段开头**先声明一行**（宏段摊进同一个翻译单元，静态函数先声明后定义是合法的）。

**迭代协议里那两格错改成能 catch 的 TypeError**（规范 7.4.2 的 GetIterator、7.4.4 的
IteratorNext）：`[...null]`、`for (const x of 5)`、`const [a] = undefined`、`next` 交出来不是
对象、真对象身上没有 `Symbol.iterator` —— 从前一律是硬错，整个进程停在那儿，而两把尺子上这些
都是 catch 得住的。两条腿各改一处（`$js_iter` / `omni_js_iter`，C 那侧新加一格
`omni_js_type_err_c`：错误对象就是 `{ $cls: […], name, message }`，与 JSON 那一族同一套）。
消息刻意不带标签名 —— 要与另一条腿一字一样，而两边的标签名对不齐（普通对象在 C 那侧是
`dict`、JS 这侧是 `object`）。

顺带修掉两格更细的：`js_iter` 从前**不带 throws**，于是"报了不马上查"——
`console.log([...badIter].length)` 那一句照跑完（印了 `no-throw`），catch 到**下一句**才生效；
展开那两处降级点因此也自己 `guarded` 一下。而 `guard()` 遇上 **void 的 op**（`console.log`
那一族）不能再往临时量里塞：C 那侧 "assigning to omni_dyn from incompatible type void" 直接
编不过（实参子树里有会抛的 op 时 `mayThrow` 对整句为真，连这一句一起被提走）——
现在 void 的那一支当一句发出去、后面照旧跟一次 pending 检查。

**正则的旗标布尔属性补上了**（规范 22.2.6.4 起的 `global` / `ignoreCase` / `multiline` /
`dotAll` / `unicode` / `sticky` / `hasIndices`）。从前一格都不在属性表里，`re.global` 静静地给
`undefined` —— `if (re.global)` 于是走错一支，而 `.flags` / `.source` / `.lastIndex` 一直是有的。
底下都是同一件事"flags 串里有没有那个字母"，但属性派发器要的是**一元**的 op，所以一格一个
（`js_re_global` …，两条腿各七个一行的实现）。别的标签照旧走普通属性读 ——
`({ global: 1 }).global` 还是 1。返回的是 dyn 而不是 C 的 `bool`：属性派发器的兜底那一支
交出去的是 dyn（`omni_js_obj_getk`），声明成 bool 会让整个派发器编不过（当场撞到）。
五腿用例里只量 g / i / m：C 那条腿的正则引擎**造**的时候就拒 `s` 与 `y`，那两格为真的样子
只在 js262 里量。

**`var` 现在是函数作用域的**（规范 14.3.2 的 VarDeclaredNames）。从前它跟 `let` 一样按块声明
—— `{ var x = 1; } return x;` 于是当场报 `unresolved identifier 'x'`，`if`/`try`/`switch`/循环里
写的 var 同样出不来。修法是栈帧入口一趟 `hoistVars`：把这一层（不钻进内层函数）所有 `var` 的
名字一次立好、值 undefined，声明那一句只剩"写一次"，没有初始化式的 `var x;` 一句都不发
（再声明一次不清零）。形参同名（`function f(p){ var p = p + 1; }`）不另立一格 —— 规范里那就是
同一个绑定。模块顶层的 `var` 是全局槽，`collectTop` 现在连**块里**写的一起收，所以
`{ var g = 1; }` 之后顶层函数也读得到它。声明之前读它是 undefined 而不是错（TDZ 只管
`let` / `const`），这一格本来就对。

连带修的是 `preCells`：它只管 `let` / `const` —— 要是也给块里的 `var` 预立一格 cell，
那格 cell 就把提升出来的那一格**遮住**了（量出来的：闭包捕获块里的 var、块外再改它，
闭包看见的还是旧值）。

**块级的函数声明通了**（规范 14.2.3：那是**块**作用域的绑定，块一进去就绑好）。
`if (flag) { function f(){…} return f(); }` 与 `while (…) { const s = 1; function h(){ return s; } }`
从前当场报 "a nested function declaration is only supported at the top of a function body"。
现在块自己也走一趟"先立 cell（preCells）、再造闭包（hoistFuncDecls）"，`hoisted` 那一格存一存
再还回去（里层的块有它自己的一套名字）。**里外同名**那一格与两把尺子不一样，刻意不量：
块级函数声明在严格/模块语义里是块作用域的（我们这一档，`qjs -m` 也是），而 qjs 当脚本跑、
node 当 CJS 跑走的是 Annex B.3.3 的旧网页语义（提到函数作用域去）—— `{ function f(){…} }`
之后再读 `f`，两种语义给两个答案。`switch` 的 case 里那一格还是拒的（那儿没有块）。

**形参默认值里的闭包看得见前面的形参**（规范 10.2.11 的形参作用域）：
`function f(x, y = () => x)` 从前报 unresolved 'x' —— 直接写 `y = x + 1` 是通的，
只有装进闭包那一格漏了，因为 `capturedNames` 只扫**体**、不扫形参表。现在形参表也扫一遍。

**提升的嵌套函数声明现在看得见外层体里的局部量**。`function outer(){ const v = 1;
function inner(){ return v; } return inner(); }` 从前当场报 `unresolved identifier 'v'` ——
很普通的 JS，拒得没道理。原因在两件事的次序上：嵌套声明是**提升**的，降级器在栈帧入口就把
它的闭包造出来（`hoistFuncDecls`，互相递归靠的就是这个），而 `v` 是体里后面那一句才声明的，
造闭包那一刻作用域里还没有它。箭头与函数表达式没这毛病 —— 它们在声明之后才降级。

修法是入口再加一趟 `preCells`：把"这一层体**顶层**声明的、而且被内层函数引用过的"名字
各先立一格 cell（值是 undefined），到声明那一句时 `defineVar` 认出这一格是预立的、只往里写。
只管顶层：块里的声明另有作用域，提到帧入口来会把生存期改宽。`main` 那一帧不走这条路
（那儿的顶层名字是真全局）。

async / 生成器的体还多一层：它被改写成状态机，局部量的赋值落在 `step` 那格闭包里，而从前
`genToStateMachine` 把体里的函数声明**整份搬到外层**去 —— 那儿更看不见它们。现在搬的只是
**名字**（跟着 `sx.hoist` 走，每一段都看得见），函数值在**入口段**里造，与"函数声明提升到
体首"这条规范一致。

**`async () => e`（表达式体的 async 箭头）从前把编译器崩成宿主 TypeError**：
`genToStateMachine` 直接读 `node.body.body`，而表达式体的箭头那儿是一格表达式。现在先摊成
`{ return e; }`。崩成宿主错误是最坏的一档（比静默错值还难查现场），所以这一格单独记着。

**模板插值走 ToString，不是 `+` 的那套**（规范 13.2.8.5 第 5 步是 `ToString(值)`，
提示是 **string**）。从前每一格插值直接接在 `js_add` 上，于是走的是 ToPrimitive 的 default
提示 —— 带 `valueOf` 的对象上两者不一样：`` `${{ valueOf: () => 3, toString: () => "S" }}` ``
规范里是 `"S"`（string 提示先问 `toString`），我们静静地给 `3`。`Symbol.toPrimitive` 上更明显：
提示本身就传错了（`default` 而不是 `string`）。修法是每一格插值先过 `js_str`（那一格本来就是
ToString 的语义，`String()` 用的是同一格），`String.raw` 的替换位同理。四条腿一起。

**三格逻辑赋值的目标只读一次**（规范 13.15.2：`??=` / `||=` / `&&=` 各自 GetValue 一次，
按它决定要不要 PutValue）。从前条件里与"保持原值"那一支各读一次 —— 名字目标上看不出来，
取值器上数得出来：`q.v ??= f()` 里 `get v()` 跑了**两趟**。现在先把取到的值落进临时量，
两处都读它。惰性位置（`c ? (a ||= 1) : 0`）开不了语句，那儿仍是读两次的老形状 ——
成员目标在那种位置本来就当场报（接收者要临时量），所以退回的只有名字目标那一格，
而名字的读没有副作用。`+=` 那一族本来就是"读一次、写一次"，没动。

**解构的默认值不再每次都算**（规范 8.6.2 / 13.15.5 里那几处 KeyedBindingInitialization：
默认值只在那一格是 `undefined` 时求）。降级出来的形状本来就是对的（`if (t === undefined)
t = 默认`），漏在**别处**：默认值里那种会抛的调用会被 guard 提成"临时量 + 一次 pending
检查"落进 sink，而 sink 是**当前语句**的前置表，于是那两句摊在整条 `If` 的前面 ——
`const { a = g() } = { a: 0 }` 里 `g()` 照样跑了一趟。属性在的时候副作用照样发生，静悄悄的。

修法是给降级器加一格 `captureSink(f)`：把 f 期间落进 sink 的语句捞出来，放进 `then` 那一块
里跟着走。与 `lazy()` 的分工是"能不能有 sink"：`lazy()` 那儿一格都不许（当场报，三元的分支
那种位置），这儿是"许，但要跟着条件走"。三条路都改了：声明位（`bindElem`）、嵌套模式带默认值
的那一支、以及赋值位（`destructInto` 的 `put`）。形参的默认值本来就是对的（那儿的 If 自己
就是语句），所以没动。

**`sort` 的比较器结果照规范 ToNumber**（规范 23.1.3.30.2 第 3 步），另外 `sort` / `toSorted`
补进了原型（`[].sort` 从前是 undefined，`[].sort.length` 于是当场报）。从前非数一律当 0 ——
交串的写法（`(x, y) => x < y ? "-1" : "1"`）因此**一格都不动**，静静地把原来的次序交回去，
两把尺子都排好了。现在两条腿都先过 `$js_num_of` / `omni_js_num_of`：布尔是 1/0、串按串解析、
`null` 是 0、`undefined` 与解析不动的串是 NaN（照旧当"相等"）。

只交布尔那种比较器（`(x, y) => x > y`）**刻意不量**：它不是一致的比较函数，规范明说次序由
实现定 —— qjs 给 `1,2,3`，node 给 `3,1,2`（各自的算法不同），我们这条腿借宿主的 `sort`，
所以与 node 一字不差、与 qjs 不同。C 那条腿是手划的归并，第三种次序也是合法的，
因此这一格既不进 js262（尺子是 qjs）也不进五腿（那道门要五条腿逐字相同）。

**`Object.assign` 收原始值当源**（规范 20.1.2.1 第 4 步）。`Object.assign({}, 3)` 从前当场报
"real is not an object" / C 那侧 "dynamic value is real, expected dict" —— 响的，但拒错了：
规范里每个源先 `ToObject` 再抄**自有可枚举键**，数 / 布尔 / bigint / symbol 包起来一格键都没有，
所以答案是"什么都不抄"，不是错。串那一支（摊成下标键）与数组那一支本来就在，这次补的是
剩下那几格原始值，两条腿各加一句标签判断。`Object.assign({}, "ab", null, undefined, 3, true)`
是 `{"0":"a","1":"b"}`，五腿用例 `21-builtin-fn-value` 里量的就是这一行。

顺带记一格**尺子自己的 bug**：`{ ..."ab" }`（对象展开一个串）在 qjs 上是 `{}`，node 与规范
都是 `{"0":"a","1":"b"}` —— 我们跟规范（也就是跟 node）。这一格因此**不能**进 js262
（那道门逐字节比 qjs），只在五腿那边量得到。`Object.assign({}, "ab")` 走的是同一段代码，
qjs 在那儿是对的，所以要按尺子对齐这一族的话，靠的是 assign 那一行，不是展开那一行。

**带标签模板的站点缓存**（规范 13.2.8.4）。`` t`a${x}b` `` 降成 `t(strings, x)`，那格
`strings` 从前**每次求值都新造一格** —— 于是 `` t`x` === t`x` `` 静静地为假，拿它当
WeakMap / Map 键的库（lit-html、graphql-tag 那一类模板缓存）永远打不中，只会一路长下去。
规范里身份跟着**源码位置**（同一处站点复用同一格，两处写法一样的站点仍是两格），所以做法是
给每个站点配一格模块级的槽（键 `@tpl<n>`，不是合法的 JS 标识符，撞不上用户的名字），
**第一次求值时**才装：`slot === undefined ? (slot = mk()) : slot`。选懒装而不是在 main 开头
一次装齐，是因为站点可能在**别的全局初始化的过程中**被跑到（``const A = tag`x`;`` 就是），
那时候 main 的序还没走到。数组身上那格 `raw` 照旧走 `js_obj_set` 的旁表。规范里那格模板对象
是冻住的，这儿没冻 —— 改得动 `strings[0]` 这一格记在"没做"那一节。

**`new Uint8Array([1,2,3])`** 补上了（从前当场报 "expects a byte buffer, found list"）。
数组与字节缓冲在这个值域里是两种值，而"实参是哪一种"只有**运行期**知道 —— 所以降级器按
标签在两格 op 之间挑：`js_arr_is_array(x) ? js_buf_of_list(x) : js_buf_view(x, …)`。
新那一格的 C 实现住在 `omni_js_arr.h` 的宏段里（那儿有 LT，走得了 list）；
`omni_js_buf_view` 在 `omni_js.c`，拿不到 list 的类型实例，所以分不出这一支 —— 这也正是
第一次尝试退回来的原因（见"没做"那一节里留着的那段）。每一格照规范 ToNumber 再 ToUint8
（截零、模 256、NaN 归 0），所以 `"3"` / `true` / `null` 都收得下。`DataView` 不收数组
（规范里那是 TypeError），所以这一支只给 `Uint8Array`。

**代理身上那四格原型/可扩展性陷阱**（规范 10.5.1-10.5.4）：`getPrototypeOf` /
`setPrototypeOf` / `isExtensible` / `preventExtensions` 从前一格都不问 ——
`Object.getPrototypeOf(proxy)` 静静地报的是**目标**那一格，陷阱一次也没被叫到。
连带修的是 `instanceof`：它走的是同一条原型链，从前直接读 `.pr`，于是带 `getPrototypeOf`
陷阱的代理 `instanceof Array` 也静静地给 false；现在每一跳都走 `$js_obj_proto_get`。
还差 `Proxy.revocable`（现在是编译期 "unresolved identifier 'Proxy'"，响的）与规范里那一整套
"不变量校验"。

**`Object.prototype.toString` 的那格标签**（规范 20.1.3.6）：从前 `Map` / `Set` / 正则 /
`Symbol` / `Date` / `Error` / `Promise` 全报 `[object Object]` —— 静悄悄的错值，按它分派类型的
库会全走错。现在两条路各补齐：不是"真对象"的那几格（Map / Set / regexp / symbol）照标签
直说；`Date` / `Error` / `Promise` 造出来的对象自己没有 `cl`（都是 "Object"），所以认它们的
**原型**（规范那儿看的是内部槽，原型链是这个值域里的替身）。`String(new Map())` 走的是同一格，
两侧从前都撞在 "cannot convert Map to string" 上，现在 C 的 `to_s16` 里也照标签直说。
剩两格照旧，是"同一种值"那条边界的后果，不是新账：`WeakMap` / `WeakSet` 报 Map / Set
（ADR-0020 P4），`ArrayBuffer` / `Uint8Array` / `DataView` 报 Object（ADR-0011 决策 10）。

**`Reflect` 那三格交出布尔，`Object.setPrototypeOf` 认不可扩展**。`Reflect.defineProperty` /
`setPrototypeOf` / `preventExtensions` 从前直接接在 `js_obj_def` / `js_obj_proto_set` /

- `console.log` 的**检视**格式：数组/对象/Map/Set/函数/Symbol 照 `String()` 走，不追
  node/qjs 的 `[ 1, 2 ]` / `{ a: 1 }`。两把尺子自己就不一致（node 印 `[ 'a' ]`、qjs 印
  `[ "a" ]`，嵌套深了 qjs 还印 `[Array]`），没有"唯一的对"。同一格里 bigint 也不补 `n`
  （两把尺子都印 `30n`）：C 那条腿上 JS 的 bigint 与方言的 int64 是同一个标签，补了 n
  方言自己的 println 就全错（量过：tests/oir 的 whole program 印成 `77n`）。所以 5 条腿的
  用例里 bigint 要用模板串印。
- `null.x` / 调用 undefined 这类**运行期类型错**是进程级的 abort，不是能 catch 的
  TypeError（每个 op 都要走 pending 槽才能改，量级在决策 14 那一档）。`JSON.parse("{bad}")`
  与循环引用的 `JSON.stringify` 同一档：规范里是可 catch 的 SyntaxError / TypeError，
  这儿是 abort。JS 那条腿单独改成可 catch 会与 C 那条腿分叉，所以两条腿一起留着。


**接收者那一格补齐了**：`js_getp` 收第三格、`js_setp` 收第四格（就是规范 OrdinaryGet /
OrdinarySet 的 Receiver）。于是 `super.x`、`super.x = v`、`Reflect.get(t,k,recv)`、
`Reflect.set(t,k,v,recv)` 四处都对上了 —— 访问器的 this 是接收者，数据格写在接收者身上
（`super.d = "own"` 落在实例上，父类原型不动）。`Reflect.set` 另有一格 op（`js_reflect_set`）
因为它交出的是**布尔**（写不进去是 false），而赋值表达式交出的是 v。
顺手修了代理那一格：接收者是代理时新属性要落到它的**目标**上（没有 defineProperty 陷阱
时规范就是这么转的）—— 不然 `p.w = 8` 写在代理对象自己身上，读回来走陷阱又成 undefined。


**私有名 `#x` 现在是符号键**（原来是叫 `"#x"` 的字符串属性，于是 `o["#x"]` 读得到、
`Object.getOwnPropertyNames` 也列得出 —— 那是这一轮最后一处 silent 分叉）。键由
`js_sym_for("#x")` 给，所以：`o["#x"]` 是 undefined、`Object.hasOwn(o, "#x")` 是假、
own-names / `Object.keys` / `JSON.stringify` 都看不见它，`#x in o` 走 has_own（brand check）。
代价写在明处：`Object.getOwnPropertySymbols` 还看得见它，而且两个类里同名的 `#x` 共用
一格键（规范靠词法作用域禁跨类访问，这个值域里没有那一层）。



`tests/js262/` 那道门现在 **34 passed / 0 known-red**（基线是 12 条全红）—— known-red.txt
里一条不剩。最后清掉的两条：`this-call-apply-bind`（Array.prototype 上摆了借得最多的
那几个方法 —— 数组的方法平时按标签派发，原型上本来一个都没有）与 `class-extends`
（`x instanceof Object` 走 js_instanceof_p，拿 realm 上那一格 prototype 比原型链）。


**内建函数当值用**（`const f = Object.keys` / `[1,2].map(Number)` / `Math.abs.name`）：
降级出一个薄包装闭包，体就是那一句 ABI 调用，所以补 undefined、lit、pre、usesJobs 还走
`abiCall` 那条路，五条腿都通（`tests/js-exec/cases/21-builtin-fn-value.js`）。两处边界：
`STATIC_CALLS` / `GLOBAL_CALLS` 里**标了 `len` 的名字才有这一格** —— `len` 是 JS 那侧的
arity，与 op 的形参个数不是一回事（`js_math` 收 2 个，而 `Math.abs.length` 是 1）；没标的
（`console.log` / `String.fromCharCode` 那些收可变实参的）照旧当场报错，不给一个 length
会撒谎的值。包装是**单件**（`Object.keys === Object.keys` 要为真）—— 顺手补上的一格：
闭包解释器从前在 JS 那条路上提前 return，单件缓存落不下去，于是 `f === f` 在那条腿上是假
而两个后端是真（`src/core/interp/eval.js` 的 makeClosure）。

已经落地的（P1/P2/P3/P4/P5 里的大件）：真对象（原型 + 描述符 + Symbol 键 + 访问器）、
`this` 是真接收者、类改原型链（static / 字段 / 访问器 / `extends` / `super` /
私有名 `#x` / static 初始化块）、迭代器协议、for-in、可选调用、tagged template、
`arguments`、解构赋值、**switch 穿透**、**try/finally**、**惰性位置里的后缀自增**、
Error 全家 + `{ cause }`、Object/Reflect/Symbol 的静态面、内建原型当值、
JSON 的 replacer / reviver / toJSON、Math 全族 + clz32、parseFloat、Array/String 的新方法、
DataView 的定宽整数与 float32、Uint8Array 的下标读写、WeakMap/WeakSet、
**Date（毫秒那一档）**、**Proxy 的七个陷阱（含 apply / construct）**、**globalThis**、正则的 lastIndex 与
**具名捕获组**、**Promise + 微任务队列**、**生成器（`function*` / `yield` / `yield*` /
生成器方法 / `it.return` / `it.throw`）**、**async（`async function` / `await` /
`for await` / async 生成器 / async 方法与箭头）**、**`fn.name` / `fn.length`**、
**普通函数当构造器（`new f()` / `f.prototype` / `new.target`）**、**`eval` 与 `Function(src)`**。

还差的一条（要另立决策，不在这一轮里）：

1. `lib/BigInt 任意精度`：这个值域里的 `int` 是 **int64**（ADR-0005），所以 `2n ** 64n`
   是 0 —— **五条腿一致地是 0**，不是某条腿偷偷不一样（量过：node/qjs 给
   18446744073709551616）。要真做需要在值域里加一格"任意精度整数"：C 侧一套 bignum
   （加减乘除模幂位移比较与十进制/任意进制打印）、JS 侧不再截成 64 位、`typeof` 与打印
   （qjs 印 `1n` 那个后缀）都要能把它与 int64 分开，MIR/原生两条腿也要跟着走。
   这一步改的是**语言的值模型**而不是 JS 前端，与 ADR-0005 直接冲突，所以要单独立一节。
   已经顺手补齐的相邻那格：`(5n).toString()` / `true.toString()` 原来落到"取属性再当函数调"
   的兜底上给出 `[object Number]`，现在两条腿都按接收者的标签走 `js_num_to_string`
   （int 不先转 double —— 2^53 之上的 int64 转过去要掉精度）。

`eval` / `Function(src)` 的落点（P6）：这两样要**编译器在运行期在场**。约定是一格运行期的
钩子 —— `host/src_eval.js` 的 `installSrcEvalHook()` 把它装到宿主全局上，产物里的
`$js_src_eval`（prelude）顺着它找。装得上的场合只有"在本进程里跑"这一条：`omni run` 的
JS 腿与 REPL；`omni build` 出来的独立产物、C 那条腿、解释器腿都装不上，那时这两个 op
**当场报错**，不假装能跑（这是刻意的：产物自己是自洽的一份，不该偷偷依赖工具链）。
认下来的是**全局 eval** 那一档（规范里的 indirect eval）：每次编一段独立的模块，
所以看不见调用者的局部量 —— `let x = 1; eval("x")` 在 qjs 里是 1，在这儿是一句编译期的
"unresolved identifier"，冒到 JS 那侧是 ReferenceError（别的编译期毛病算 SyntaxError）。

`fn.name` / `fn.length` / `f.prototype` 的落点：函数不是真对象，这几格因此不是自有属性，
而是 `Function.prototype` 上的访问器 —— name/length 存在**闭包记录**里（`$nm` / `$ln`，
由 lower.js 的 closureOf / topFnValue 填，emit.js 的 closureMake 发），prototype 存在一张
按闭包记录身份查的 side table 上（prelude 的 `$FNPROTO`）。所以"具名函数取出来的值"
必须是**单件**（`single: true`，与 sexpr 的 fnref 同一格）：不然 `f === f` 与
`new f() instanceof f` 都会是假 —— 这一条是量出来的。
`new.target` 走一格运行期的槽（放的人只有 `js_fn_construct`，取的人是函数入口），
窄口记在 prelude 那一段注释里。箭头的 name（规范里来自赋值目标）与内建静态面的取值
（`Object.keys` 当值用）还没有。C 那条腿：这一族 op 都在 `P1_JS_ONLY` 里，发射时就拒。

生成器/async 这一刀的形状与它认下来的子集写在 `src/core/frontend-js/genfn.js` 的文件头上。
try / catch / finally 三种形状都通了：这个值域里的异常是"挂起槽 + 提前 return"
（ADR-0007），所以接手要**驱动**帮一把 —— 它看见挂起槽满了就把那格值送回 step（mode 2，
与 `it.throw` 同一条路），step 开头那一段先看有没有活着的 catch（`_g_cat`）、再看 finally
（`_g_fin`），都没有才原样往上冒。finally 体因此**发两份**（正常路 + 非正常路），所以它
自己不许有 yield / await，也不许有 break/continue/return。`yield*` 是先把内层收齐再一格
一格转发（`js_iter` 的老账）。拍数是量出来的：`await` 一拍，async 生成器的 `yield`
多一拍（规范 27.6.3.8 先 Await 让出去的值）。

## 决策

### 1. 走"扩现有降级器"，不另起一台引擎

不新建 `js-vm/` 子系统。理由：五条腿的差分（解释器 / JS / C / LLVM / 原生）是这棵树唯一
可靠的正确性来源，另起一台引擎等于把它作废，而且编译器自己的 JS 往返轴（`tests/js-roundtrip`）
还得留在这条路上。代价写在明处：**能挂起的控制流**（生成器、async）没有运行期栈可用，
只能在降级里做**状态机改写**（regenerator 那一套）；`eval` 与 `Function(src)` 需要编译器
在运行期在场，非 node 宿主上仍然只能报错。

### 2. 尺子是 qjs 的 stdout，逐字节

编 `reference/quickjs-2026-06-04` 出 `qjs`，同一份 `.js` 两边各跑一趟比 stdout（新门
`tests/js262/`）。test262 的 checkout 本机没有，先不进门；阶段验收时再补。
QuickJS 自己 `test262.conf` 里标 `skip` 的那些（Intl、Temporal、decorators、
ShadowRealm、explicit-resource-management、tail-call…）**我们也不做** —— "QuickJS 那一档"
就是这条线。

### 3. 对象模型是地基，先它，别的都排在后面

真对象一格值：`{proto, 有序属性表, 描述符, Symbol 键, extensible}`。`js_obj_*` 全家改走它，
`dict<string,dynamic>` 退成实现细节。`this` 随之从"捕获的 cell"改成**调用接收者**——
这一刀牵动调用约定（现在每个 JS 函数是 `fn(list<dynamic>)->dynamic`，没有 this 槽）。

### 4. 阶段顺序（按依赖排，不按难度）

- **P1 对象模型**：真对象 + 描述符 + 原型链 + Symbol + 访问器 + 迭代器协议 +
  `this`/`call`/`apply`/`bind`/`new.target` + 类改成原型链（static / 字段 / 访问器 /
  任意 `extends` / `super`）+ 对象字面量补全 + `ToPrimitive`/`instanceof`/`typeof` 对齐
- **P2 可挂起的控制流**：生成器（状态机改写）、Promise + 作业队列、async/await、
  for-await、async 生成器
- **P3 语法补全**：for-in、finally、labels、tagged template、可选调用、逗号表达式、
  `arguments`、解构与默认值补全、可选 catch 绑定、私有字段 `#x` 与 static block、
  数字分隔符与 BigInt 字面量、严格/宽松模式的差异
- **P4 标准库推到 QuickJS**：String/Array/Object/Number/Math/JSON/Date 全方法、
  Map/Set/Weak*/WeakRef/FinalizationRegistry、Proxy/Reflect、TypedArray 全家 +
  DataView + ArrayBuffer/SharedArrayBuffer + Atomics、任意精度 BigInt、Error 全家（cause /
  AggregateError）
- **P5 正则与 Unicode**：照 `libregexp.c` 复刻字节码 + 回溯引擎（命名组、lookbehind、
  sticky/dotAll、`u`/`v` 标志、Unicode 属性），字符表照 `libunicode.c`
- **P6 运行期编译**：`eval` / `Function(src)` / 动态 `import` / `import.meta`（node 宿主
  有引擎的那一路先通，别的报错）

### 5. 封闭 ABI 的成本照旧，但允许"一族一个 op"

每个 op = `js_abi.js` 一行 + prelude 一份 + C 运行时一份。P4 那一堆方法要是一人一个 op，
表会涨到上千行 —— 所以**同族方法合成一个 op + 一个 `lit` 选择子**（`js_arith` 的 `op`
字段就是这个先例）。判据：签名相同、语义同族。

## 已知风险

- `this` 那一刀会动到每一处成员调用的降级，而编译器自己的源码就跑在这条路上：
  改坏了是"编译器编不出自己"。所以 P1 内部还要再分片，每片都能单独跑 `tests/js-exec`。
- 状态机改写会让生成器函数的 OIR 体积涨几倍；C 后端那边是几万行生成 C，编译时间会涨。
- 任意精度 BigInt 要在值域里再加一格（现在 `BigInt` 就是 int64 回卷，ADR-0011 决策 5），
  那与 ADR-0005 的值语义有冲突，得单独立一节。

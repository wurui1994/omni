# ADR-0045：照别人的 `.y` 复刻一门语言 —— R 那四处必须偏离的地方

## 决定

**一门语言的语法有现成的 `.y` 时，`ext/<语言>/<语言>.grammar` 是"照转出来的文本改几处"，
不是手抄，也不是直接用那份 `.y`。** 改的每一处都要有根因，而且要写在那份 `.grammar`
的文件头上 —— 与 `.y` 的差别是**这门语言的账**，不是某次提交的说明。

R 是第一门这么做的（ADR-0034 那个导入器落地之后的第一个真主顾）。四处差别，一条一个根因：

1. **一条候选式一个标签。** 导入器出来的动作只留左部名字，于是
   `(-> (NUM_CONST) (expr $1))` 与 `(-> (SYMBOL) (expr $1))` 出的节点一模一样 —— 而
   **CST 里没有记号类别**（`glr/driver.js:356` 移进时只留 `tk.node`，把 `tk.type` 丢掉了）。
   adapter 分不开"这是个数还是个名字"。所以照 `ext/chez/chez.grammar` 的规矩改：
   `(num …)` / `(str …)` / `(sym …)` / `(null)` / `(placeholder)`。
   反过来，二元算符那一族**刻意共用一个 `bin` 标签**、算符文本走 `$2` —— 那正是 R 自己的
   `xxbinary($2,$1,$3)`：`<-` / `<<-` / `:=` 三个写法都是 LEFT_ASSIGN，分开它们只能看文本。
2. **词法自己写。** R 的词法是那份 `.y` 第二个 `%%` 之后的**手写 C**（`token()` / `yylex()`
   / `NumericValue` / `SpecialValue` / `SymbolValue`），不是 `.l`，导入器一个字也拿不到。
3. **顶层多一条 `program : exprlist`。** R 的 `prog` 是"一次一条表达式"（`END_OF_INPUT` /
   `'\n'` / `';'` 各一条候选式，C 那侧 `R_ParseVector` 循环调用 parser）。读整份文件要有
   一条自己的起始符号 —— 这是唯一一处**结构性**增补。
4. **`eaoh -> expr` 挂 `(prec LOW)`。** 那 28 处移进/归约冲突 R 那份 `.y` 上同样撞，
   bison 的默认动作是**移进**（于是 `\(q) q + 1` 的函数体是 `q + 1`）。我们这条路上
   "默认移进"不存在：两支都活着，GLR 会老老实实报歧义（它就该报）。给那两条产生式挂上
   最低那一级之后 28 处全按"移进"定下来 —— **与 bison 的默认同解，但是说出来的**。

## 为什么第 4 条不是"照 bison 加一条默认"

因为"默认"是 LR 生成器的实现细节，不是语法的意思。bison 遇到移进/归约冲突时印一行警告
然后移进；GLR 驱动没有那一步 —— 它把两支都留着，到运行期发现两棵树都成立就报歧义。
两者都没错，错的是**让语法的意思藏在某个工具的默认值里**。所以这一格的办法只能是把那句话
写进语法（一句 `(prec LOW)`），而不是在驱动上加一条"撞了就移进"。

代价明说：`glr table` 上那 28 行冲突消失了，于是"这门语法有多少处真歧义"这个数变得更小、
也更可信 —— 剩下的 36 处全是 `%nonassoc GT GE LT LE EQ NE`（`a < b < c` 在 R 里就是错的）。

## 换行：`(auto-semi …)` 上加的那两格

R 的词法为换行专门带了一个 `contextstack`（`gram.y:3826–3904`）：切出一个换行之后问三件事。
三问一一对上 `(auto-semi …)` 的三格，其中两格是这一版加的（**别的语言不声明就一个字节不
受影响**）：

- `(brackets "()" ("[[" "]" 2) "[]")` + `(brackets-clear "{}")` —— "在不在括号里"。
  **是栈不是计数**：R 判的是 `*contextp == '('`，也就是**栈顶**。`f(function(x) { … })`
  里面那几个换行照旧是分隔符，因为栈顶是 `{`。计数版在 R 那棵树的 958 份 `.R` 上量过：
  从 940 掉到 **728**。`("[[" "]" 2)` 那个层数也是 R 自己的做法（`gram.y:3990` 推两格）——
  `[[` 是一个记号，闭合它的 `]]` 是两个。
- 模式项 `(until "关")` —— 吞到**第一个** `关` 之前。这是这套贪心不回溯的匹配器里唯一的
  非贪心项（ADR-0034 里已经为块注释留了同一条口子）。R 的原始串 `r"{…}"` 内容里真会出现
  单个 `}`（`(?:…){0,2}` 这种正则），要扫的是**两个字符**的 `}"`。

第三问（"往下看一眼是不是 `else`"）用的是现成的 `unless-before`，但必须带上 `else` 后面
那一格空白或 `{`：光写 `"else"` 会按前缀撞上 `else.expr` 这个真名字
（`src/library/compiler/R/cmp.R`），把两行粘成一行。

## 门槛

- `node bench/grammars.js r` —— R 自己那棵树里 **958 份 `.R`／`.r` 全过**。
  挑出去的 4 份是本来就不该读得下来的，一份一份挑（不按目录一刀切），理由在
  `ext/r/bench.json` 里。
- `node tests/r/oracle.js` 的第二节 —— **那份 `.y` 的漂移守卫**：它一直转得出来、
  建得出表、产生式条数与我们那一份差 ≤ 6（现在差 2）。"正本是 gram.y"这句话只有在这一格
  绿着的时候才成立。
- `node tests/r/oracle.js` 的第一节 —— 八份例子逐字节对本机 `Rscript --vanilla`。
  这是这条路上第一次**正确性的参考实现就在手边**：期望值不是我们编的。

## 这一条**没有**决定什么

- 没有决定 R 的值模型。向量化、`NA` 的传播、属性、S3/S4 分派、懒求值全都**没做**，
  一条一条写在 `ext/r/SPEC.md` 的"明说的不足"里。那是另一版的事，而且要先有"向量"这一层。
- 没有把那份 `.y` 搬进仓库。仓库里只有转换器与我们自己那份 `.grammar` ——
  与 ADR-0034 的分工一致（`.y` 是**读**的，不是**抄**的）。

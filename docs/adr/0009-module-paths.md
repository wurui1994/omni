# ADR-0009：模块与导入路径

状态：已接受（2026-08-25）· 实现：`stage0/src/module/load.js`、`stage0/src/parse/parser.js`、
`stage0/src/hir/check.js`

## 背景

在这条 ADR 之前，标准库是靠 `cli.js` 里一段叫 `libsFor` 的正则接入的：源文件里出现
`json` 或 `dynamic` 字样，就把整个 `lib/json.omni` 拼到程序前面。它有三个直接后果，全都真实发生过：

1. **误判**。`/\bJson\b/` 在 `parseJson` 里匹配不上，于是 `parseJson(s)` 报的是
   "undefined function 'parseJson'" —— 一个和真正原因毫无关系的错误。
2. **模式是整程序的**。用户代码和 lib 拼成一个 program，只有一个类型模式。一个 `.omnid`
   文件会把 `lib/json.omni` 也拖进纯动态模式编译，这与 ADR-0008 "模式按文件" 的说法相矛盾。
3. **没有边界**。lib 的每个内部 helper（`jsonStr`、`jsonValue`、`jsonCur`…）都是全局名字。

所以模块系统不是"再加一个特性"，而是补上一个本来就假定存在的东西。

而导入路径这件事，几乎每一门主流语言都在上面留下过伤口。这条 ADR 的主体因此不是"我们支持
什么"，而是**"我们刻意不支持什么，以及那条路是谁踩坏的"**。

## 决定

### 1. 语法：`import "路径";`，没有别的形态

```omni
import "./util.omni";        // 相对
import "std/json.omni";      // 包
```

没有 `from`、没有名字列表、没有别名、没有 `import *`、没有 `import x as y`。
被导入模块的**公开顶层名字整体进入导入方的作用域**（Asymptote 的 `import` 模型）。

要藏什么由**被导入方**决定，不由导入方挑选：

```omni
private int jsonCur(JsonParser p) { ... }   // 只在本模块可见
```

理由：挑选式导入（`from x import a, b`）把"谁该看到什么"的决定权交给了调用方，于是库作者
无法演进内部实现 —— 任何内部名字都可能已经被某个调用方直接 import 了。默认公开 + `private`
让边界只有一处、由拥有者维护。

### 2. 只有两类 specifier，判别只看第一个字符

- 以 `./` 或 `../` 开头 ⇒ **相对**，相对**导入方文件所在目录**解析，仅此一处。
- 其余 ⇒ **包**，形如 `包名/包内路径`，包名经清单查到根目录后拼接。

判别是**全序、无重叠、无回退**的：不存在"先当相对试试，不行再当包试试"。

### 3. 刻意不做的九件事，以及它们的来历

| 不做 | 谁踩过 | 具体的痛 |
| --- | --- | --- |
| 隐式相对导入 | Python 2 | `import string` 可能拿到同目录的 `string.py`，也可能拿到标准库；同一行代码的含义取决于旁边有什么文件 |
| 向上逐级查找 | node_modules | 解析结果取决于祖先目录的内容，`cd` 到别处就变；同一个包在树里出现多份不同版本，而源码里看不出来 |
| 猜后缀 / 目录索引 | node（`.js`/`.json`/`index.js`）| 一次导入变成 N 次 stat；`./x` 到底是 `x.js` 还是 `x/index.js` 要读磁盘才知道。对我们更致命：**后缀决定类型模式**（ADR-0008），猜后缀等于猜模式 |
| URL 当导入路径 | Go 早期 | 导入路径同时是下载地址，代码和某个域名的存续绑死（`code.google.com` 消失时全网 import 失效）|
| 绝对路径 | —— | 把某台机器的目录布局写进源码 |
| 有序搜索路径 | Java classpath / C `-I` | "先找到的赢"，同名类静默相互遮蔽，且顺序由构建脚本决定，源码里看不见 |
| 文本包含 | C `#include` | 被包含者能看见包含点的一切、且重复包含要靠 include guard 自救 |
| 环 | Python / node（部分初始化模块）| 拿到一个字段还没赋值的模块对象，错误发生在很远的地方 |
| 大小写不敏感的解析 | mac / Windows | `import "./Util.omni"` 在开发机上过、在 Linux CI 上炸 |

对应的规则：

1. 不以 `./` 或 `../` 开头的路径**一定**是包名。缺 `./` 不会"退化成相对"，直接报错并给出改法。
2. 包名 ⇒ 根目录的映射来自**清单**，一层间接，没有搜索。stage0 的内置清单只有一条：
   `std` → `stage0/lib/`。将来换成真正的项目清单文件，形态不变。
3. 路径必须写全后缀（`.omni` / `.omnid` / `.omnis`），只解析成一个候选，永不 stat 第二次。
4. 含 `://` 的路径直接拒；绝对路径直接拒；`\` 直接拒（只认 `/`）。
5. `.` 与 `..` 只允许出现在路径开头的连续段里；`./a/./b`、`./a/../b` 都是错误 ——
   它们让"两个不同的字符串是不是同一个模块"变成需要计算的问题。
6. **模块身份 = `realpath`**。符号链接、以及从不同文件用不同相对路径指到同一个文件，都算同一个
   模块，只加载一次、只初始化一次。
7. 相对路径**不能逃出包根**（入口文件所在目录，或包的根目录）。爬出去的东西不属于这个包。
8. **环是错误**，并且报出整条链：

   ```
   omni: error: import cycle:
       ./imports/cyc_a.omni
       imports ./cyc_b.omni
       imports ./cyc_a.omni
   ```

9. 解析成功后，逐段核对 basename 与磁盘上的名字**逐字节相同**；只有大小写不同时报专门的错误，
   把 mac 过、CI 炸挪到本地就发现。

### 4. 可见性：默认公开、`private` 收回，且**不传递**

`A` 导入 `B`、`B` 导入 `C`，则 `A` 看不见 `C` 的名字。否则 `B` 换一个内部依赖，就会悄悄改变
`A` 能用的名字集合，而 `A` 的源码里根本没提到 `C`。

不可见的候选在查找时**当作不存在**，所以撞上别人的私有名字时，报的是
`undefined function 'secret'` 而不是 `'secret' is private`：别人的私有名字不该出现在我的诊断里。

### 5. 初始化顺序：后序拼接，没有调度器

加载是深度优先，模块的顶层语句按**后序**拼进合成的 `main`：被依赖者永远排在依赖者前面。
于是"用到时还没初始化"在结构上不可能发生，不需要初始化调度、不需要惰性求值、也不需要
"模块已初始化"标志位。这也是为什么第 8 条必须禁环 —— 有环就没有后序。

`tests/cases/18_import.omni` 直接验证这一点：输出必须是 `geom init` / `shape init` / `main init`，
且 `geom init` 只出现一次（菱形依赖只加载一次）。

### 6. 模式按文件，这条 ADR 才让 ADR-0008 兑现

每个 decl 带上它所属模块与**它所在文件的模式**，检查器在检查每个声明前把这两者摆好。
于是一个 `.omnis`（禁止隐式 dynamic）文件可以导入一个 `.omnid`（一切缺省都是 dynamic）文件，
两边各按自己的规则检查 —— `tests/cases/19_per_file_mode.omnis` 就是这个断言，
在 `libsFor` 时代它不可能通过。

### 7. REPL 是唯一的隐式导入

REPL 会话隐式带一行 `import "std/json.omni";`：交互式回显的值随时可能是 dynamic，而
`print(dynamic)` 要降级成 `dynToText`。**只有 REPL 有这个待遇**，源文件的依赖必须写在文件里。
`:list` 不显示它。

## 后果

- `libsFor` 删除。`cli.js` 不再猜依赖，`compileProgram` 只做"入口 → 模块图 → 检查 → OIR"。
- `lib/json.omni` 的 12 个内部 helper 与 `JsonParser` 类标了 `private`，公开面收缩到
  `parseJson` / `stringifyJson` / `dynToText` 三个。
- 用到 json 的文件必须自己写 `import "std/json.omni";`（6 个测试文件因此各加了一行）。
- 诊断里的路径一律显示成 cwd 相对路径。模块**身份**仍是 realpath，但 realpath 与机器绑定，
  照原样印进诊断会让快照测试在别的机器上全部失效。

## 已知局限（记下来，不装作没有）

1. **类型名仍在一张全局表里。** 函数的可见性是按模块过滤的，类型不是：两个模块各有一个
   `private class Foo` 会报 `redefinition of type 'Foo'`。修法是把 `types` 也做成
   按模块的查找表，等有真实需求再动。
2. **顶层变量共享合成 `main` 的作用域。** 两个模块各有一个顶层 `var n` 会撞。
   同上，等按模块的值命名空间。
3. **`private` 不能加在 class 的单个方法上**，只能整类。方法的可见性跟着它的 class。
4. **没有 `access` / `unravel`**（Asymptote 的"带前缀导入"与"打散命名空间"）。现在只有
   Asymptote `import` 的那一档。等真的出现名字冲突再加，加法已经想清楚：`access` 只需要给
   导入的名字加一个前缀作用域，不改解析规则。
5. **清单是硬编码的一条 `std`。** 换成文件形态时要一并决定版本与锁文件，那是另一条 ADR。

## 被否掉的方案

- **`#include` 式文本包含**：最简单，但被包含者能看见包含点的一切，且模式没法按文件确定。
- **`from x import a, b` 挑选式导入**：把边界的决定权给了调用方，库作者无法演进内部实现。
- **允许环、用惰性初始化兜住**：这是把"顺序错了"从编译期错误变成运行期的半初始化值。
- **不写后缀、由编译器补 `.omni`**：看起来更干净，但后缀承载类型模式（ADR-0008），
  补后缀就是猜模式；而且一旦有第二个候选，就回到 node 的"stat 一串路径"。
- **包名直接映射到目录名（不要清单）**：等于隐式的搜索路径，回到 classpath 的遮蔽问题。

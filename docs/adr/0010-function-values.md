# ADR-0010：函数值与闭包

状态：已落地 · 日期：2026-08-25 · 相关：ADR-0001（自举）、ADR-0006（类型系统）、ADR-0007（错误模型）

## 为什么现在做

自举的拦路虎不是解析，是**语言特性**。编译器自己的源码里有 110 个箭头函数、161 处带回调
的数组方法；没有函数值，JS AST 就没法降级成 OIR，C0 → C1 → C2 那个不动点连第一步都走不了。
所以这是自举链条上的下一块，而不是"顺手加的语法糖"。

## 决策

### 1. 类型写法：`fn(int, string) -> bool`

只有签名，没有参数名。参数名属于 lambda，不属于类型 —— 否则 `fn(int a)->int` 与
`fn(int b)->int` 会是两个类型，而它们显然应该能互相赋值。

类型相等是**逐位相同**（`typeKey` 一致），没有协变逆变。子类型化会立刻把重载解析的
代价模型（ADR-0006 的那张有代价的转换图）拖进偏序关系里，而现在还没有需要它的场景。

### 2. lambda 必须写全注解：`fn(int x) -> int { ... }`

不做"由形参位置的期望类型倒推 lambda 类型"。理由是顺序依赖：实参在**重载解析之前**就要
定型，如果 lambda 的类型要看它被传给哪个重载，那"选哪个重载"和"实参什么类型"就互相
依赖了。C++ 在这上面付出的代价（模板 + lambda + 重载三者互相牵引）足够说明问题。

写全注解让 lambda 自带类型，环就不存在。代价是啰嗦，收益是解析顺序永远是一遍过。

### 3. 捕获按值，且在创建闭包的那一刻拷贝

这是本 ADR 最重要的一条。

```
int base = 100;
fn(int) -> int f = fn(int x) -> int { return x + base; };
base = 200;
f(5);        // 105，不是 205
```

三个理由：

- **C 侧没有别的选择**。按引用捕获意味着闭包活得比栈帧长时要把变量搬到堆上（JS/Python 的
  cell、Swift 的 box）。那是一整套逃逸分析加装箱规则，而且和还没上线的 ARC（ADR-0007）
  纠缠在一起。按值捕获只需要一次结构体拷贝。
- **两个后端必须给同一个答案**。JS 的闭包按引用捕获，所以生成的 JS **不能依赖宿主的词法
  作用域** —— 必须显式把捕获拷进闭包记录。经典的"循环里建闭包"就是判据：Omni 的
  `for` 循环里建的闭包各看到自己那一轮的值，JS 若靠宿主作用域会全看到最后一轮。
- **Python 的晚绑定是公认的坑**。`[lambda: i for i in range(3)]` 全返回 2，Python 自己的
  文档都得教人写 `lambda i=i:` 绕开。既然要选一个，就选不需要教的那个。

引用类型的捕获拷的是**引用**，所以透过捕获的 list/dict/class 改内容照样可见 —— 这是引用
语义，不是"按引用捕获"。想让闭包影响外面，就捕获一个容器或对象。

因此**给捕获的变量赋值是编译错误**，而不是"改了但外面看不见"：

```
'base' is captured by value, so a lambda cannot assign to it
  — return the new value, or capture a class/container and mutate that
```

### 4. 表示：一个指针，指向"函数地址 + 捕获"合成的记录

C 侧：

```c
typedef void (*omni_fnptr)(void);
struct omni_closure_s { omni_fnptr fp; };
typedef struct omni_closure_s *omni_fn;
```

每个 lambda 生成自己的记录布局，第一个字段与上面对齐：

```c
struct omni_clo_0_env { omni_fnptr fp; int64_t c_n; };
static int64_t omni_clo_0(omni_fn self_, int64_t v_x) {
  struct omni_clo_0_env *self = (struct omni_clo_0_env *)self_;
  return omni_add(v_x, self->c_n);
}
static omni_fn omni_mk_0(int64_t c_n) { ... }
```

三个细节：

- **记录自己当作第一个实参传进去**，而不是另外传一个 env 指针。于是函数值是**一个**指针，
  不是"函数指针 + 环境指针"的胖值 —— 存进容器、比较、判空都简单，也不需要为胖值定义拷贝。
- `fp` 声明成函数指针类型而不是 `void *`：函数指针与对象指针的互转在 C 里不保证，函数
  指针之间的互转是允许的（只要按真实类型调用）。
- **每个签名一个类型化的调用助手** `omni_call_fn_int__int(f, a0)`。不在调用处直接展开
  强制转换，因为那样 `f` 会被求值两次（一次取 `fp`、一次当 self 传），
  `get_handler()(x)` 就会调用两次 `get_handler`。

JS 侧一一对应：`{ fp, c_* }` + `$callFn(f, ...args)`，第一个实参同样是记录自己。

### 5. 具名函数当值用：包一层薄适配器

`fn(int)->int t = twice;` 生成一个零捕获的适配器闭包，形参照抄、转手调用 `twice`。
这样**所有**函数值共用同一套调用约定，调用处不需要区分"这是 lambda 还是具名函数"。
代价是一次多余的调用；同一个函数只包一次（按 mangled 名缓存）。

有多个重载时必须有期望类型来定案：

```
fn(real) -> real g = pick;   // 按签名挑中 real 那个
var h = pick;                // 错误：2 个重载，用作值是歧义的
```

### 6. lambda 提升在检查器里做，后端只看见普通函数

C 没有嵌套函数。把"lambda → 顶层函数 + 闭包记录"这层降级放在检查器（`hir/check.js`），
两个后端就都只需要认识三个新节点：`MakeClosure`、`CaptureRef`、`CallFn`。OIR 里不出现
"嵌套函数"这种只对某些目标成立的概念，符合 ADR-0001 对 OIR 的约束。

捕获集合是**按需登记**的：检查 lambda 体时遇到一个不在本 lambda 作用域里的名字，就沿着
外层帧逐层往外找，**每一层都登记一次捕获**。内层 lambda 的值来自外层 lambda 的捕获槽，
而不是直接跨层读外面的栈帧 —— 外层早就返回了，跨层读会读到失效的帧。这也顺带让遮蔽
（inner 声明同名变量）自然正确：本地作用域先查，查到就不是捕获。

### 7. 相等是同一性，不是"同一个函数"

`==` / `!=` 比较闭包记录的地址（JS 侧是对象同一性），语义在两个后端一致。`f == null`
可用。刻意**不**定义"两个闭包是否等价"：那要么比较捕获内容（结构相等，代价不明），
要么比较函数地址（`adder(1)` 与 `adder(2)` 会相等，明显错）。`<` 之类的序比较不支持。

## 后果

- 函数值可以存进容器（`list<fn(int)->int>`、`dict<string, fn(int)->int>`）、当字段、
  当参数、当返回值。`fs[0](x)`、`adder(1)(2)`、`(cond ? f : g)(x)` 都能调用 ——
  被调方不再按语法形态枚举，而是"求值出来看类型是不是 fn"。
- 闭包记录在 arena 上分配，和别的对象一样不单独释放（ADR-0001 第 4 节）。编译器是批处理
  进程，这没问题；长期运行的程序要等 ARC。
- 函数值**暂时不能装箱进 dynamic**（`boxable` 不含 fn）。要动态分派就用 `dict<string, fn(...)>`。

  这里和 ADR-0006 第 1 节有一处**未解决的张力**：那份 ADR 把 `dynamic` 定义成"完整的动态
  值域（含 class 实例、函数值）"，`json` 才是可序列化的子集。现在拦着不做，是因为装箱进去
  之后**取不回来** —— 运行期没有签名信息，`asFn()` 不知道该按什么类型调用，除非再引入
  "dynamic 上的动态调用"（实参个数与类型都在运行期检查）。那是一条独立的决定，等
  JS AST → OIR 真正需要它时（JS 的对象字面量里就放着函数）再单独开 ADR，而不是现在
  顺手加一个取不回来的标签。

## 已知限制

1. **没有自递归的 lambda**。`fn f = fn(...) { ... f(...) ... }` 里 `f` 在初始化器求值时
   还没声明。需要具名递归就写顶层函数。
2. **捕获的粒度是变量**，不是"用到的字段"。捕获一个 struct 会整份拷贝。
3. **没有默认实参、没有命名实参**：函数值没有形参名，这两个特性都依附于名字。
4. **一次适配器调用的开销**跑不掉（第 5 节）。将来在 OIR 上做直调消解（`MakeClosure`
   紧跟着 `CallFn` 的情况）可以去掉。
5. **`print(fn)` 不支持**，也没有 `fn` 的字符串形式。打印函数只能打印它的意义，而
   "函数的意义"没有跨后端稳定的文本。

## 被否掉的方案

- **胖值 `{fp, env}`（两个字长）**：存进容器和比较都要额外规矩，而"记录自己当 self"
  这个做法用一个指针就解决了。
- **按引用捕获 + 逃逸分析装箱**：见第 3 节。等价于提前把 ARC 的一半做完。
- **`auto` / 类型推断的 lambda**：见第 2 节，会让重载解析与实参定型互相依赖。
- **只支持"不捕获的函数指针"**：那就不是闭包，编译器源码里的回调（几乎全都捕获）一个
  都写不出来，等于没做。
- **把 lambda 降级成 class + 一个 `call` 方法**（Java 8 之前的写法）：需要为每个 lambda
  合成一个类型，还要让重载解析理解"这个类型有 call 方法"。节点更多，收益为零。

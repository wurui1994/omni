# ADR-0008：可选类型、三种模式与文件后缀

状态：已接受（2026-08-25）· 实现：`stage0/src/parse/parser.js`、`stage0/src/hir/check.js`、`stage0/src/cli.js`

## 背景

三个约束同时压过来，而它们互相拉扯：

1. **语法要像 Asymptote/C 系**：类型前置（`int x = 1`），不能用 `x: int` 后置形式。
2. **必须能不写类型**：REPL、脚本、以及"读一段 JSON 就用"的场景，逼着用户先想清楚类型是反人类的。
   Rust 式的纯静态在这里是错的答案。
3. **静态后端不能装箱**：C 后端的价值就在于 `list<int>` 是一段连续 `int64_t`。一旦"不写类型"
   意味着"到处装箱"，C 后端就退化成一个慢解释器。

外加一条来自别人踩过的坑：**Julia 的教训** —— 全程序类型推断 + 按调用点隐式单态化 + 安装依赖时
预编译一切，三者合起来让编译时间失控，而且错误信息发生在离用户代码很远的地方。我们不能这样。

## 决定

### 1. 选方案 3：一门语言、三种模式、三个后缀

但**不是三门语言**：一套类型系统、一个编译器、一份 OIR、一套后端。三种模式只在
**「缺省类型注解时怎么办」** 这一个轴上不同。

- `.omni` —— **混合（默认，主语言）**：缺省注解 ⇒ 从初始化器推断；推不出来 ⇒ `dynamic`。
- `.omnid` —— **纯动态**：缺省注解 ⇒ 一律 `dynamic`，不推断。REPL / 脚本 / JS 子集的落点。
- `.omnis` —— **纯静态**：缺省注解 ⇒ 从初始化器推断；推断结果落到 `dynamic` 或没有初始化器
  ⇒ **编译错误**。stage1（自举编译器）用这个模式写，保证零意外装箱。

注意 `.omnis` 禁的是**隐式** `dynamic`：显式写出 `dynamic` / `json` 仍然合法（否则没法解析 JSON）。

后缀只决定**默认**模式。CLI 的 `--mode mixed|dynamic|static` 可覆盖（REPL 用这个），
且只覆盖**入口文件**；被导入模块的模式由它自己的后缀决定。
模式是**按文件**的：每个声明带着它所在文件的模式进检查器（ADR-0009 第 6 节）。
一个 `.omnis` 文件可以导入一个 `.omnid` 文件，两边各按自己的规则检查
（`tests/cases/19_per_file_mode.omnis`）。文件首行 pragma 还没有，等有需要再加。

### 2. 四种声明形态，每种的作用域规则都来自它的出处

- `int x = e;` / `list<int> x = e;` —— **C / Asymptote**：类型前置，**块作用域**，静态类型。
- `let x = e;` —— **TS / JS**：**块作用域**，类型由 `e` 推断。
- `var x = e;` —— **JS**：**函数作用域**（提升到函数顶部），类型由 `e` 推断。
- `x = e;`（`x` 未声明）—— **Python**：**函数作用域**，类型由 `e` 推断。
  **这就是主语法里"动态"的写法：什么都不写。**

让形态决定作用域不是为了省事，而是因为每条规则都能追溯到它借来的语言，用户不需要记新规则。
`var` 与裸赋值会被提升到函数顶部并在那里初始化成零值，因此
`if (c) { x = 1; } else { x = 2; } print(x);` 按 Python 的直觉工作；而 `int x` / `let x`
按 C/TS 的直觉在块结束时消失。

**明确不做类型后置**（`x: int`）。理由：与 `Type ident` 的 tentative 消歧（parser 已跑通）冲突，
且一门语言里两套声明语法会同时污染 CST、格式化器和用户的肌肉记忆。

### 3. 推断只在函数内 —— 这是对 Julia 的直接反应

- **函数签名就是接口**。无注解的形参 = `dynamic`，**不是**"按调用点推断"。
  跨函数、全程序类型推断**明确不做**。
- 推断出的类型此后**单态**：`let x = 1; x = "s";` 在混合/静态模式是错误。
  （动态模式下缺省注解本来就是 `dynamic`，所以同样的代码合法 —— 模式差异只体现在这里。）
- **不做编译期隐式单态化**。容器是编译器已知的参数化类型（唯一例外，ADR-0006）；
  用户泛型等 comptime。特化只发生在两处：显式 comptime，或 JIT 对**实际热路径**的惰性特化。
- **依赖安装期不编译任何东西**。分发单元 = 源码 + 声明接口缓存；代码生成只发生在
  「构建某个具体程序」（整程序 C 发射）或运行期 JIT。禁止"预编译所有依赖"这类设计。
- REPL 的每次输入是一个增量编译单元，只编译新增的顶层项。

**stage0 的 REPL 与上面两条的偏差（记录在案）**：

1. **不是增量编译，是重放整个会话**。stage0 的检查器是整程序的，没有模块系统之前做不到
   只编译新增顶层项。重放在当前语言下**语义精确**（可观察副作用只有 `print`，没有 IO、
   时钟、随机数），实现上是：整体编译 → 整体执行 → 只把比上次多出来的 stdout 打给用户。
   副产品是错误处理变得干净：编译或运行失败的那一块直接不进会话，状态自动回到上次成功的
   样子，不需要任何回滚代码。代价是 O(n²)。真·增量等模块系统。
2. **默认模式是 `mixed` 而不是 `dynamic`**。`dynamic` 上还没有算术：`x = 10` 之后
   `x * x` 会报 "operator '*' cannot be applied to 'dynamic' and 'dynamic'"，
   一个做不了乘法的 REPL 没有意义。`mixed` 下 `x = 10` 推断成 `int`，算术 / UFCS /
   原生 json 都能用，代价是变量单态（`x = "s"` 报错，但错误消息里就写了怎么办）。
   等 `dynamic` 的算术落地，默认值改回 `dynamic`；`--mode` / `:mode` 现在就能切。

REPL 的输入解释规则（`stage0/src/repl.js`）：括号未闭合就续行；表达式单独一行会回显
（`1 + 2` 打印 `3`），但以 `;`/`}` 收尾、以语句关键字开头、或顶层带赋值/自增的输入算语句，
不回显。回显是靠把输入包成 `print(...)` 再编译实现的，所以包不过就退回当语句 —— 只有
「以 `)` 收尾」（可能是要副作用不要值的调用）才静默退回，其余情况报错，
否则 `ys`（`print` 目前不支持 `list`）会静默什么都不做。

### 4. 任意嵌套：支持，但只经由 `dynamic` 一条通道

- `dynamic` 的值域 = JSON 值域（ADR-0006）：`null` / `bool` / `int` / `real` / `string` /
  `list<dynamic>` / `dict<string,dynamic>`。所以 `[[1, {"a": [2]}]]` 合法，类型是 `list<dynamic>`。
- **不做联合类型**（`list<int|string>`）。要么装箱（那就是 `list<dynamic>` 绕远路），
  要么按元素带标签（等于把 tagged union 提前塞进容器）。**异质 ⇒ 统一降为 `dynamic`**，一条规则。
- 异质推断是**自上而下**的：一旦某层决定用 `dynamic`，它的子字面量就以 `dynamic` 为期望类型
  重新推断，于是嵌套的异质 JSON 字面量整棵树都落在 `list<dynamic>` / `dict<string,dynamic>` 上。
- **dict 的键不降级为 `dynamic`**：键要参与哈希与插入序，跨标签比较/哈希是泥潭。
  键必须统一到单个可哈希静态类型，统一不了就报错。JSON 对象键恒为 `string`，不受影响。
- Python 的任意嵌套之所以自然，是因为一切都是装箱对象。我们把"装箱"收敛成一个**显式的类型**，
  而不是让它散布在所有容器里 —— 静态路径因此保持不装箱。

### 5. 原生 json 原样支持：源码里不出现 `dyn()`

`dyn()` 保留，但只用于显式消歧；正常读写 JSON 不需要它。

- **构造**：`dynamic j = {"name": "ann", "tags": [1, 2], "ok": true};`
  异质 dict 字面量推断为 `dict<string,dynamic>`，每个值在 coerce 时自动插入 `Box`。
- **读取**：`dynamic` 直接支持 `j["k"]`、`j[0]`、`j.length`、`for (dynamic x in j)`。
- **写入**：`j["k"] = 5;`、`j.push(v)`。
- **条件**：`if (j["ok"])` 合法 —— 运行期要求标签为 `bool` 并解包。
  **不引入 JS 的 truthiness**（`0`/`""`/`null` 为假）：那是跨后端分叉源，也是 bug 温床。
  JS 子集前端需要 truthiness 时用一个显式的、单独命名的操作。
- **`dynamic` 的运行期分派面是一张封闭清单**（不是"什么都能干"）：
  `[]` 读/写、`.length`、`for-in`、`push`、`has`、`keys`、`tag`、`asInt/asReal/asBool/asString/asList/asDict`。
  标签不符 ⇒ 运行期错误，消息文本两个后端一致（ADR-0005）。
- `print(dynamic)` / `string(dynamic)`：**标签是 `string` 取原文，其余取 JSON 文本**
  —— 与 Python 的 `print`/`str` 一致（`print("a")` → `a`，`print(["a"])` → 引号在里面）。
  实现上降级为对 stdlib `dynToText` 的调用，**不在两个运行时里各写一份序列化器**
  （json 的唯一实现仍在 `stage0/lib/json.omni`）。

## 被否决的方案

- **只做混合模式，不要后缀**：REPL 与自举编译器的需求是相反的（前者要"别烦我"，
  后者要"任何隐式装箱都是 bug"）。一个模式满足不了两端，而用 lint 开关表达会让"这段代码
  在什么规则下成立"取决于命令行，比后缀更难追踪。
- **类型后置 + `var`**（Go/TS 风）：与约束 1 直接冲突。
- **全程序类型推断**（Julia/ML 风）：见第 3 节。它会把"改一行代码"变成"重编译世界"。
- **JS truthiness**：见第 5 节。

## 已知代价

- `var` 与裸赋值的函数作用域提升需要编译器把声明挪到函数顶部（`Local` 前置 + 原地变赋值）。
  这让 OIR 里的声明位置与源码位置不一致，调试信息将来要补映射。
- 混合模式下 `let x = 1;` 之后 `x = "s"` 报错，对从 Python 过来的人是个惊讶点。
  这是有意的：不单态化就没有静态后端。错误信息里直接写明"改用 `dynamic x` 或换 `.omnid`"。
- ~~模式目前是整程序的~~ —— ADR-0009 的模块系统落地后已修正：模式按文件，
  `libsFor` 那套"整程序拼库"已删除。

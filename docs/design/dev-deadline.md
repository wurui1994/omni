# 开发期的时限（谁都不许挂在终端上）

这一份说清一件事：**这条链上任何"跑"的动作都有一个墙上时限**，默认的那个数在开发期是
30 秒，发布构建里没有这一格。

## 为什么要它

挂住的那一趟**一个字节的信息都没有**。它不是"慢"——慢至少还会结束、还能量。
一个不收敛的定点循环、一个等 stdin 的子进程、一个死循环的例子，在终端上就是十几分钟
的空白，而那十几分钟里没人知道该看哪儿。时限把它变成**一句有名有姓的话 + 退出码 124**。

`omni run` 从前就有 `--timeout`（默认 30s）。不够的是另外两条路：

* **`build` 那一趟**（我们自己那台编译器里挂住）——`run` 的时限管不到它；
* **链出来的可执行文件不经 `omni` 跑**（判据脚本 `sh -c ./out`、人手敲 `./out001`）——
  那时连 `omni` 都不在场。

## 三处，一个约定

| 谁 | 怎么中断 | 默认 | 关掉 |
| --- | --- | --- | --- |
| `omni <任何动词>` | 宿主的看门狗（`runTimeout`：子进程用 `spawnSync` 的时限，本进程用另一根线程） | 跑一个程序 30s、编译这一趟 300s | `--timeout 0` / `OMNI_RELEASE=1` |
| 生成出来的原生程序 | 自己的 `SIGALRM`（`omni_deadline_init_`）**加**一格外部看门狗当备用 | 30s（外部那格晚 2s） | `OMNI_TIMEOUT=0` / `OMNI_RELEASE=1` |
| 生成出来的 JS（`node out.mjs` 直接跑也算） | 一格**外部看门狗**（`$dl_arm`） | 30s | `OMNI_TIMEOUT=0` / `OMNI_RELEASE=1` |

**不存在"不管它"的情形。** 三处都在，而且三处读的是同一个开关。

秒数按这个次序问，先有的算：

1. `--timeout SEC`（只管这一趟；`30s` 带单位也收）
2. 环境变量 —— 跑程序是 `OMNI_TIMEOUT`，编译是 `OMNI_BUILD_TIMEOUT`
3. 仓库根的 `.env` 里那一行
4. 默认值（30 / 300）

`0`、`off`、`none` 都是"不限"。

`--timeout SEC` 会**写回 `OMNI_TIMEOUT`**（只在"跑一个程序"那几个动词上）——
不然它只管住了第一层：后两层读的是环境变量，看不见命令行。量出来的（2026-09-26）：
`run x.sx --timeout 4` 从前是 30s 才停的（`.env` 里那个数）。

## 常驻工人那一档：`OMNI_CLI_NO_SHOT=1`（**关枪，不关预算**）

Studio 的热工人（`src/core/studio/worker.js`）是**常驻进程**：第一层那一枪打的是"本进程"，
打下去工人就得重开。所以工人要躲那一枪 —— 可**躲法从前是错的**。

从前工人设的是 `OMNI_TIMEOUT=0` / `OMNI_BUILD_TIMEOUT=0`。那两格是环境变量，
**会跟着孩子走**，于是同一趟里：

* 第一层：`sec === 0` → 一格时限都不装，`spawnSync` 也就没有 `timeout`；
* 第二、三层：孩子（生成出来的程序）读到 `OMNI_TIMEOUT=0` → `SIGALRM` 不装、
  外部看门狗也不起。

**三层一起没了。** 量出来的后果（2026-09-26）：两个 GUI 例子跑了 28 分钟还在，而父进程
早就不在了 —— 孤儿进程，只能手动 `kill -9`。这正是上面那句"不存在'不管它'的情形"
被破掉的那一处。

现在改成一格**只管枪**的开关：`OMNI_CLI_NO_SHOT=1`。宿主的 `runTimeout` 看见它就只记
截止时刻、不起那根线程（`src/core/host/native.js`；这一格读环境变量而不是多一个形参，
因为 `runTimeout` 是宿主 op —— `hir/js_abi.js` 的 `js_run_timeout`，arity 2，
另有 JS prelude 与 C 两份实现）。于是：

* 子进程照旧被 `spawnSync` 的时限管着（`DEADLINE_MS` 照旧记）；
* 生成出来的程序照旧拿到真的 `OMNI_TIMEOUT`，第二、三层照旧在；
* 常驻工人不会被自己那一枪打死，超时仍由池子数着、到点杀工人。

顺带修的一格（同一处）：`armDevDeadline` 现在**先把上一趟的截止时刻清掉**再决定这一趟。
常驻工人里 `runCli` 会被调很多趟，而"这一趟不装时限"那几个 `return` 从前会把上一趟的
`DEADLINE_MS` 留着 —— 下一趟每个 `spawnSync` 都只剩 1ms，表现成"莫名其妙超时"。

判据（`.omni-cache/probe/` 下的一格死循环 `.sx`，三条腿各量一趟）：开枪档 JS 腿、
不开枪档 JS 腿、不开枪档原生腿 —— `--timeout 4` 之下都在 5s 内停，`ps` 里**一格残留都没有**。

## 那一格外部看门狗

一行 `sh`，起的时候 detach + `setsid`，干三件事：

1. **每秒看一眼目标还在不在**（`kill -0`）—— 没了就自己退。所以程序正常跑完时它跟着走，
   不会拖住终端，也不会留下孤儿。
2. 到点先写一句话，再 `kill -TERM`。
3. 再等 5 秒还在，就 `kill -KILL`。

开销：一个睡着的 `sh`，一秒一次 `kill -0`。量出来正常程序**一点都没变慢**
（js 40ms、原生 12ms，与没有它时相同）。

**为什么 JS 那条腿只能这样**：紧的 JS 循环把事件循环整个占住，`setTimeout` 永远不会响 ——
从进程内部拦不住自己。外部那一格不在这个进程里，所以进程内发生什么都拦不住它。

**为什么原生腿有了 `SIGALRM` 还要它**：`SIG_BLOCK` 过 SIGALRM 的代码、把 `ITIMER_REAL`
另作他用的库、`exec` 换掉整个映像的那一趟 —— 三种情形下那一格都会**静静失效**。
外部那一格是那三种情形的兜底，所以它的时限比进程内那一格晚 2 秒：正常情形下让
进程内那一句先说话（退 124），轮不到外面动手。

一个已知的近似：认的是 **pid**，所以理论上有 pid 复用的窗口。窗口是"目标退出到看门狗
下一次 `kill -0`"之间的一秒，而那一秒里系统要把同一个 pid 分给别人 —— 开发期的时限
不值得为它再加一层握手。


## `.env`

一份普通的 `名字=值`，`#` 起头是注释，允许 `export ` 前缀：

```
OMNI_TIMEOUT=30
OMNI_BUILD_TIMEOUT=300
```

两边各自读它：CLI 那侧是 `cli.js` 的 `dotEnv()`（找当前目录与仓库根），
生成出来的程序那侧是 `omni_js_host.c` 的 `omni_dl_from_dotenv_()`（只看当前目录 ——
往上找会把"在哪儿跑"变成一件说不清的事，而这一格的全部意思是"手边这个仓库的开发约定"）。

## 发布那一档

`OMNI_RELEASE=1`（CLI 那侧 `--release` 也算）：三处一格时限都不装。

理由：发布出去的程序不该因为某台机器上写了 `OMNI_TIMEOUT` 就自杀。

**编译期那一档还差一格**：C 那侧整段写在 `#ifndef OMNI_RELEASE` 里，可
`--release` 还没接到 `-DOMNI_RELEASE` 上 —— 今天靠的是运行期那一问
（`getenv("OMNI_RELEASE")`）。要"一个字节都不编进去"就补那一格编译旗子。

## 为什么原生那一格是 SIGALRM，不是线程

死循环里事件循环与协程调度都不转，只有信号能打断它。处理函数里只有 `write` 与 `_exit`
两个调用，都是异步信号安全的。`setitimer(ITIMER_REAL, …)` 收小数秒，所以
`OMNI_TIMEOUT=0.5` 也说得通。

退出码 **124**，与 `timeout(1)` 同一个约定。

## 判据

`tests/build/` 那一组（不跑语言，只量机制）。要手验：

```
OMNI_TIMEOUT=1 ./loopx                  # 原生死循环 -> 一句话 + 退 124（进程内那一格）
OMNI_TIMEOUT=2 node loop.mjs            # js 死循环   -> 一句话 + TERM（退 143，外部那一格）
OMNI_TIMEOUT=0 ./loopx                  # -> 不限（外面 timeout -s KILL 才停得下来）
cd 有 .env 的目录 && ./loopx             # -> 读 .env 里那一行
OMNI_RELEASE=1 ./loopx                  # -> 一格时限都不装
```

量过的那三行：正常程序**一点都没变慢**（js 40ms、原生 12ms），看门狗也不拖住退出。

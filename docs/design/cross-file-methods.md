# 跨文件那一族：方法与库函数从哪儿来

> 这一份是**决定与判据**，不是愿景。上游是 ADR-0037 §5.1a（自举尺子）与
> `docs/design/node-graph-typed-overlay.md`（#40）。写在动手之前 —— 这一族已经**吃掉过两刀**
> （两刀都量出来是负的，记在下面第二节），所以先把三条路摊开、各配一条会红的判据。

## 一、这一族有多大（`--strict-calls` 那一档，2026-09-18）

`node bench/tograph.js --strict-calls`：

- **go** 646 份没落成图，其中 **475（73.5%）** 是这一族
- **vlang** 1252 份没落成图，其中 **599（47.8%）** 是这一族
- 三门合计 **1074 / 1964 = 54.7%** —— **过半**

墙上的话长这样（一条一个方法名，所以条数多、每条不大）：

```
12  go->graph: 这一批只接 fmt.Print* 与声明过的方法，收不了 .Pos
12  go->graph: 这一批只接 fmt.Print* 与声明过的方法，收不了 .Fatalf
36  v->graph:  这一批只接声明过的方法与声明过的字段，收不了 .contains
31  v->graph:  这一批只接声明过的方法与声明过的字段，收不了 .str
```

**一句话说清这一族是什么**：`x.M(…)` 里的 `M` 声明在**别的目录**（go 的另一个包、V 的另一个
模块）或**标准库**里。今天两门的映射都只认"这一趟扫到的声明"（同目录 + `opts.also`）。

## 二、已经量过的两条死路（别再走）

**死路一 · 整包/整目录喂方法名。** 把 `opts.also` 的方法名也收进 `METHODS`：
vlang 那一栏当场从 1044 掉到 338、go 从 81 掉到 47。**根因**：`METHODS` 是一张
**名字 -> 接收者类型**的平表（单态分派），一个包摊开看**重名到处都是**（`Ship.instance`
与 `GameObject.instance`），撞名就当场报。改成 shapesOnly（只收 struct 的字段名、不收方法名）
之后仍旧净 **−4** —— 也记在账上。

**死路二 · 让兜底"看起来能落"。** V 那一份的兜底是"取字段再调它"，量出来 **423/1310 份
（32.3%）**的图里含它 —— 而对**方法**调用那条兜底**运行期跑不通**（记录上没有那个字段）。
`--strict-calls` 把它也当墙之后 V 是 916/42.3%。**不许用"落得出图"换"跑不通"**。

## 三、三条路（各一条判据）

### A. 名字按接收者类型压平（mangle）

`fn (s Ship) instance()` -> 图上一格函数 `Ship__instance`；调用点 `x.instance()` ->
`Ship__instance(x)`。撞名问题消失（那才是"两个类型的同名方法"的正解）。

**要什么**：调用点得知道 `x` 是哪个类型 —— **一格名字 -> 类型的环境**。
映射那一层今天**没有**它（`STRUCTS` 只答"这个类型长什么样"）。

**代价**：这条路等于在映射里写一份该门语言的类型推断 —— 十一门各写一遍就是十一份重复，
那正是 #40 要消掉的东西。**除非**让它问覆盖层（`graph/types.js`）：那就要覆盖层能在
**建图的半路**回答"这格节点是什么类型"，而不是建完再问。

**判据**：`ext/<lang>/examples/method2.v`（新）—— 两个类型各有一个同名方法，
六条腿输出一致；把 mangle 那一步删掉，这份例子当场撞名报错。

### B. 方法当字段：构造时把闭包装进记录（lua 那条路）

`record-new` 时给那个类型的每格方法加一格字段（值是一格 `func`），于是
`x.M(a)` = `call(field-get(x,'M'), [x, a])` —— **兜底变成正解**。
这条路已经在 lua 那门上落过（元表那一批，任务 #19）。

**代价三条**：① 构造点**在别的包里**时也要知道方法表（同一个跨文件问题，只是搬了个地方）；
② 每格记录都胖了（字段数 = 数据字段 + 方法数），`stat.js` 的节点数会涨一截；
③ 方法值是**闭包**，而 core / wat 两条腿在"函数出现在表达式位置"上还欠着账。

**判据**：`tests/graph/shape.js` 那条"字段名静态可知"的判据不许红（方法字段也是静态可知的），
加一格反向证物：构造点看不见方法表时**必须报**，不许悄悄少装一格字段。

### C. 图上加一格"按名字派发"的节点

一格 `dispatch(obj, 名字, 实参…)`：运行期在宿主那侧查"这个对象上叫这个名字的东西"。
ADR-0033 §2.3 那条判据要**四家以上**要它才给新节点 —— 这一格的出处是：
go / V / nim（`method`）· lua（元表 `__index`）· cpp（虚函数）· mojo（trait）—— 够。

**代价**：它把"名字 -> 实现"的决定**推到运行期**，于是 wat / c 两条腿要一张运行期的表
（那正是我们在别处一直避免的东西：`nodes.js` 文件头第三条"次序是算出来的边，不是一格算子"
的同一条纪律 —— 派发也该是算出来的，不是一格节点）。

**判据**：这一格要有一份"删了它六条腿照旧"的证物（`delete.js`），
以及一份"它与静态分派**答案相同**"的证物 —— 后者是它存在的全部理由。

## 四、决定：先 A，但**先补它缺的那一格**

三条路里 A 是唯一**不动代数、不动运行期**的（mangle 是纯改名）。它缺的那一格是
"调用点知道接收者的类型"，而那一格恰好就是 **#40 第四步**（`opts.hints` 把
`STRUCTS` / `METHODS` 交给覆盖层）之后覆盖层能答的东西。

所以次序是：

1. **#40 第四步**（覆盖层收 hints，能答"这格 `ref` 是哪个具名类型"）——
   那一步的判据在 `tests/graph/types.js` 上（正向 + 反向证物）。
2. **让映射能在半路问覆盖层**：`toNode` 那一趟带一格 `env`（名字 -> 具名类型），
   `:=` / 形参 / 字段读三处填它。**这一步不落任何新节点**，判据是"填错就撞名报错"。
3. **mangle**：`METHODS` 从"名字 -> 类型"变成"类型.名字 -> 一格函数名"，
   撞名那条 throw 删掉（它是这一族今天最大的一条墙）。
4. 量一次尺子 —— 这一步才动那 1074 份。

B 与 C 都**记在这儿不做**：B 的代价是记录变胖 + 构造点仍旧要方法表；
C 是新节点 + 运行期表，而 A 走通之后它们就都不必要了。哪天 A 卡住（比如接口/`any` 那一族
真的要运行期派发），再回来看 C —— 那时它的分母是"A 之后还剩多少"。

## 五、不做什么

* **不做全库索引**（把 go 的 `src/` 或 V 的 `vlib/` 整棵先扫一遍）：那是"死路一"的加强版，
  撞名会更多；而且尺子的分母是"那门编译器自己的源码"，把标准库也扫进来会把两层账搅在一起。
* **不猜标准库的签名**（`.contains` / `.join_path` 那一族）：那些是 V/go 的 stdlib，
  要它们就得**真的编 stdlib**（那是尺子的下一层，ADR-0037 §5.1a 里的 ① 那一档）。
  这一份只管"同一份源码树里、声明在别的目录"的那一半。

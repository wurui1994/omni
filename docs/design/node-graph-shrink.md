# 图的第二个目标：变换要**缩**，不许胀

（ADR-0033 的节点代数、`docs/design/node-graph-contract.md` 的契约五问之后的一份**目标文档**。
这一份不定机制，只钉两件事：**为什么现在每一层都在胀**，以及**图这一层要把它掉过头来**。
所有数都是量出来的，日期与量法写在每一行后面。）

## 一句话

图不只是「十门语言接进来的公共表示」。它的第二个目标是：
**一条 pipeline 走完、最后一格后端是 C 时，出来的代码不比源码胀，形式也没丢。**

## 一、现在的账：每一层都在胀（arm64 macOS，2026-09-16 量）

自编译那一整条链，逐层量：

- **JS -> JS**：`src/` 8.9M（137968 行）-> `dist/omni.mjs` 19.2M —— **2.2x**
- **JS -> C**：同一份 `src/` -> 生成的 C 13.8M / **270256 行** —— 行数 **1.96x**
- **C -> 二进制**：那份 C -> `.text` 35331080（我们自己那台 C 编译器）/ clang 11.7M 的产物
  —— 见 `cli.js` 的 `selfCC` 那段注释里的三行账
- 小一点的两格，比例是一样的：
  - OIR 腿 `tests/cases/01_basics.omni` 66 行 / 1262 字节 -> C **109 行 / 3616 字节**（1.65x 行、2.9x 字节）
  - graph 腿 `ext/lua/examples/basics.lua` 44 行 / 1092 字节 -> C **435 行 / 13190 字节**；
    其中固定序言 358 行（一次性），**按源码长起来的那一段 77 行**（1.75x 行）

一句话：**每一层都乘一个大于 1 的数，一层都没有小于 1 的。**

## 二、为什么胀：变换不等效于优化

现在这条链上的每一步都是**展开**，不是化简。三个来源，都能指着代码说：

1. **一格富的构造落成好几格简单的**。`for...of` -> 迭代器协议那四步；`a?.b` -> 判空 + 取值；
   `++` -> ToNumeric + 加一（`js_inc`）。每一步都对，但每一步都**只加不减**。
2. **动态值把每个算符变成一次调用**。生成的 C 里 `a + b` 不是一条 `add`，是
   `omni_js_add(a, b)`；graph 那条腿更直白 —— 那 77 行程序里有 **24 行**声明 `gv`
   （16 字节、带标签），`sumto(5)` 落成 `fn1_sumto(g_num(5.0))`：**一个静态就知道是
   整数的实参也要装箱**。最扎眼的一行是 lua 的 `n * fact(n - 1)`：

   ```c
   gv t8 = g_num(g_d(v_n) * g_d(fn2_fact(g_num(g_d(v_n) - g_d(g_num(1.0))))));
   ```

   `g_num(1.0)` 造出来、`g_d(...)` 当场拆掉 —— **装箱又拆箱一个字面量**。
3. **后端再乘一次**。同一份 C，我们那台后端曾经比 tcc 大 2.85x（现在 1.78x，第一百四十二到
   一百四十五片那四刀）—— 那是「每个值过一趟栈格」乘出来的，与前两条无关，是**第三次**乘。

三条叠起来就是 2.2 / 1.96 / 2.85 这几个数的来历。**没有哪一步在减**。

## 三、图这一层要掉过头来

图与前两条腿（OIR/MIR）的区别不在「又一层 IR」，在**它手里的东西还没被展开**：

- 记录、列表、映射、区域、`scope-exit`、多值，**都是节点**，不是糖化后的产物
  （`nodes.js` 那 27 格，每一格都有出处）；
- 每一格节点声明了**效应六格 + lifetime**（`prims.js` 里 pure 那一栏写着「可重排、可共享、可删」）；
- 所以「这一格能不能删 / 能不能合 / 能不能就地做」这三个问题，**在图上问得出来**，
  在 MIR 上已经问不出来了（那时候 `record-new` 已经变成一串 store）。

于是第二个目标可以写成三条**可量**的要求：

- **不胀**：源码 N 行 -> 最后那一格 C 的「按源码长起来的那一段」应当 **≤ N 行**
  （固定序言另算，那一段是常数）。今天是 1.75x。
- **不丢形式**：字段名静态就知道的记录，落成 C 的 `struct`，不是堆上一块 + 线性找键；
  只装整数的量落成 `long long`，不是 `gv`；只被直接调用的函数落成直接调用，不是函数指针表。
  今天全丢了 —— 那 77 行程序里 `struct` **出现 0 次**（只有序言里那四个通用结构），
  `gv` 出现 24 行。
- **变换是减法**：每个 pass 要能报出「删了几格节点」，加不回去。

## 四、诚实的自评：三格里两格立住了，第三格是空的

- **保真性够**：`sx` 那条腿把图序列化再读回来**逐字节相同**，读回来的图跑出同一份输出
  （`tests/graph/run.js`，108/108）。这就是保真性的判据，不是感觉。
- **灵活性够**：十门语言 × 5 个后端的矩阵，569 passed / 0 failed；
  节点级缺口 interp/sx/js 各 0 格、wat 0 格、c 0 格（剩的是形状上的账，各有证物）。
- **变换那一格原来是空的**：`src/core/graph/` 下一个 pass 都没有，路是 `fromtree` -> 后端
  一遍到底 —— ADR-0033 那套效应/lifetime 声明是**为了变换**才写的，却一个消费者都没有。
  **这就是这份文档钉住的欠账**（2026-09-17 起：第一个 pass 落地，见下面两条）。
- **尺子先有了**（2026-09-17）：`src/core/graph/stat.js` + `omni run/build --engine graph --stat`
  能报出「这张图多少格、都是些什么格、纯与有效应各几格」，`--stat-diff FILE` 按 op 逐格相减。
  量到的原话（`ext/lua/examples/`，arm64 macOS）：
  `record.lua` 19 格 / 14 条边 / 深 4（纯 4、有效应 15），
  `method.lua` 84 格 / 71 条边 / 深 10（纯 12、有效应 72）——
  两者相减是 `+17 map-get · +7 map-set · -4 field-get · -1 record-new`，
  也就是「一格 `record-new` 换成一族 map 操作」这笔账**现在有数字了**（判据 `tests/graph/stat.js`）。
- **第一个 pass 也有了**（2026-09-17）：`src/core/graph/shrink.js` + `--shrink` ——
  常量折叠（pure 的内建 + 全常量实参，借的是解释器那同一个 kernel）
  与死绑定删除（名字没人 `ref`/`set` + 初值通体 pure）。
  量到的数：`lua/strcat` 12 -> 8 格（`-2 const · -2 prim:concat`）、
  `lua/numstr` 10 -> 8、`nim/conv` 10 -> 8；十门例子里**16 份缩得动、85 份报 0**
  （缩不动不是失败，是那几份里本来没有常量表达式、也没有死绑定），
  101 份**输出无一处改变**（interp 那条腿逐份比过）。
  **五条腿的输出一字不变**，`sx` 那条腿缩完仍然读回来逐字节相同（判据 `tests/graph/shrink.js`，529 格）。
  于是第三格从「空的」变成「**有一个消费者、还欠后面那两条**」。
- **接着量了一遍第 1 节，结果是负的**（同日，同一台机器）：第一个 pass 落地之后 graph 腿
  那份 C **一行都没少** —— `basics.lua` 435 行 / 11468 字节缩前缩后逐字节相同（它一格都没折），
  `intmath.lua` 403 行 / 10921 字节同样不动，只有 `strcat.lua` 少了 84 字节（10446 -> 10362）。
  `g_num(g_d(` 的次数（3 / 3 / 1）与 `gv` 声明数（15 / 12 / 7）**一个都没变**。
  这条负结果要留在账上，因为它说清了一件事：那 77 行里的胀是**装箱**，不是常量表达式，
  常量折叠压根碰不到它 —— 第 1 节那五行要动，得靠下面第 2、3 条（形状与窄化）。

## 五、下一刀的判据（做到了怎么算）

按「一个例子家族一格判据」的老规矩，第一批三条，每条都要能量：

1. **常量折叠 + 死绑定删除**（pure 那一栏的第一个消费者）：
   `tests/graph` 里现有例子上报出「删了几格」，且五个后端输出一字不变。
   **已落地**（2026-09-17，`src/core/graph/shrink.js` + `--shrink`，判据 `tests/graph/shrink.js`
   529 格：规则六条 + 十门例子全矩阵 × 五条腿缩前缩后一字不变 + 「16 份缩得动」那一格眼睛）——
   剩的那一步是「让它默认开」：判据已经够了，缺的是一句决定（默认开会改掉
   `build --engine graph` 的产物文本，那是要单独记一笔的事）。
2. **形状推断落到 C**：字段名静态可知的 `record-new` -> C `struct`；
   判据是 `ext/*/examples/record.*` 那一族出来的 C 里**出现 `struct`、`gv` 计数下降**。
   **落地了**（2026-09-17，`backend-c.js` 的 `recPlan`，判据 `tests/graph/shape.js` 19 格）：
   `record.lua` 那一份现在发 `struct r1 { gv f_x; gv f_y; };`，取字段是 `v_p.f_x`
   （一格偏移），`g_rec_new` / `g_field_get` 在程序那一段**一次都不出现**，
   `gv` 局部量从 4 格降到 3 格（剩的三格是 print 的缓冲）。
   同形的记录共用一格 `struct`（编号按登记顺序，所以两次出来逐字节相同）。
   三处不动：记录**跑出去**（当实参 / 被 print / 进列表 —— 宿主面只认 `gv`）、
   字段名不在名单里、那格 `record-new` 被共享 —— 每一条都有一格判据。
   91 份例子的 C 合计 982075 -> 980994 字节、`gv` 局部声明 943 -> 923。
3. **数值窄化**：只与整数常量与整数变量作用的量 -> `long long`；
   判据是 `intmath` 那一族的 `g_num(g_d(` 往返归零。
   **头一半落地了**（2026-09-17，`backend-c.js` 的 `numPlan` + `dOf`/`condOf`，
   判据 `tests/graph/narrow.js` 27 格）：一个函数体里「只装数」的**局部量**、以及
   **每个调用点递的都是数**的那些**形参**，落 C 的 `double`。`intmath.lua` 现在是

   ```c
   static gv fn1_sumto(double v_n) { double v_acc = 0.0; double v_i = 1.0;
     while (1) { if (!((v_i <= v_n))) break; v_acc = (v_acc + v_i); v_i = (v_i + 1.0); } … }
   static gv fn2_fact(double v_n) { if ((v_n == 0.0)) { … } gv t7 = g_num(v_n * g_d(fn2_fact((v_n - 1.0)))); … }
   ```

   量到的数：`intmath.lua` 10921 -> 10827 字节、`gv` 声明 12 -> 10、`g_num(` 17 -> 10；
   91 份例子的 C 合计 984881 -> 982075 字节，`g_truthy(g_bool(` 92 -> 7 次。
   **判据这一条已经满足**（同日晚一点，序言裁完之后重量）：`intmath` 那一份的
   `g_num(g_d(` **归零**。这个 0 的来历要说清 —— 最后一次往返住在**序言的 `g_add` 里**
   （`return g_num(g_d(a) + g_d(b));`），窄化把这一份的加法变成了 C 的加法，`g_add` 就没人用了，
   第七节那一裁把它一起带走。**装箱并没有全没**，只是不长那个样子：
   `g_num(v_n * g_d(fn2_fact((v_n - 1.0))))` —— 那是**返回值**那一侧（函数回 `gv`）。
   要它也没，得先证「每条路都回数」（走到底没 `ret` 时回的是 nil，`g_d(nil)` 是读没意义的字节）。
   判据 `tests/graph/narrow.js` 把这两件事都钉住了（0 次 + 那一行原文）。

三条都落地之后再重量第 1 节那五行——**目标是让至少一行小于 1**。

## 七、重量（2026-09-17，三条都落地之后，arm64 macOS）

三条判据都落了地，于是照第五节最后那句话重量。**只量 graph 那一行** ——
JS -> JS 与 JS -> C 那两行走的是另一条 pipeline（前端 -> OIR -> 后端），这一刀一个字都没碰。

- `ext/lua/examples/basics.lua` 44 行 / 1092 字节 -> C **435 行 / 11364 字节**
  （2026-09-16 是 435 行 / 13190 字节 —— **字节 -13.8%**，行数没动）；
  其中固定序言 **361 行 / 10114 字节**（常数，与源码长短无关），
  **按源码长起来的那一段 74 行 / 1250 字节**（上一版 77 行）。
- 于是那一行的比例：行 77/44 = 1.75x -> **74/44 = 1.68x**；
  **字节 1250/1092 = 1.14x** —— 这是五行里离 1 最近的一格。
- 别的量：`gv` 局部声明 15 -> 13、`g_num(` 19 -> 12；91 份例子的 C 合计
  984881 -> **980994 字节**、`g_truthy(g_bool(` 92 -> **7** 次、`gv` 局部声明 943 -> 923。

**结论要说实话：一行都还没小于 1。** 三条判据做的是「不丢形式」，而剩下的胀有名有姓：

1. **固定序言 361 行**：`gv` 那套表示 + 列表 / 记录 / 映射 / 串那几族的实现。
   它是常数，所以源码一长它就摊薄 —— 但小例子上它就是那 435 行里的 83%。
   真要动它，得让序言**按用到的那几族裁**（用不到 map 就不发 map 那一段）。
2. **`gv` 边界上的装箱**：`print` 收 `gv *`、函数回 `gv`。窄化能把体内那一段变成 double，
   到边界还得装回去 —— 下一格是**返回值也窄**（要先证「每条路都回数」）。
3. **一格值一格临时量**：`gv t3 = g_nil(); … return t3;` 这种是「C 里没有语句表达式」
   换来的，与前两条无关。

所以下一刀的判据接着写在这儿：**序言按用到的族裁**（判据：`strcat.lua` 那一份不该发
map 与列表那两段）、**返回值窄化**（判据：`intmath` 的 `g_num(g_d(` 归零）。

## 八、序言按用到的族裁（2026-09-17，第七节第 1 条落地）

那 361 行序言是**一整份**发出去的：一份只印两个串的程序也带着映射、列表、切片、`g_pow`。
`backend-c.js` 的 `trimPrelude` 把它按名字**传递地留**（一格土生土长的摇树）：
序言切成一格格定义，根是这份程序自己那一段里出现的 `g_*`，然后按每格定义引用的名字闭包。
`#include` / `typedef` / `#define` / libc 那几行原型一律留（是地基，也就十几行）。

敢裁的理由是**漏留一格的后果是编不动**（我们自己那台 C 前端当场报「不认得这个名字」），
而那条路上有 98 份例子在跑。判据 `tests/graph/prelude.js` 另加一条纯文本的安全网：
**93 份产物里，程序那一段用到的每一个 `g_*` 都要在这份产物里有定义**。

量到的数（同一台机器，与第七节同一个切点）：

- `basics.lua` 44 行 / 1092 字节 -> C **228 行 / 5542 字节**（裁之前 435 行 / 11364）；
  序言 361 -> **154 行**、程序那一段 74 行 / 1250 字节（一个字没动）。
- `strcat.lua`：377 -> **166 行**（映射 / 列表 / 切片 / `g_pow` 一格都不发）。
- 91 份例子的 C 合计 980994 -> **496106 字节（-49.4%）**、`gv` 声明 923 -> 602。

于是第 1 节那一行**又动了一次**：整份产物 13190 -> 5542 字节，**-58%**（今天两刀合起来）。
比例仍然大于 1（整份 5542/1092 = 5.1x、只看程序那一段 1250/1092 = 1.14x）——
剩下那 154 行序言是 `gv` 那套表示加用得上的那几族，**它已经与「用了什么」成正比**。

## 九、返回值也窄（2026-09-17，判据 3 的第二半）

窄化的第三格：**函数回 `double`**。能窄的条件只有两条，都在图上问得出来（`numPlan` 的 `rets`）：

- **体的最后一格是 `ret`** —— 掉出去那条路走不到（掉出去回的是 nil，那可不是数）；
- 体里每一格 `ret` 都带值，而且那个值**是数**（`ret` 不带值的一律出局）。

「是数」这一栏因此多了一条：**一次调用算数**，前提是那个函数的返回值窄了 ——
所以这三格（局部量 / 形参 / 返回值）是**一个不动点**里一起算的（`fact` 递归调自己那一句
正是这么立住的）。调用点在值位置上装回去（`g_num(fn(…))`），在算术位置上就是裸调用。

`intmath.lua` 现在长这样 —— 与手写的 C 只差一格临时量：

```c
static double fn2_fact(double v_n) {
  double t5 = 0.0;
  if ((v_n == 0.0)) { double t6 = 1.0; return t6; }
  double t7 = (v_n * fn2_fact((v_n - 1.0)));
  return t7;
  return t5;
}
int main(void) { gv pt9[1]; pt9[0] = g_num(fn2_fact(5.0)); g_print(pt9, 1); return 0; }
```

量到的数：`intmath.lua` **193 行 / 4871 字节**（今天开工时是 403 行 / 10921）、
`g_num(g_d(` **0** 次、`gv` 局部声明 2 格、`g_num(` 3 次（全在印那一步 —— `g_print` 收 `gv *`）。
91 份例子的 C 合计 496106 -> **495830 字节**、`gv` 局部声明 602 -> **536**。
判据 3 那句「`g_num(g_d(` 往返归零」现在是**真的归零**（形参 / 局部量 / 返回值三处都窄了），
判据 `tests/graph/narrow.js` 连那几行原文一起钉住。

## 六、不做什么

- **不把图变成一个通用优化器**。这一层要的是「不丢形式地落地」，不是重写一遍 LLVM
  的 pass 管线：能在图上问出来的才在图上做，问不出来的留给后端。
- **不为了缩而牺牲判据**。任何一个 pass 都要过「同一张图、每个后端可观察行为一致」那张矩阵；
  缩不下来是账，缩错了是事故。
- **不改契约五问**。`can`/`carry`/`effect`/`region`/`lower` 一格都不动 ——
  变换发生在图上，后端仍然只回答问题。
